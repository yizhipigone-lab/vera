### 关键方法论发现 1: 网页公式「换皮」泛滥
- GS1318 与 GS0737 归一化源码相似度 **1.00**(同公式仅变量名/标题不同)
- GS1333 = GS1318 + 三行定义了但从未引用的死代码 → 输出逐日逐股完全相同(信号对 3282~3284)
- 3 条「21% 三连」是**同一条鱼称了三次重**。粗扫达标数 5 需先归族再计数

### 关键方法论发现 2: 最优参数跨段收敛(参数本身稳健)
- 训练段(2024-09~2025-11)独立定参: 最优 = act8%/dd0.5%
- 全段精调冠军: 同 = act8%/dd0.5%
- 两段独立数据收敛同一参数区 → 排除「参数恰好拟合」的嫌疑，**公式有真 alpha，只是幅度有限**

### 关键方法论发现 3: 样本外是注水数字的照妖镜
- GS0607 全段最优 24.4% → 训练段定参后验证段仅 10~15%
- 差额 = 「先看答案再选参数」的水分(约 9~14pp)
- 但结构特征(浅回撤 -2.3~-3.6%、高胜率 64-68%、卡玛 4.9-6.4)全部保持 → 非伪策略，是「真 alpha 但弱一档」

## 四、流程资产沉淀(下一批可直接复用)

1. `farm_parallel_sweep.py` — run 阶段 6-8 进程并行 + 零信号 memo(免重复 prep)。实测 82 条并行 18 分钟 vs 串行 4-6h(提速 15-20x)
2. `farm_refine_passers.py` — 2592 组合分片并行精调(run --shard/--nshards 断点续跑)
3. `zero_signal_memo.json` — 39 条真零信号记忆, 免每轮重复 prep
4. `gs_5m_sweep.py` SWEEP_TAG 环境变量 — 训练/验证段缓存目录隔离(样本外必需)
5. 经验坑:
   - prep 判空须按 dict 判(`"Close" not in kline`, 返回是 dict 非 DataFrame)
   - onboard ok=True 只代表添加动作成功, 不代表能跑选股
   - run 超时须放宽(高信号公式单片可超 2h); 机器重启/进程偶死靠断点续跑兜底
   - **删除类操作必须先列后删双确认**(本次误删 5m 源缓存教训, 校验须用 pyarrow 真读)
