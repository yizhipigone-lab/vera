# 图表分析深挖包设计

> **状态：** 方案已获用户批准（2026-08-13）；范围已钉定「回测 Tab + 实盘分析 Tab 一起」
> **Phase 1 已完成（2026-08-13）：** 交付 `web/js/deep_math.mjs` + `web/js/charts_deep.js` + `tests/web/test_deep_math.mjs`；水下曲线（回测+实盘）与蒙特卡洛扇面（回测）上线，前端测试 43+31 全绿。蒙特卡洛实际口径以 §3/§4.1 修正后的描述为准（`pnl / 入场时点总权益`，非仓位口径）
> **范围：** 本文件只交付设计；不修改生产代码，进入实现前须另立实现计划并再次审批
> **实施原则：** 深模块优先（小接口藏大实现）、避浅模块与假接缝、最小修改、TDD、每步回归、任一失败立即停止

## 1. 目标

在现有 ECharts 结果展示之上，新增 5 张「分析洞察型」图表，把「看一眼结果」升级成「嚼碎结果」：

1. **水下曲线** — 回撤的"沉没感"可视化
2. **蒙特卡洛收益扇面** — 把回测"不可全信"的警告画成不确定性区间（展示口径：默认线性轴+累计收益%；扇面外圈跨度 >50 倍时自动切换对数轴+净值倍数，由 `chooseScale` 函数判定，测试锁定）
3. **滚动指标面板** — 夏普/收益/波动率的滚动窗口序列
4. **业绩归因图** — 收益来自哪个板块/哪只票
5. **单笔交易 K 线回放** — 点一笔交易看买卖点录像

落地范围：5 张图全挂在**回测 Tab**；其中水下曲线、滚动指标、业绩归因这 3 张**同时铺到实盘分析 Tab**。

> **「数据同源」边界说明**（修正评审指出的夸大表述）：实盘 deals 与回测 trades **字段不同构**——实盘票代码字段叫 `code`（非 `stock_code`）、买卖方向是 QMT 整数常量（buy=23 / sell=24，见 `trade/book.py`）、时间是 epoch 秒；实盘 `pnl_amount` 是纯价差毛盈亏（任何费用未扣）且仅卖出行有值；2026-08-07 之前的历史卖出 `pnl_amount` 为 None。因此共享的 `attribute_returns` 入参约定为**归一后的 `{code, pnl}` 列表**，归一逻辑留在各调用侧（详见 §4.2/§6.4）。

**不改变**：回测买卖口径（信号日 T 收盘价）、退出优先级、止损止盈算法、任何指标计算语义、任何接口签名与返回结构的既有字段。

## 2. 现状诊断与缺口

### 2.1 回测侧（web/js/charts.js）

现有图表：权益曲线+基准叠加、月收益柱、盈亏分布直方图、退出原因饼图、持仓天数分布、交易表、降级卡、未平仓表。全是「单点全区间结果」，缺「随时间/随持仓/随板块的分解」。

关键事实（已读代码确认）：
- 权益曲线 `data.equity` 每条已带 `date / equity / drawdown`（`charts.js:417-420` 已在用 `r.drawdown`）→ 水下曲线可**纯前端**画。
- 交易明细 `data.trades` 每条已带 `profit_pct`（或 `return`）、`pnl`、`stock_code / entry_date / exit_date / entry_price / exit_price / shares / hold_days`（`charts.js:319-330`）→ 蒙特卡洛可**纯前端** bootstrap（单笔收益率口径 = `pnl / 入场时点总权益`，见 §3）。

### 2.2 实盘侧（web/js/analysis.js）

现有：权益曲线、日历热力图、月收益热力图、盈亏分布、退出原因饼图、成交表、盘后日报卡。缺口同回测侧，且**无基准对比、无归因、无滚动指标**。

关键事实（已读代码确认）：
- `/api/trade/analysis/equity` 返回逐日净值+回撤（`trade/api.py:636-648`）→ 水下曲线、滚动指标可复用。
- `/api/trade/deals` 返回逐笔成交，卖出行带 `pnl_amount`（`analysis.js:617` 已在用）→ 业绩归因的数据上游。

### 2.3 归因所需的「票→行业」映射（已读代码确认）

`policy_kb/build_sector_index.py` 已提供 `build_stock_sector_index() -> {stock_code: sector_code}`（128 个通达信 881 行业〔数量为 docstring 记述，代码无断言，TDX 改版会静默变化〕，进程级缓存，一票多归属取首个）。行业名来自 `DataFetcher.get_sector_list()` 的 `code/name`。

> 边界说明：实盘归因复用这套静态「票→行业」映射是**事后分析**，不是研究信号回灌交易决策；与回测侧 `policy_priority` 打标同一数据源，不跨「只报告不调仓」红线。

## 3. 选定方案

**混合分层**（不全部前端、也不全部后端）：

- **便宜图前端算**：水下曲线、蒙特卡洛——纯算术，前端现成数据即可，后端算了反而多一次网络往返。蒙特卡洛单笔收益率口径 = `pnl / 入场时点总权益`（按 `entry_date` 匹配权益曲线），**不用仓位口径**——仓位口径等于假设每笔全仓，1351 笔复利会虚高三四个数量级（2026-08-13 冒烟实证：旧口径中位 20352x vs 新口径 2.50x 贴合真实终点）。
- **要映射/窗口的图后端算**：滚动指标（bar→日聚合 + 年化）、业绩归因（票→行业映射）——前端拿不到映射，后端是纯函数。
- **要拉数据的图后端供数**：单笔 K 线回放——前端按票拉 K 线，后端给一个薄 adapter 复用 `DataFetcher.get_kline`。

架构上每张图 = **一个深模块**（小接口藏大实现），详见 §4。

## 4. 深模块设计（核心约束）

> 设计纪律：**深模块 = 小接口 + 大实现**。接口越小、门后逻辑越厚，调用方杠杆越大、维护局部性越强。反向（浅模块 = 一堆方法每个一行、或纯转发层）一律不建。
> 参照范式：现有 `renderEquityCurve(domId, data, strategyName, colors)` 已是一个深模块（4 参接口，门后藏基准叠加/回撤辅线/缩放/工具箱/主题）。

### 4.1 前端深模块（5 个导出函数，接口 = 函数签名 = 测试面）

| 深模块 | 接口 | 门后隐藏的实现 | 依赖 |
|---|---|---|---|
| `renderUnderwater` | `(domId, equity, colors)` | 峰值回看、下沉色块填充、回撤负值轴、tooltip、缩放 | charts.js 的 `echartsInit/getColors/hexToRgba` |
| `renderMonteCarlo` | `(domId, trades, equity, colors)` | 逐笔收益抽取（`pnl / 入场时点总权益`，按 `entry_date` 匹配权益曲线；不用仓位口径——1351 笔全仓复利会虚高三四个数量级，2026-08-13 冒烟实证旧口径中位 20352x vs 新口径 2.50x）→1000 次重抽样、5/25/50/75/95 分位、扇面区间填充、超大集下采样、`chooseScale` 线性/对数轴自动切换 | 同上 |
| `renderRolling` | `(domId, rolling, colors)` | 多指标叠图（滚动夏普/收益/波动率）、双 Y 轴、窗口标注 | 同上 |
| `renderAttribution` | `(domId, attribution, colors)` | 板块排序、正负着色、瀑布/堆叠切换、Top-N 个股 | 同上 |
| `openTradeReplay` | `(trade, klineData)` | K 线渲染、买卖点 marker、止损/阶梯档位线、弹窗生命周期 | fetch `/api/stock/kline` + `echartsInit` |

**深度论证**：每个 render 函数对外就 2-4 个参数，调用方（`vera-ui.js` 的回测结果渲染、`analysis.js` 的实盘页）只学一个函数名 + 固定数据形状，就拿到一整张可缩放、可导出、主题自适应的图。所有 ECharts option 组装、边界处理（空数据/负值/色块）都收敛在函数体内——改配色、改交互、修 bug 只动一处（局部性）。

**刻意不建**：不建 `ChartService` 类、不建 `IChartRenderer` 接口、不建「每函数一行」的碎片工具。现在每张图只有一个实现，建抽象层就是假接缝（违反铁律 8「如无必要勿增实体」）。

### 4.2 后端深模块（纯函数，吃数据吐结果，不内部抓取）

| 深模块 | 接口 | 门后隐藏的实现 | 接缝位置 |
|---|---|---|---|
| `rolling_metrics` | `(daily_equity, window=60) -> {window, dates, rolling_sharpe, rolling_return, rolling_vol}` | bar→日聚合（5m/1m 取每日末值）、日收益、滚动窗口、年化、窗口不足处为 null（序列化必须过 `safe_serialize`——FastAPI `allow_nan=False`，NaN 会让响应直接 500） | `backtest/metrics.py` |
| `attribute_returns` | `(items, sector_index) -> {by_sector:[{name,pnl,pct}], by_stock_top:[{code,name,pnl,pct}]}` | items 为**归一后的 `{code, pnl}` 列表**（不是原始 trades，归一在各调用侧）；板块聚合（by_sector 按 pnl 降序）、by_stock_top 按 \|pnl\| 前 10、多归属取首个、未映射票归入「未标」、pct = pnl / 总净盈亏（总和为 0 时 pct 为 None） | 新 `backtest/attribution.py` |
| `/api/stock/kline` | `GET ?code&start&end` → 逐日 OHLC | 复用 `DataFetcher.get_kline`、日期格式归一、field-major→row 序列化 | `server.py` 薄 adapter |

**深度论证**：`attribute_returns` 把「票→行业→聚合→排序→兜底」这一整段复杂逻辑收进一个函数签名，回测侧与实盘侧两个调用方共享（一次实现，两处复用 = 杠杆）；测试直接喂构造好的归一 `{code, pnl}` 列表 + `sector_index`，不碰 TDX、不碰网络。`rolling_metrics` 同理，bar→日聚合是门后实现，调用方只关心「给我滚动序列」。

**刻意不建**：不建 `AnalysisService` 类、不建 `IAttributionProvider` 接口、不建 `RollingMetricsCalculator` 单例。归因/滚动就是纯函数，接缝就是函数签名，测试与调用走同一个面。

### 4.3 文件容器（避 <800 行上限，也避浅拆分）

现有 `charts.js` 已 791 行，5 个新 render 塞进去会破 800 行上限（注：800 行上限是审计惯例——见 CHANGELOG/审计报告——而非 AGENTS.md 明文，`engine.py` 已破例）。故新增 `web/js/charts_deep.js` 收纳 5 个前端深模块，只单向 import charts.js 的共享 helper（`getColors/hexToRgba/echartsInit/esc`），**无循环依赖**。charts.js 保持不动（除 export 已就绪的 helper）。

## 6. 数据流

### 6.1 回测侧（水下 + 蒙特卡洛，纯前端）

`/api/run` → `result_writer.serialize`（已有 `equity` + `trades`）→ `vera-ui.js` → `charts_deep.renderUnderwater(data.equity)` + `renderMonteCarlo(data.trades, data.equity)`。零后端改动。

### 6.2 回测侧（滚动 + 归因，后端算）

`BacktestResult` → `metrics.rolling_metrics(daily_equity)` / `attribution.attribute_returns(items, sector_index)` → 追加进序列化响应 → `renderRolling` / `renderAttribution`。`sector_index` 由 `policy_kb.build_stock_sector_index()` 提供（进程级缓存）。回测侧调用方先把 trades 归一为 `{code, pnl}` 列表再传入；归因金额口径 = trades 现成的 `pnl` 字段（金额口径，扣卖出侧佣金/印花税/滑点、未扣买入侧费用，见 §8），**禁止**用 `profit_pct × entry_price × shares` 重算（`profit_pct` 是全毛收益、一分费用未扣，重算会得到与引擎不一致的第二口径）。

### 6.3 回测侧（K 线回放）

交易表点某行 → `fetch(/api/stock/kline?code&start&end)` → `openTradeReplay(trade, klineData)`。入场/出场日期来自 `trade.entry_date/exit_date`。

### 6.4 实盘侧（水下 + 滚动 + 归因）

`/api/trade/analysis/equity`（逐日净值+回撤）→ 水下/滚动；`/api/trade/analysis/attribution`（后端聚合 deals + 票→行业）→ 归因。实盘侧调用方负责把 deals 归一为 `{code, pnl}` 列表再调共享的 `attribute_returns`——deals 与 trades 字段不同构（`code` 而非 `stock_code`、QMT 方向常量 buy=23/sell=24、epoch 秒时间、`pnl_amount` 仅卖出行有值且为毛盈亏，见 §1 边界说明），归一逻辑不进入共享函数。

## 7. 向后兼容硬约束

1. 不改变回测买卖口径（信号日 T 收盘买入）、退出优先级、止损止盈算法。
2. `BacktestResult`、`PipelineResult`、API 响应既有字段一律不动；新增字段「有才加、失败/空不加」。
3. `charts.js` 现有导出函数签名不变；`renderEquityCurve` 等老图零改动。
4. 实盘 `/api/trade/analysis/*` 既有端点返回结构不变；只新增 `/attribution`。
5. 前端无新图数据时（老结果缓存、降级、异常）静默隐藏新图容器，不影响老图渲染（松耦合降级）。
6. 归因/滚动任一后端计算失败 → 该 key 不序列化 → 前端不渲染对应图，不影响主结果。

## 8. 错误处理

- 不新增宽泛 try/except；后端纯函数失败向上抛，由 `result_writer` 接缝捕获后「跳过该 key」，不拖垮主结果。
- 空数据：`trades` 为空 → 蒙特卡洛/归因图不渲染；`equity` 不足 2 点 → 水下/滚动不渲染。
- 窗口不足（equity 点数 < window）→ 滚动序列对应位置为 null，前端画断点线，不报错（序列化必须过 `safe_serialize`，NaN 在 FastAPI `allow_nan=False` 下会让响应直接 500）。
- 归因映射失败（`build_stock_sector_index` 返部分结果/行业拉取失败）→ 未映射票归入「未标」，不抛。
- K 线拉取失败（停牌/无数据/接口错）→ 弹窗内显式提示「无 K 线数据」，不崩页面。
- 实盘归因跨 2026-08-07 时历史卖出无 `pnl_amount`：端点返回 `meta.skipped_no_pnl` 计数，前端显示「N 笔历史卖出无盈亏记录未计入」提示，不静默吞掉。
- `/api/stock/kline`（Phase 3）需防 inf 漏出导致 500（`/api/benchmark/history` 有同款隐患）、需做股票代码格式校验。
- 盈亏字段口径（已读代码验证，**修正评审发现的硬伤**）：trades 每条有现成 **`pnl` 字段**（`backtest/engine.py:835`，金额口径，扣卖出侧佣金/印花税/滑点、未扣买入侧费用）；归因金额直接用 `pnl`，**禁止**用 `profit_pct × entry_price × shares` 重算——`profit_pct` 是全毛收益、一分费用没扣（`backtest/loop/loop.py:423-428`），重算会得到与引擎不一致的第二口径。

## 9. 测试设计（TDD）

### 9.1 前端（node 可测的纯逻辑部分）

测试对象是独立纯函数模块 **`web/js/deep_math.mjs`**（沿用 `reason_util.mjs` 先例）——`charts.js` 顶层碰 DOM，import 它的 `charts_deep.js` 无法在 node 下测（Phase 1 实证），故数学口径全部抽到 deep_math.mjs，`charts_deep.js` 只做 ECharts 组装。**node 测试不进 CI**（CI 只跑 ruff+pytest），验收靠手动跑 `node tests/web/xxx.mjs`。

- 蒙特卡洛分位数：构造固定收益序列，断言 50 分位中位数、95 分位区间边界数值正确；断言单笔收益率口径 = `pnl / 入场时点总权益`（非仓位口径）。
- 水下曲线峰值回看：构造逐日 equity，断言每个点 drawdown = (equity/历史峰值 - 1)。
- 归因排序/正负分离：构造归一 `{code, pnl}` 列表 + sector_index，断言 by_sector 聚合与排序正确。

### 9.2 后端纯函数（pytest）

- `rolling_metrics`：构造逐日净值，断言滚动夏普/收益/波动率数值；bar 级输入聚合到日正确；窗口不足处为 null 且序列化过 `safe_serialize` 后无 NaN 漏出。
- `attribute_returns`：构造归一 `{code, pnl}` 列表 + sector_index，断言板块 pnl 聚合（by_sector 按 pnl 降序）、by_stock_top 按 \|pnl\| 前 10 截断、多归属取首个、未映射票入「未标」、pct = pnl / 总净盈亏（总和为 0 时 pct 为 None）。
- `/api/stock/kline`：mock `DataFetcher.get_kline`，断言日期归一、OHLC 序列化、异常返错。

### 9.3 每步门禁

每改一个文件：定向测试 → 现有最相近测试 → `git diff --stat` 自查 → 任一旧测试失败立即停。

### 9.4 最终回归

- 新增定向测试全绿。
- `python -m pytest tests -q -rs` 全量不倒退（实施前实测基线，不照抄数字）。
- 既有 `tests/test_snapshot_parity.py`、回测/实盘 parity 测试全绿。
- 手动冒烟：跑一次真实回测 + 打开实盘分析页，5 张图正常渲染、空数据优雅降级、无 console 报错。

## 11. 完成标准

- 5 张新图在回测 Tab 全部可用；水下/滚动/归因在实盘分析 Tab 可用。
- 每个前端 render 是深模块（≤4 参接口，ECharts 组装全在门内）；后端归因/滚动是纯函数深模块。
- 无浅模块（无 `AnalysisService`/`IChartRenderer` 类、无假接缝、无碎片工具函数）。
- 既有字段/签名/算法零变化；新字段「有才加」；空数据/失败静默降级不崩。
- 新旧图共存，无循环依赖，`charts.js` 不破 800 行、新文件 `charts_deep.js` 亦不破。
- 测试不倒退；归因盈亏金额口径 = trades 现成的 `pnl` 字段（金额口径，扣卖出侧费用、未扣买入侧费用，已读 `backtest/engine.py:835` 验证，非猜测）；禁止用 `profit_pct × entry_price × shares` 重算（`profit_pct` 为全毛收益，见 §8）。
