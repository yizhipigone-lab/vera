## 4. 交易规则明细 (所有回测统一, 除特别注明)

### 买入

- 信号: 本地解释器对每个 (股票, 日期) 评估公式条件, 输出布尔信号矩阵
  (决策 #10: 替代原「通达信条件选股 XG」)
- **信号线判定 (2026-08-26 00:31 用户纠正, 重要)**: 输出变量名**不要求叫 XG**,
  输出值**不要求恰好等于 1**——规则是「公式唯一输出, 当日值 > 0 即信号成立」:
  - 信号线 = 公式唯一的输出语句, 两种形态都认: 具名输出 `名字:表达式;`
    或结尾裸表达式 `表达式;`
  - 值判定: > 0 (0/1 布尔输出、涨跌幅之类数值输出统一按 >0 判;
    ">0 还是 ≠0"的边角语义在验收协议里用交叉校准锁定)
  - 实测这批 546 个公式**全部是单一输出结构**: 具名单输出 361 个 +
    裸表达式输出 185 个, 无多输出歧义, 无需额外裁决规则
- 执行: 信号次日开盘价买入 (引擎现有约定)
- 附加规则 (本工作流自带的防呆默认, 配置里可关):
  - **30 日首信号过滤**: 一只票近 30 个交易日内已有过信号, 本次丢弃
    (防止同一个信号反复触发把仓位来回打脸)
  - **卖出后 20 交易日冷却**: 清仓后同票 20 个交易日内禁止回买

### 卖出三件套 (谁先触发谁执行)

| 规则 | 参数 | 说明 |
|------|------|------|
| 硬止损 | 成本价 -6% | 买入价亏 6% 无条件砍, 跳空低开按开盘价保护 |
| 移动止盈 | 激活 3.5% / 回撤 1% | 放风筝: 浮盈 3.5% 后开始跟踪最高价, 从高点回落 1% 即按线价卖出 |
| 时间平仓 | 10 个交易日 | 到期无条件卖出 |
| 优先级 | **止损优先** | 同一根 K 线同时触发时, 止损赢 (priority=stop_first) |
| 阶段止盈 | **关闭** | 用户明确不用 ladder_tp |
| 公式卖出 | 关闭 | 纯买点驱动, 公式不参与卖出 |

### 成本假设 (引擎现值, 报告中注明局限)

佣金万三双边 + 印花税万五 (卖出单边) + 滑点 0.1%。
⚠ 印花税 2023-08 前实为千一, 引擎统一按万五算, 对 2023 年前的结果会略乐观,
报告中标注。

### 5 分钟模式差异 (仅 Stage 4)

- 信号仍在日线周期出 (解释器在日线数据上评估公式), 买入后切 5 分钟线监控三件套
- 盘中触线即时成交 (不等日线收盘)
- 5 分钟数据缺失的股-天自动降级日线 (引擎 degrade_5m 已有机制)
- 数据起点: 按用户要求, 从 5 分钟线最早可得处开始 (本地 5m 缓存 2004 年起;
  实际以每只票 parquet 首行日期为准, 报告列出覆盖情况)

## 5. 淘汰标准 (默认档, 数字可调)

> 比喻: 每一轮考试都有及格线, 越往后及格线越严, 而且后两轮是「换考卷」
> ——不光分数要够, 还得证明不是只会做某一种卷子。

| 阶段 | 区间 | 频率 | 及格线 (全要满足) |
|------|------|------|--------------------|
| S1 | 2020-01~2026-07 | 日线 | ① 区间年化 > 沪深300 同区间年化 ② 最大回撤 ≤ 45% ③ 总交易数 ≥ 30 (排除运气) ④ 胜率 ≥ 40% 或盈亏比 ≥ 1.3 |
| S2 | 2014-01~2026-08 | 日线 | ① 年化 > 基准 ② 回撤 ≤ 40% ③ 总交易数 ≥ 80 ④ 盈利月占比 ≥ 45% ⑤ 前 5 大回撤恢复时间中位数 ≤ 120 交易日 |
| S3 | 2005-01~2024-12 | 日线 | ① 年化 > 基准 ② 回撤 ≤ 45% ③ 任一「5 年子窗口」收益 > -20% (防偏科: 2005-09/2010-14/2015-19/2020-24 四个子窗口都不许崩) |
| S4 | 2004起~今 | 日线信号+5m执行 | 与 S3 自己的日线版对比: 扣费后年化不劣化 (≥ 日线版 × 0.95) 且仍跑赢基准 |
| S5 | 同 S4 | 同 | 不淘汰, 只做池子间对比出报告 |

**兜底保护**: 每阶段结束, 若淘汰后剩余为 0, 自动回捞该阶段得分前 10 名进下一轮并在报告中标注 (防止全军覆没导致流水线白跑)。

## 6. 多 Agent 团队设计 (用户拍板: 完整 LLM 多角色)

### 6.1 分层原则 (先说清楚为什么这样分)

计算和判断分开——**算数的事交给脚本, 拿主意的事交给 AI**:

- 回测、扫描、指标计算是确定性数学, 546 个公式逐个让 LLM「想」一遍既慢
  又不可复现 → 全部走脚本
- 「这个公式是不是看着像未来函数但其实没事」「差 0.2 分被杀的公式该不该
  救」这种需要经验和常识的判断 → 交给 LLM 角色团队
- 脚本每阶段产出结构化 JSON 落盘, Agent 只读 JSON + 源码做判断,
  判断结果也落盘 → 全程留痕、可追溯、断点可续

### 6.2 五类角色

| 角色 | 介入时机 | 职责 | 输入 | 输出 |
|------|----------|------|------|------|
| ① 公式审查 Agent (Auditor) | S0 之后 | 逐批判读源码, 找静态规则漏掉的隐性未来函数 (如子公式引用、变体写法)、确认公式具备「买点」语义而非纯画图指标 | 源码 txt + 静态扫描 JSON | 复核意见 JSON (放行/存疑/建议排除+理由) |
| ② 数据质检 Agent (Warden) | 每阶段跑完 | 审查异常清单: 零信号公式、信号过密 (日均>50 票=没法实操)、一字板无法成交占比、退市股、指标离群值 | 阶段汇总 JSON | 异常标注 + 复核意见 |
| ③ 多空辩论 Agent (Bull/Bear) | S2 结束时 | 对「边缘带」公式 (差 10% 以内被杀/过线) 各写一份多头/空头论证 | 该公式全阶段明细 | 辩论记录 |
| ④ 风险裁决 Agent (Risk Manager) | 辩论后 | 权衡双方, 敲定边缘带公式生死, 防机械阈值误杀或漏放 | 辩论记录 + 指标 | 最终晋级名单 + 理由 |
| ⑤ 报告 Agent (Writer) | S5 之后 | 汇总全部数据生成 HTML 图文报告 + 人话解读 | 全部产物 | final_report.html |

### 6.3 落地实现

- Orchestrator 总控脚本按阶段推进, 每阶段完成即产出中间 JSON
- Agent 调用钩子: `agents/run_agent.py`, 优先走本项目 `brain/` LLM 通道;
  LLM 不可用时自动降级为「规则复核 + 报告中明示该阶段无 AI 复核」,
  保证流水线永不因 LLM 故障卡死
- 每次运行一个 run 目录, agent 意见全部存档备查

   - 静态扫描输出额外产出**每公式的函数使用清单**和**输出结构统计**
     (具名单输出/裸表达式输出/多输出), 供解释器预判可解析性
2. **传参**: 解析 txt 第 2 行参数 (如 `15,0`) 作为默认参数传给**本地解释器**
   (原需求「传参到通达信」已被决策 #10 纯本地方案取代; 参数行缺失用公式内
   默认值)
3. **漏斗从便宜到贵**: S1 只对静态扫描幸存者 (~330) 算全区间信号矩阵;
   S2/S3/S5 全是对同一份信号矩阵的切片重放, 零重复计算 (详见 §7.3)
4. **池子对比零额外计算**: S5 直接从全 A 信号矩阵里按池子成分过滤后重放回测
5. **断点续跑**: state.json 记录 (公式, 阶段) 粒度状态, 中断后 `--from S2`
   续跑; 单公式失败记录后继续, 不中断整批
6. **解释器覆盖度风险**: 通达信函数库数百个, 解释器只实现常用子集 (~60 个);
   遇到不认识的函数 → 公式标记 unsupported 出局并记录原因, 绝不硬猜语义。
   正式跑批前执行 §7.3 解释器验收协议

### 7.3 性能工程设计 (快而不笨, 2026-08-26 用户要求; 00:25 纯本地方案后重写)

#### 瓶颈定位 (先想清楚慢在哪, 再谈快)

| 环节 | 耗时量级 | 是否瓶颈 |
|------|----------|----------|
| 静态扫描 546 个 txt (读文件+正则) | 秒级 | 否 |
| **解释器信号计算 (~330 公式 × 5400股 × 22年, numpy)** | **单公式秒~十秒级, 可多核并行** | **是新瓶颈, 但量级小两个数量级** |
| 回测计算 (引擎矩阵, 信号矩阵切片) | 单公式秒级 | 否 |
| 5 分钟线回测 (仅 ~20 个幸存者, run() 慢路径) | 单公式分钟级 | 次要 |
| LLM Agent 复核 (每阶段异步一次, 不逐公式) | 分钟级 | 否 |

> 原方案的死结是通达信选股——「只有一个窗口的政务大厅」, 排队是宿命。
> 纯本地方案等于把政务大厅搬到自己家: 信号计算变成 numpy 矩阵乘法,
> 5400 只股票 22 年一次算完, 还能开多核。旧瓶颈 (单实例串行、客户端在线、
> 断连重试) 整体消失。

#### 六条提速主线 (纯本地版)

1. **信号矩阵一次算全区间、处处切片** (最关键):
   每个公式只算一次 2005-2026 全区间信号矩阵 (股票×日期布尔矩阵),
   S1/S2/S3 是它的区间切片, S5 池子是它的行切片 (按池子成分过滤行),
   全程零重复计算。比旧方案的「增量补段缓存」更彻底——根本没有第二算。
2. **多进程并行**: 本地计算是 CPU 密集且无单实例限制, 按公式拆任务,
   N 核并行 (8 核机 ≈ 330 公式/8 ≈ 40 个/核), 总墙钟时间再除以核数。
3. **漏斗从便宜到贵**: S1-S3 全是矩阵切片, 便宜; 最贵的 5 分钟线
   只伺候最后 ~20 个幸存者。
4. **一次算、全 run 用**: 六个基准指数全区间绩效、六个池子成分名单、
   交易日历, run 启动时算好缓存, 之后查表。
5. **断点续跑 (公式×阶段粒度)**: state.json 落盘进度, 中断后续跑不重算;
   单公式失败跳过记录, 不废整批。
6. **可观测**: 实时进度条 + 滚动平均耗时预测剩余; 每阶段输出耗时分解
   (解析/信号计算/回测), 给调优留数据。

#### 准确性防线 (快, 但不能假)

| # | 防线 | 说明 |
|---|------|------|
| 1 | **涨跌停可成交性** | 信号次日开盘一字涨停 → 放弃该笔买入 (不追); 持仓卖出日跌停 → 顺延到下一可成交日。不处理这条, 短线公式收益全是虚的 |
| 2 | 停牌/退市 | 停牌日不可买; 退市强制平仓 (引擎 reason=11 已有); S1-S3 全A含已退市股, 缓解幸存者偏差 |
| 3 | **解释器语义一致性** | 通达信函数有特有语义坑: SMA(X,N,M) 是递推不是简单均线、REF 负周期、HHV/LLV 窗口边界。防线: ① 每函数单元测试 (手工小样本对比, 如 MA(C,5) 5 根K线手算) ② 代表性公式交叉验证 (见下方验收协议) ③ 算不了的函数 → unsupported 出局, 不硬猜 |
| 4 | 样本外参考列 | final 幸存者额外展示「最近 12 个月」分段表现 (只展示不淘汰), 防全区间筛选过拟合 |
| 5 | 随机抽检 | 每阶段随机抽 3 个公式, 人工核对信号日期与成交价 |
| 6 | 引擎路径坑 | `run_cached` (快) 不支持 5m 降级, `run()` (支持) 用于 S4; S1-S3 用快路径 |
| 7 | 复权口径 | 本地 parquet 前复权与通达信选股默认前复权同口径; 单次 run 内数据快照统一, 无跨段漂移 |

#### 解释器验收协议 (跑批前必过)

1. **单元测试全绿**: ~60 个函数逐一手工小样本比对 (构造 5~10 根 K 线,
   手算 vs 解释器输出)。
2. **代表性公式交叉验证**: 挑 3~5 个只用已实现函数的经典公式
   (如 MACD 金叉类), 通达信在线时用 XG 跑同区间选股, 对比信号
   (股票,日期) 一致率 ≥ 99% 才放行; 通达信不在线则改用常识锚点验证
   (如「10日均线上穿30日均线」公式的信号必须发生在金叉日)。
   交叉验证同时锁定信号值语义 (输出 >0 还是 ≠0 算成立, 见 §4 信号线判定)。
3. **解析覆盖率报告**: 546 个公式里成功解析/unsupported/死因分布先出
   一份小报告, 覆盖率异常低 (如 <55%) 先查解释器再开跑。

#### 时间预算 (校准后回填, 以下为估算)

| 阶段 | 假设 | 预估 |
|------|------|------|
| S0 静态扫描+解析 | 546 文件 | < 5 分钟 |
| S1 信号+回测 | ~369 公式, 8 核并行 | 15~40 分钟 |
| S2/S3 切片回测 | 幸存者, 矩阵切片 | 5~15 分钟 |
| S4 5m | ~15 公式 × run() 慢路径 | 1~3 小时 |
| S5 池子 | 矩阵行过滤 | 分钟级 |
| 报告+Agent | HTML + LLM | 半小时内 |
| **合计** | | **约 2~4 小时, 当天完成** |

> 另计一次性成本: 解释器开发与单测认真做约 1~2 天 (这是「自己重新写」
