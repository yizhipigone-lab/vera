## 一、一句话结论（大白话）

之前的盘后日报，「交易明细」挤成双列表格，看不出简称、看不出赚了多少、看不出剩多少。

现在改成**每条交易单独成一块**，一眼看全：

> 买了/卖了多少股、成交金额、赚了多少钱（红绿色）、因为啥买卖、卖出占当初买入的几成、还剩多少股多少市值。

顺手修了「飞书没收到推送」的元凶（卡片 weight 写成小数被飞书静默拒收），并给投递加了业务码校验，以后再被拒会在日志里说话。

---

## 二、交易明细长啥样（举例）

**卖出块**（以 000878 云南铜业 8/7 卖出为例）：

```
云南铜业 000878.SZ · 卖出
300股 × 16.70 = 5,010.00
盈亏 -21.00 (-0.42%)              ← 亏损红色
原因 阶梯止盈档位1: 预埋 16.51 ...
卖出比例 27%                       ← 本次卖300 ÷ 累计买入1100
剩余 200股 · 市值 3,340.00
```

**买入块**（不显示盈亏、不显示卖出比例，因为买入没有这两个概念）：

```
宁德时代 300750.SZ · 买入
1000股 × 10.00 = 10,000.00
原因 尾盘选股
剩余 1000股 · 市值 10,000.00
```

字段缺一个就少一行（fail-soft），不会因为某笔数据不全整张卡崩掉。

## 三、卖出比例口径（用户拍板）

**卖出比例 = 本次卖出股数 ÷ 当初买入总股数（累计买入，含历史补仓）**

为什么是「累计」而不是「最初那一笔」：

| 口径 | 000878 实例 | 问题 |
|---|---|---|
| ✅ 累计买入（含补仓） | 买600+补仓500=1100；卖300→**27%**；卖200→**18%** | 合理，全卖最多100% |
| ❌ 最初那一笔 | 只算第一次的600；卖300→50% | 补仓后全卖会超100%，反直觉 |

分母用「到卖出时刻为止的累计买入」，重放按时间顺序累加，符合「当初一共买了多少」的直觉。

## 九、遗留 / P2（审计建议，本次不动）

1. **消费者线程做重放**：`_build_trade_summary` 在 EventEngine 消费者线程里同步跑 `load_all_trades` + 全历史重放。15:05 盘后时段 + 整段 try/except 兜底 + 量级几十毫秒，**搭 EOD 已有慢活流的车，可接受**。P2 可考虑把剩余/比例计算挪到 notifier worker 线程。
2. **trades 表无上限增长**：O(N) 重放，多年后 N 可能到十万级。P2 加按年归档。
3. **research 脚本独立复刻**：`send_today_feishu.py` 是 `_build_trade_summary` 的人工对账版，逻辑分叉。生产口径变（如税费回溯）时需手动同步，属技术债。

## 十、怎么用

- **自动**：每个交易日 15:05 自动推送（`_DailyTimer` → `EVENT_EOD` → `_notify_daily`），无需干预。
- **手动补发/核对**：
  ```
  python research/send_today_feishu.py --dry      # 预览不发
  python research/send_today_feishu.py --verify   # 真发+读飞书业务码
  python research/send_today_feishu.py            # 真发（走 notifier 队列）
  python research/send_today_feishu.py 2026-08-07 # 指定日期
  ```
