## 一、现在的状态

### 1. 前端整体（已摸清，别重新踩）

- **单文件壳 + 多 JS**：`web/index.html`（一个文件装 CSS 变量 + 全部 HTML + 页签）+ 
  `web/js/vera-ui.js`（回测页主逻辑）、`web/js/trade.js`（交易页）、`web/js/analysis.js`
  （分析页）、`web/js/charts.js`（图表/明细表）。
- **服务**：回测页由 `server.py`（8080）serve；交易页数据打 `trade_main` API（8081，跨域）。
- **字体/配色已达标**：本地托管 `Space Grotesk` + `JetBrains Mono`（`web/fonts/`），
  `:root` 一套 light + dark CSS 变量（`--bg/--surface/--card/--up/--down/--accent...`），
  红涨绿跌语义正确。**这块不用动**。

### 2. 已做完（本轮 quick wins，未提交）

- 抽了 `.hint` 类（`font-size:11px;color:var(--text2)`），替换 index.html + trade.js +
  charts.js 里 11 处内联灰字提示。
- 11 处 9px/10px 辅助字提到 11px（表单 label、日志、KPI 提示、进度文字、表单错误、
  板块提示/匹配/空态、日历金额/成交数、概念"更多"）。
- 改动文件：`web/index.html`、`web/js/trade.js`、`web/js/charts.js`（未提交）。

### 3. 响应式现状（本次要改的）

- `web/index.html:64` 写死 `body{...min-width:1280px}`，**全文件零断点**
  （唯一 `@media` 是 `prefers-reduced-motion`）。
- 已有折叠能力：`.sidebar`（380px）+ `.sidebar-toggle`（折叠按钮，`transition:width .25s`），
  但只在桌面手动折叠，**不随屏幕宽度自动响应**。
- 页签结构：`#pageLab/#pageTrade/#pageResearch/#pageRecords/#pageAnalysis/#pageData`
  用 `position:fixed;top:41px;left:0;right:0;bottom:0`（约 line 308），`.tab-bar` 置顶。

### 4. 设计审计结论（design-review 技能，源码审计路线）

- **评分**：设计 B+ / AI slop A（有真字体、有 CSS token、有"卦"字 logo，不是 AI 味界面）。
- **HIGH-1**：无响应式（`min-width:1280px`）—— 唯一"影响能不能用"的缺陷。
- **MEDIUM-2**：字号偏小（已在本轮修到 11px）。
- **MEDIUM-3**：内联样式泛滥（已用 `.hint` 收了一部分，仍有余量可继续抽类）。
- **LOW-4**：`.form-section-title` 与 `.sector-header-title` 的金色竖条 `::before` 重复，可合并 token。
- **LOW-5**：按钮缺 `:active` 反馈态。

## 二、响应式方案（建议断点）

| 屏宽 | 布局 |
|---|---|
| ≥1024px | 现状不变（三栏：sidebar + 主区 + 明细） |
| 768–1023px | 平板：sidebar 默认折叠（复用 `.sidebar-toggle`），主区占宽 |
| <768px | 手机：sidebar 变 overlay 抽屉，主区全宽 |

**参考范式**：用户给 DSH 装的 `dsh-web-mobile` 插件（`github:mexiaosqwq/dsh-web-mobile`）
就是同一件事 —— 窄屏隐藏左侧 rail、目录变抽屉、会话全宽。思路可直接搬：**窄屏 sidebar
从"占位列"改成"overlay 抽屉 + 左缘浮动开合按钮"**。

## 三、下一步（按优先级）

1. **去掉 `min-width:1280px`**，加断点基础骨架（`@media (max-width:1023px)` / `(max-width:767px)`）。
2. **手机端 sidebar 改抽屉**（overlay + 遮罩 + 左缘按钮，学 dsh-web-mobile 的 y=72px 避开摄像头带）。
3. **交易页密集表格**（`.td-table`/`.trade-table`，10-11px mono）手机端处理：
   横滚容器 or 精简列（只留代码/现价/当日盈亏/浮盈，其余进详情）。
4. 平板断点：sidebar 默认折叠 + 弹窗限宽居中（768-1023px）。
5. 收尾 LOW-4/LOW-5（竖条合并 token + 按钮 `:active`）。

## 四、坑（血泪）

- **8081 是用户真在跑的实盘 trade 服务**，前端 E2E 只能用 Playwright `page.route`
  mock API，**绝不 bind/inject/pollute 8081**；`data/trade/trade.db` 是真数据，别碰。
- `web/index.html` 是一个大文件（1300+ 行），CSS 和 HTML 混在一起，改响应式**优先加
  `@media` 块，别重构 DOM 结构**（交易页表格是 JS 字符串拼的，动结构要连带改 trade.js）。
- 交易页表格列多（代码/简称/数量/可用/成本/现价/当日涨幅/当日盈亏/市值/浮盈/盈亏%/入场/
  持仓天数/阶梯档/卖出按钮，共 15 列），手机横滚是最低风险的过渡方案，别一上来就砍列。
- 本地部署优先：字体/资源都本地，别引 CDN/外链（Google Fonts 已被移除过）。
- 另一会话可能在并行干活，进程/文件锁冲突（WinError 32）属常态，重跑即可。
