## 二、怎么做的

### Phase 1：语义搜索

**技术选型**：
- 嵌入模型：`BAAI/bge-small-zh-v1.5`（512 维，fastembed ONNX 版）
- 运行时：**fastembed**（纯 ONNX 运行时，~200MB，无 torch）——实施初版曾用 sentence-transformers + torch 走过弯路（详见下），三审时按铁律 4 迁回 fastembed
- 存储：numpy `vectors.npy` + `meta.jsonl`，无外部数据库依赖
- 搜索：numpy 矩阵点积（两侧 L2 归一化 = 余弦相似度），毫秒级

**模型下载（国内网络实测结论）**：fastembed 首次运行自动下载 ONNX 模型（~200MB）到 `data/brain_model_cache/`。直连 HuggingFace 被墙，`_get_model` 内置两个缺省环境变量（不覆盖用户已有配置）：`HF_ENDPOINT=https://hf-mirror.com`（镜像）+ `HF_HUB_DISABLE_XET=1`（镜像不支持 xet 协议，大文件走 xet 会 401，实测踩出）。缓存目录不用 fastembed 默认的 Temp 目录（会被系统清理）。

**torch 弯路记录（如实）**：实施初版因 HF 被墙改走 ModelScope 下载，拿到 PyTorch 权重遂用 sentence-transformers + torch（~2GB），构成对铁律 4 的偏差。三审验证 fastembed 经 hf-mirror + 禁用 xet 可正常下载后，已迁回 fastembed，pyproject 移除 torch/sentence-transformers，索引用 ONNX 向量全量重建，检索评估维持 12/12。

**分块策略**：
- 按 `\n\n` 分段 → 合小段（<200 字）→ 硬切长段（>450 字）→ 丢碎块（<50 字）
- 公司文件自动提取 frontmatter 中的 name/行业作为前缀，丰富向量语义
- **分块前剥离 YAML frontmatter**（node_id/export_date 等机器元数据不进向量、不进 snippet）

**索引完整性（二审修复）**：
- `_save_index` 原子写：两文件均先写 tmp 再 `os.replace`，meta 最后落盘——读者任意时刻只看到完整的旧索引或新索引。原实现非原子两文件写 + 无线程间/进程间保护，实测已造成 vectors 9046 行 ≠ meta 5839 行的撕裂态（search 张冠李戴或静默返空）
- `_load_index` 对齐校验：vectors 行数 ≠ meta 行数即降级返空并提示重建，不再用错位的 idx 取 meta
- 线程安全：`threading.Lock` 保护进程内 build/update 互斥；跨进程安全由原子写保证

**索引规模**：4598 文件 → 4693 块，检索评估 **12/12（100%）**（frontmatter 剥离后块数下降系元数据移除的正常现象）

**LLM 调用方式**：通过 Bash CLI（`python -m brain.search_engine search "查询词"`），与大脑的 Read/Grep/Glob/Bash 工具模型完全吻合

### Phase 2：联网搜索

**搜索引擎优先级**：百度 → 必应 → DuckDuckGo（大陆可达性排序）

- 百度：`requests` 直连 HTML 解析（大陆最快，无 API key）
- 必应/DuckDuckGo：通过 `ddgs` 库调用
- ddgs 版本签名漂移做 try/except 兜底
- **空摘要回退（二审修复）**：百度 HTML 只能稳定抽到标题（snippet 恒为空），原实现百度返回标题即命中、不再回退，LLM 的主力数据源只有标题没有摘要。现改为：结果有条目但 snippet 全空 → 视为无效，自动回退到带摘要的 backend
- 已知余项：百度结果 URL 多为 `baidu.com/link?url=` 跳转链，标注来源时不透明；HTML 解析对反爬/改版脆弱（有 bing/ddg 回退兜底，可接受）

**安全措施**：
- 搜索结果经 `sanitize_untrusted()` 清洗（去控制字符/防 prompt injection）
- 两次调用间隔 ≥2s 防限流
- 任何失败返空列表 + 提示"退回训练知识"

**Prompt 路由（B1/B2 双模式）**：
- B1 纯知识：概念解释/方法论，直接用训练知识
- B2 实时信息：含"最近/新闻/政策/股价"等时间敏感词 → 先调 `search_web` 搜索再回答

### Phase 3：评估升级

**v1 → v2**：
- 题库：10 题 → 30 题（5 类 × 6：本地查证 / 概念知识 / 实时信息 / 判断分析 / 边界与诚实）
- 评分：仅正则 `must_contain` → 正则 + LLM judge 五维度（准确性/完整性/引用质量/反证充分/表达清晰，各 1-5 分）
- v1 `golden_set.json` 完整保留作为回归基线

**LLM judge**：
- 独立 claude CLI 子进程（不用 `ask_brain`，避免研究助理 persona 污染评分）
- JSON 解析容忍 markdown 围栏/前后杂波/缺维度检测/越界检测
- `<answer_to_evaluate>` XML 包裹防 prompt injection
- 报告落盘 `output/brain_eval/YYYYMMDD_HHMMSS.json` + `.md`
- **async 上下文安全（二审修复）**：原实现直接 `asyncio.run()`，在已有事件循环的线程（如 research_api 的 async 上下文）调用会 RuntimeError；现自动检测并切换到新线程跑独立 loop

### 基础设施修正

三项关键修复（均为计划外偏差，如实列出）：

1. **Bash 权限**：`claude_cli.py` 加 `--dangerously-skip-permissions`。**注意：该 flag 对所有大脑调用生效**，大脑 LLM 的任意 Bash 命令（含写/删）零审批直通——这是 B2 联网搜索的前提（-p 非交互模式下 search_web 调用会被权限闸自动拒绝），代价是安全模型只剩 QMT 对账 + prompt 红线两道软闸。**已经主人拍板保留**，`claude_cli.py` docstring 已补诚实声明。
2. **CLI 默认值**：`__main__.py` timeout 120→300s、max-turns 8→20，与 `claude_cli.py` 核心默认值对齐，解决 DeepSeek agent loop 轮次不足问题
3. **模型下载路径**：HuggingFace 直连被墙，fastembed 经 `HF_ENDPOINT=https://hf-mirror.com` 镜像 + `HF_HUB_DISABLE_XET=1`（镜像不支持 xet 协议，大文件 401，实测踩出）自动下载到 `data/brain_model_cache/`；两变量由 `_get_model` 缺省设置，不覆盖用户已有配置
