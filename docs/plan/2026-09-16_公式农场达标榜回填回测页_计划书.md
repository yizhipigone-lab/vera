# 2026-09-16 公式农场达标榜回填回测页 计划书

## 背景与目标

达标榜（农场页面）目前只能"看"不能"用"：用户看到达标公式后，要去回测页手工重填公式名和最优组合参数，既慢又容易抄错。本计划在「达标」组每行加「→ 送去回测页」按钮：**点击 → 回填回测页表单（公式名+最优组合参数+农场口径）→ 顶部横幅说明来源并给「恢复原配置」→ 用户人工核对后自己点「开始回测」**。

**已拍板（2026-09-16）**：按方案 A（只回填不代跑）实施；按钮只放「达标」组（样本不足/未达标组不放，防误导）。

**为什么不代跑（方案 A 的核心理由）**：回测页结果与农场粗扫结果常并排比较，口径必须用户眼见为实确认——"人工过目"是防两口径混淆的最后一道闸；且回测是分钟级重操作，表单是工作台不是发射台。

## 侦察结论（全部实读代码/数据确认）

1. **参数源**：粗扫明细 CSV（`output/gs_5m_sweep/<GS>/sweep_*.csv`）每行带完整组合参数列 `cost,act,dd,ladder,time_days,cond_days,cond_profit`——无需解析 key 字符串。档案 `archive.json` 的 `best` 目前只存 `key/annret/maxdd/calmar/winrate/trades`，需扩存 params 并一次性重建回填全部 822 条。
2. **当前数据无阶梯止盈边界**：36 粗扫组合 `ladder` 全为 `off`；档案 783 条 keyed 最优组合全部 `Loff`；7 条达标公式最优组合 = 硬止损 20% + 移动止盈激活 8%/回撤 0.5% + 时间止损 20 或 40 天（与收割总榜沉淀的"普适最优出场配置"一致）。仍设计阶梯止盈的诚实降级（见三-4）。
3. **回测页字段齐全**：沪深300（`cfgUniverse` value=23）、5 分线（`cfgPeriod` value=5m）、T 日收盘（`cfgEntryPriceMode` value=close_t 且为默认）、优先级单选 `name="cfgPriority"` 取值 `stop_first/ladder_tp_first/trailing_first`（移动止盈优先=trailing_first 是 HTML 默认 checked）。
4. **回填不走 `applyConfigDict`**：该函数对 dict 里**缺失的字段会重置为 HTML 默认值**（`[web/js/config.js:203]`），会冲掉用户的佣金/滑点/最低买入等设置。改为前端专用回填函数**只写自己要写的 ~19 个字段**，其余字段一律不动。
5. **粗扫口径实锤**（2026-09-16 验证链）：`farm_backtest` 未传 `--universe-type` → `gs_5m_sweep` 取 `ConfigLoader.load_defaults()`（只读 `config/default.yaml`，第 20 行 `type: "23"` 沪深300）→ 与 `farm_backtest.CALIBER` 显示常量一致；回测页保存的 `current.yaml`（全 A）不影响粗扫。

## 自我审阅记录（开工前逐行核验，2026-09-16）

1. **勘误 1（真实自相矛盾，已修正）**：初版 `SWEEP_CALIBER` 把 `priority` 写成机器值 `"trailing_first"`——但 `farm_backtest` 粗扫报告抬头用 `CALIBER["priority"]` 做**显示**（现为"移动止盈优先"），别名化后报告会打印英文。已改为 `priority="移动止盈优先"`（沿用现有显示值）+ 新增 `priority_value="trailing_first"` 供回填接口用。
2. **验证通过项**：`cfgStart/cfgEnd` 是 YYYYMMDD 文本框（`[web/index.html:495]`），window 去横线转换正确；`cfgEntryPriceMode` 默认即 `close_t`（`[web/index.html:489]`）；优先级单选三值与默认值（`[web/index.html:573]`~575）；`applyConfigDict` 缺失字段重置默认值属实（`[web/js/config.js:203]`，不走它的决策成立）；36 组阶梯全 off、档案 keyed 最优组合全 Loff、7 条达标 key 结构与收割总榜沉淀一致；`load_defaults()` 只读 default.yaml（`[utils/config_loader.py:75]`）；GS 编号四位数字（`^GS\d{4}$` 白名单成立）；`farm_summary` 加第 3 个公开函数后接口数 3 ≤ 8。
3. **边界确认**：`farm_backtest.CALIBER` 改为别名后新增键（universe_type/entry_price_mode/priority_value）对现有读取处（universe/period/dividend/capital/max_buy/entry/priority/combos）纯增量、零影响。

## 详细设计

### 一、后端

**1. `core/farm_rules.py` 新增 `SWEEP_CALIBER`（粗扫口径单一真相源，防第三份手写）**：

```python
SWEEP_CALIBER = {
    "universe_type": "23", "universe": "沪深300 (TDX type 23)",
    "period": "5m", "dividend": "前复权",
    "capital": 3_000_000.0, "max_buy": 20_000.0,
    "entry": "信号日 T 最后一根 5m bar (15:00) 收盘买入",
    "entry_price_mode": "close_t",
    "priority": "移动止盈优先",        # 显示值 (报告抬头在用, 自我审阅勘误 1)
    "priority_value": "trailing_first",  # 机器值 (回填单选框用)
    "combos": 36,
}
```

`farm_backtest.CALIBER` 改为 `= farm_rules.SWEEP_CALIBER` 别名（沿用 future_tokens 收口模式；报告抬头读取处不变）。回填接口与报告抬头从此同源——侦察结论 5 指出的"两处手写会漂"问题顺带收口。

**2. `farm_backtest._slim_best` 扩存 params**：从 CSV 行取 `cost/act/dd/ladder/time_days/cond_days/cond_profit` 存入 `best["params"]`（float/int 转换，ladder 留字符串）。`update_archive` 不动（归档条目自动带 params）；完成后跑一次 `--rebuild-archive` 回填 822 条历史。

**3. `core/farm_summary.py` 新增第 3 个公开函数 `backtest_prefill(data_root, gs)`**（接口总数 3 ≤ 8）：

- 读 `archive.json` 该 gs 条目：不存在 → `KeyError`；`best` 为空或 `params` 缺失（旧档案）→ `ValueError("该公式没有带参数的最优组合, 请重建档案 (④ --rebuild-archive)")`；
- 返回 `{gs, file, url, window, params, caliber(SWEEP_CALIBER 子集), combo_text, ladder_note}`；
- `combo_text` 中文组装（术语铁律）：`硬止损20% + 移动止盈激活8%/回撤0.5% + 时间止损20天`（`cond_days>0` 追加 `+ 条件时间止盈N天/盈利M%`）；
- `ladder != "off"` → `ladder_note="原组合含阶梯止盈(档位未存入粗扫明细), 已按关闭回填, 请人工核对"`（当前数据触发不到，为未来留的诚实降级）。

**4. `core/farm_api.py` 新增 `GET /api/farm/prefill?gs=`（薄路由）**：gs 白名单校验（`^GS\d{4}$`，防任意键探测）；KeyError → 404「该 GS 不在档案」；ValueError → 409「需重建档案」；成功 200 返回回填包。

### 二、前端

**5. `api.js`**：`fetchFarmPrefill = gs => get('/api/farm/prefill?gs=' + encodeURIComponent(gs))`。

**6. `vera-ui.js`**：

- 达标组 `rowHtml` 末尾加 `<button class="btn farm-to-bt" data-gs="...">→ 回测页</button>`（事件委托挂在 `#farmBoard` 上，样本不足/未达标组不加）；
- 点击流程：`_farmToBacktest(gs)` →
  ① **快照**：记录即将被覆盖的 19 个字段当前值（见字段表）到 `_farmPrefillSnapshot`；
  ② `fetchFarmPrefill(gs)` → **逐字段直写**（不走 applyConfigDict，侦察结论 4）：公式名/公式参数清空/沪深300/5m/close_t/区间/300万/2万/硬止损启用+阈值/移动止盈启用+激活+回撤/阶梯止盈关闭/时间止损启用+天数/条件时间止盈按 cond_days/优先级 trailing_first；
  ③ `switchTab('backtest')` → 显示横幅；
- **横幅**（`index.html` 回测页配置区上方新增 `<div id="farmPrefillBanner">`，默认隐藏）：内容 = `已从公式农场回填: GS0607(捕捉起涨点) · 最优组合 硬止损20%+移动止盈激活8%/回撤0.5%+时间止损20天 · 口径: 沪深300·5分线·300万·单票2万·T日收盘 · 请核对后手动点「开始回测」`（+ ladder_note 若有）+ 两个按钮「恢复原配置」「知道了」；
- **恢复原配置**：把快照逐字段写回，隐藏横幅；「知道了」仅隐藏横幅（保留回填）。

**回填字段表**（快照与直写同一集合）：`cfgFormula, cfgFormulaArg, cfgUniverse, cfgPeriod, cfgEntryPriceMode, cfgStart, cfgEnd, cfgCapital, cfgMaxBuy, cfgCostStopEn, cfgCostStopVal, cfgTrailingEn, cfgTrailingAct, cfgTrailingDD, cfgLadderEn, cfgTimeEn, cfgTimeVal, cfgCondTimeEn` + 单选 `cfgPriority`（含 `cfgCondTimeDays/cfgCondTimeProfit` 仅 cond_days>0 时写，但快照照记 → 共 21 个快照点）。

### 三、参数→字段映射

| 组合参数 | 回测页字段 | 转换 |
|---|---|---|
| cost = -0.20 | cfgCostStopEn=✓, cfgCostStopVal | `abs(cost)*100` → 20 |
| act = 0.08 | cfgTrailingEn=✓, cfgTrailingAct | `act*100` → 8 |
| dd = 0.005 | cfgTrailingDD | `dd*100` → 0.5 |
| ladder = off | cfgLadderEn=✗ | 非 off 时 ✗+ladder_note 降级 |
| time_days = 20 | cfgTimeEn=✓, cfgTimeVal | 直写 |
| cond_days = 0 | cfgCondTimeEn=✗ | >0 时 ✓+天数+盈利%×100 |
| priority | cfgPriority=trailing_first | SWEEP_CALIBER |
| window | cfgStart/cfgEnd | `2024-09-11`→`20240911` |
| caliber | cfgUniverse=23, cfgPeriod=5m, cfgEntryPriceMode=close_t, cfgCapital=3000000, cfgMaxBuy=20000 | SWEEP_CALIBER |
