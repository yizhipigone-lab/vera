## 0. 一句话目标

给选股结果(候选池)每只票打"十五五行业优先级"标签(第一/二/三优先级 / 规避 / 未标),在 web 选股表加一列展示,辅助人工决策。**纯展示**:不验证、不筛选、不进交易。

---

## 1. 背景

详见 ADR-0001 / CONTEXT.md。政策匹配三层架构:A(行业,静态映射,零 LLM)/ B(概念,radar_lite)/ C(个股,LLM 研判)。MVP 先做 A。

A 层用**通达信 128 行业**(弃申万——用户决策:通达信永久免费、VERA 已接、无需映射桥)。十五五映射原按申万组织,翻译为通达信版(申万仅作方向参考)。

## 4. 数据

### 4.1 tongdaxin_priority.json

128 个通达信行业 → 四档(P1/P2/P3/AVOID)。结构示例:

```json
{
  "881319.SH": {"name": "半导体", "priority": "P1"},
  "881326.SH": {"name": "消费电子", "priority": "P1"},
  "881291.SH": {"name": "军工电子", "priority": "P2"}
}
```

**翻译流程**(grill Q3 钉定):

1. 拉 128 行业清单(`DataFetcher.get_sector_list()`)
2. 我基于用户的申万映射起草稿(名称语义对齐,四档)
3. **用户 review 草稿**,改不认同的边界
4. 定稿

**边界默认**:通达信有、申万映射没明说的行业 → **第三档(P3,中性保守)**。ETF/可转债/不在 128 行业的票 → 未标。

### 4.2 票→行业反向索引

VERA 现有 `get_sector_stocks` 是**正向**(行业→票),无反查(已读 [data_fetcher.py:564-607](../../core/data_fetcher.py) 全方法确认)。建 `build_stock_sector_index()`:

- 遍历 128 行业 × `get_sector_stocks` → `{票: 行业}` dict
- 进程级缓存(参考 `core/data_cache.py` 的 DataCache 模式)
- 一只票多归属(若发生)取第一个 + 记 warning(通达信 881 通常一只票一行业,实施时验证)

首次构建 ~17s(128 次 `get_sector_stocks`,有 sector 缓存;**依据**:选股缓存二期实测 TDX 批次地板 ~16s,见 CLAUDE.md),之后命中。

## 5. 接缝

- `PipelineResult` 加 `policy_priority`(dict 票→档位,**建议字段不执行**)
- **插入点**(plan-audit W-1 修正,[pipeline.py:335](../../pipeline/pipeline.py) 因子过滤之后、[:348](../../pipeline/pipeline.py) step2_backtest 之前):调 `policy_tagger.tag(selections)` 拿 `policy_priority` dict,用局部变量持有;在 [:392](../../pipeline/pipeline.py) `PipelineResult` 构造时塞入。此点 selections 已是最终候选池,且回测未跑(标签不依赖回测结果)。
- web 选股表加列;`policy_priority` 随 `ResultWriter.serialize` 的 resp **自动进** `last_result.json` / `{ts}.json`(三共用,无需额外接缝;plan-audit W-2 修正);`reports.json`(ReportGenerator)本期不改。
- **失败/超时兜底**:`policy_tagger` 抛异常 → `policy_priority = None`(PipelineResult 默认值),serialize 走"有才加 key"不出现该字段,选股/回测/交易**不受影响**(松耦合铁律;Pipeline 该步 `try/except` 隔离)。

## 8. 不破坏现有(规则 3)

- `policy_kb/` 独立新模块,不动 `selection/` `backtest/engine.py` `trade/`
- `PipelineResult` 加字段是**加法**(默认 None);`_FIELDS` 元组追加是**加法**(现有 5 字段语义不变,新增第 6 个)——实测 [:51-66](../../pipeline/result_writer.py) 的 `__contains__`/`__getitem__`/`get` 对老字段行为不变
- `ResultWriter.serialize` 用"有才加 key"(`if policy_priority:`),None 时 resp 形状与现状**字节一致**(对齐 `degradation` 先例,backward compat 硬约束 [:8](../../pipeline/result_writer.py))
- web 加列是加法,不改现有列
- `policy_priority` 失败 → None → serialize 不加 key,选股/回测/交易零影响
- 现有测试全绿;选股结果数字字节级不变(基线 diff)

## 9. 风险

| 风险 | 控制 |
| --- | --- |
| 反向索引多归属(票属多行业) | 取第一个 + warning;实施时验证通达信 881 是否真的一票一行业 |
| 128 行业清单变化(通达信调整) | 失效行业记 warning 跳过;`tongdaxin_priority.json` 加版本字段 |
| 翻译草稿边界错(误判优先级) | 用户 review 定稿;边界默认 P3 保守 |
| 松耦合破坏(policy 崩了影响选股) | tagger 失败兜底 None;Pipeline `try/except` 隔离;serialize 有才加 key |
| 不验证 = A 层无数据支撑 | 用户有意(ADR-0001 记录);价值靠辅助 + 喂 B/C 锚点 |
| **板块拉取失败**(TDX 断/限流)(plan-audit W-3) | `get_sector_stocks` 返 [](实测 [:604-607](../../core/data_fetcher.py));反向索引空→候选全员未标;tagger 兜底 None,与现有失败语义一致 |
| **板块成份股漂移**(底层缓存无 TTL)(plan-audit W-4) | `core/data_cache.py` 无 TTL(CLAUDE.md 已知问题),反向索引继承此问题(新股进/退市剔除看不到);本期跟随底层不单独打补丁;记 §10 后续,待板块缓存 TTL 项目一起改 |
