## 1. 背景与探针结论（全部实测，非推测）

**公式体检精度核实**: 体检全流程日线——选股 `default.yaml:26 period: "1d"`, 回测 `BacktestEngine(config).period` 缺省 "1d" ([engine.py:181](../../backtest/engine.py#L181))。因子体检是因子级评估 (IC/族/A-B), 日线是正确粒度, **1m 项目与体检无关, 不动体检**。

**1m 探针结论**:

| 探针项 | 实测结果 |
|---|---|
| TDX 周期参数 | `period="1m"` 一次通过 ✓ |
| 每日 bar 数 | **恰好 240 根** (09:31~11:30 120根 + 13:01~15:00 120根), 无集合竞价杂 bar, 首 bar 09:31 末 bar 15:00 |
| 数据深度 | **≥2026-01-26** (非 1 月初; 01-01~01-23 无数据)。02-17~02-23 春节休市无 bar 属正常 |
| API 单次上限 | **~24000 根** (100 交易日) — 长窗口必须分段, 首次深拉曾被截断误判深度 |
| 单股成本 | 39 交易日 0.23s; 全市场 5000 只回填估算 ~19 分钟 |
| 缓存体积 | ~0.1 GB/月, 全部深度 ≈ 0.5 GB |
| 回测矩阵 | 全市场 × 22 交易日窗口 ≈ **1.3 GB/份** (与 5m 日常用法同量级; 深度短天然限制窗口) |

**5m 渗透面核实** (1m 需对应处理的全部点位):
- 常量: [backtest/_constants.py:18](../../backtest/_constants.py#L18) `_BARS_PER_DAY {"1d":1,"1w":1,"5m":48}` + `_PERIODS_PER_YEAR` + `:58 STD_5M_BAR_TIMES`
- 引擎: [engine.py:271](../../backtest/engine.py#L271) `if self.bars_per_day == 48` 触发 `_drop_nonstandard_5m_bars` ([engine.py:871](../../backtest/engine.py#L871), 按 STD_5M_BAR_TIMES 过滤杂 bar); `degrade_5m` ([engine.py:894](../../backtest/engine.py#L894))
- K线缓存: [kline_cache.py:54](../../core/kline_cache.py#L54) 目录只有 ("1d","5m"); `:236` gap 检测 `period in ("1d","5m")`; `:450` `if period == "5m"` 部分 bar 检测 (48 根不变量)
- 回填: [backfill_kline_cache.py:55](../../tools/backfill_kline_cache.py#L55) `--period choices=["1d","5m"]`
- 公式自适应扫描: [formula_runner.py:20](../../core/formula_runner.py#L20) `_CALENDAR_BARS_PER_DAY {"1d":1.0,"1w":1/7,"5m":48.0}`
- server 映射: [server.py:157](../../server.py#L157) `period=="5m" → sel 1d / bt 5m`
- UI: index.html `select#cfgPeriod` (日线/周线/5分线)

## 2. 目标与非目标

### 目标
- web 回测页可选"1分线": 选股仍 1d (尾盘信号), 回测 1m 精度 (与 5m 同模式: sel_period=1d, bt_period=1m)
- 回测区间硬限制 ≥20260126 (截断+告警, 不静默)
- K 线缓存/回填/引擎 bpday 泛化 (240 根不变量)
- 小池 (沪深300) e2e → 全市场 e2e → 1m vs 5m 归因对比报告

### 非目标（明确不做）
- **体检精度变更** (保持 1d, 已核实全流程日线)
- **1m degrade** (1d 填充 240 根): 1m 仅 ~6 个月深度, 降级面是"几乎全历史", 无意义; 区间直接截断
- 周线/其他分钟级周期
- tools 批量脚本 1m 化 (后续按需要另开)
- 公式批次并行 (另开任务, 与周期无关)

## 3. 设计

### 3.1 常量层 ([backtest/_constants.py](../../backtest/_constants.py))
- `_BARS_PER_DAY` + `"1m": 240`
- `_PERIODS_PER_YEAR` + `"1m": 60480` (240×252; 与 engine/degrade_report 的 `.get(self.period, bars_per_day*252)` 兜底公式自洽, 审计 B.6 确认)
- 新增 `STD_1M_BAR_TIMES` (frozenset, 照 `_std_5m_bar_times()` 生成器, [constants:38-55](../../backtest/_constants.py#L38)): 09:31~11:30 每分钟 120 个 + 13:01~15:00 每分钟 120 个
- 新增映射 `STD_BAR_TIMES = MappingProxyType({"5m": STD_5M_BAR_TIMES, "1m": STD_1M_BAR_TIMES})`, 引擎按 period 选表 (STD_5M_BAR_TIMES 名称保留向后兼容)
- **[v2 修订]** `_CALENDAR_BARS_PER_DAY` ([formula_runner.py:20](../../core/formula_runner.py#L20)) **不加 "1m" 映射**: 选股保持 1d 用不到; 加上则未来任何 1m 选股会被 `_MAX_SCAN_COUNT=3000` 封顶 ([formula_runner.py:26](../../core/formula_runner.py#L26)) 静默浅扫 (3000 根 ≈ 12.5 个 1m 交易日), 不如让它查表失败显式回退

### 3.2 kline_cache 分钟级泛化 ([core/kline_cache.py](../../core/kline_cache.py))
- `__init__` mkdir: 加 `"1m"` 目录 (`_parquet_path` 依赖目录已存在, 硬必需)
- gap 检测 `period in ("1d","5m")` → `("1d","5m","1m")`
- 部分 bar 检测: `_warn_partial_bars_5m` ([kline_cache.py:475](../../core/kline_cache.py#L475), 硬编码 `_BARS_PER_DAY_5M = 48`) → 泛化为 `_warn_partial_bars_intraday`, 按 `BARS_PER_DAY[period]` 查表 (5m=48, 1m=240); `period == "5m"` 判断改 `in ("5m","1m")`
- **[v2 新增] 单段跨度守卫**: `_fetch_and_store` 一次 tdx_fetcher 调用拉全段, 1m 下 >90 交易日即超 24000 根被静默截断 → 按 ≤90 交易日 (21600 根) 分段拉取合并 (防审计 B.3 的极端窗口截断)

### 3.3 回填 ([tools/backfill_kline_cache.py](../../tools/backfill_kline_cache.py))
- `--period` choices + `"1m"` ([tools/warmup_kline_cache.py:27](../../tools/warmup_kline_cache.py#L27) 同族预热工具顺带补, 审计遗漏项)
- **24000 根上限守卫**: 回填分段长度 ≤ 90 交易日 (21600 根), 分段循环推进 (与 §3.2 单段守卫同源)
- 起始日 20260126 (深度起点), 状态文件 `backfill_state_1m_20260126.json`
- 全市场首跑 ~19 分钟, 后台执行

### 3.4 引擎 ([backtest/engine.py](../../backtest/engine.py))
- **[v2 修订, 审计 HIGH-1] degrade 守卫落在条件本身**: `engine.py:280` `if self.degrade_5m and self.bars_per_day > 1` → `if self.degrade_5m and self.bars_per_day == 48`。web 默认 degrade_5m=True ([server.py:188](../../server.py#L188)), 无此守卫 1m 必踩静默全错 (48 槽位 reindex 丢 192/240 根, loop 按 bpday=240 解释); 落在条件上则 tools 直构造 BacktestEngine 的路径同样免疫。同时 period=1m 且 degrade_5m=true 时 logger.warning 明示"1m 无降级"; `engine.py:193` 注释"仅 period=5m 等分钟级"措辞同步改
- **[v2 修订, 审计 HIGH-2] `_drop_nonstandard_5m_bars` 不改名**: 有 2 个外部调用方 ([gs_5m_sweep.py:141](../../tools/gs_5m_sweep.py#L141), [quantqq_5m_sweep.py:190](../../tools/quantqq_5m_sweep.py#L190))。做法: 新增 `_drop_nonstandard_intraday_bars(close, ..., bar_times)` 泛化函数, 旧名保留为 5m 委托 alias; `engine.py:271` 条件 `== 48` 改 `in (48, 240)` 并按 `STD_BAR_TIMES[self.period]` 选表
- **区间硬限制**: `run()` 入口, `period=="1m" and start_time < "20260126"` → 截断 start 到 20260126 + `logger.warning` (不静默); end 不设限
- **[v2 新增, 审计 MED-3] 取数跨度守卫**: 极端 max_hold (90) → win_td=105 → 单股单次调用 ~127 交易日×240 ≈ 30.5k > 24000 上限 → 前段静默截断。对策: §3.2 的 `_fetch_and_store` ≤90 交易日分段从源头解决 (所有调用方免疫); 同时 1m 的 win_td 应用层 cap 90 (`_resolve_window_td` 或 run 入口 warning)
- 稀疏窗口取数 (`get_kline_windowed`): period 透传; 月桶按股票聚合, 配合上条单段守卫后无 24000 风险
- **[v2 修订, 审计 MED-5] matrix_cache**: 22 天窗口 ~0.8-1.3GB/份可控; 但阶段2归因区间 (~100 交易日) 全市场单份 ≈ 3.8GB (+准备段副本峰值 5-6GB RAM)。对策: **1m matrix_cache keep=2**; 归因跑分月窗口 (单月 ≤ 22 交易日) 或沪深300, 不做"全市场×100天"单发
- entries/tradable/loop/_build_entry_signals: 已按 bpday 参数化 (5m 路径实测), 零逻辑改动
- 进度 (core/progress): fetch/loop 均 done/total 速率法, 无需改
- **[v2 新增, 审计 LOW-7] benchmark 免改确认**: `benchmark.py:105` `is_minute = BARS_PER_DAY.get(period,1) > 1` 加常量后自动 True; 指数 1m 深度不足时自然落回日粒度回退 (与 5m 同哲学)。实施时跑一次确认指数 1m 可取即可

### 3.5 server + UI
- [server.py:158](../../server.py#L158): `period=="1m"` 同 5m 模式 → sel_period="1d", bt_period="1m"

### 3.6 归因复验（阶段2，本计划书内含）

## 4. 风险与对策

| # | 风险 | 对策 | 严重度 |
