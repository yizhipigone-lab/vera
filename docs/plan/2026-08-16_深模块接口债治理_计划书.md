### P0-1 消除 `prefilter.py` 规则镜像（正确性隐患 + 契约违反）✅ 已完成（2026-08-16）

> 已落地：预筛条件下沉到各策略的 `prefilter(x)` 方法（标量束 `PrefilterInputs`），`TriggerPreFilter` 改为遍历 `dispatcher.strategies` 统一调用；策略缺 `prefilter` → fail-open 恒 True（防静默漏卖）。全量测试通过。

- **原现状**：`prefilter.py` 为性能优化把每个卖出策略的触发条件抄了一份作为预筛；文件头契约是「拿不准返 True」（fail-open），但兜底却 `return False`，**新策略漏补 = could_trigger 返 False = 静默漏卖**。
- **目标（两步）**：
  1. **立即缓解（先堵正确性洞，非直接改 line 91）**：当前 `prefilter.py:91` 的兜底 `return False` **同时覆盖**「已知策略都不触发」和「未知策略存在」两种情况，直接改 True 会把 84.7% 的空跑跳过率打成 0%、预筛整体失效。正确做法：在 `__init__` 把 `dispatcher.strategies` 的 key 与已知策略集合（cost_stop/ladder_tp/trailing/time_stop/cond_time/first_day/atr_stop + formula_sell）比对，**仅当存在未知策略时才恒 True**，否则维持现有预筛。注：当前 builder 恰好只有这 8 个策略（`[backtest/loop/builder.py:86-119]`），所以「未知策略漏卖」是**未来风险**而非现状 bug，本步是防御性修复。
  2. **派生重构**：让预筛条件从策略对象派生——每个策略暴露一个**标量输入束**谓词（如 `prefilter_condition(bundle)`），prefilter 遍历策略统一调用，不再手抄每策略 if 分支。**用标量束而非 `(pos,bar,ctx)`**，因为预筛的本意就是跳过构造完整对象。

### P2-2 三处「行情陈旧判定」统一到 fail-closed ✅ 已完成（2026-08-16）

> 已落地：新建共享函数 `trade/quote_stale.py::is_quote_stale(quote, clock, stale_sec)`（单一判定真相源，含 tick_ts_missing/no_ts/ts_none/stale 四类原因），monitor/executor/rotation 三处改为调它；executor 的 fail-open「无 ts 判不陈旧继续卖」改为 fail-closed「无 ts 判陈旧不卖」（有意修复）。80 测试通过。

- **现状（审计修正）**：三处阈值都是 `quote_stale_sec=60`（**一致**，之前「阈值不一致」是错断言）。真实分歧有两重，**物理成因是 `monitor.on_quote` 的 effective_ts 回填**（`[trade/monitor.py:167-179]`：tick 缺 ts 键或 ts 值为 None 时，用 event_ts/本地时钟顶上，并打 `tick_ts_missing` 标记）：
  ① **ts 缺失处理**——`executor` 只判 `("ts" in quote) and (quote["ts"] is None)`，ts 键缺席或值为 None 都按「不陈旧」继续卖；`rotation` 把无 ts 当「陈旧」；
  ② **tick_ts_missing 标志**——`monitor`（走回填路径）和 `rotation` 都显式查该标志，而 `executor` 不查（tick 显式缺戳但 ts 键存在且有值时 executor 会放行）。
  统一时两重分歧 + 回填语义都要并进共享函数，否则只改 executor 会留下 monitor 回填这条漏网暗线。
