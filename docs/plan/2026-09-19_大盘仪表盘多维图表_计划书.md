## 0. 侦察结论（计划的事实基础，全部实读验证过）

1. **日线序列不用新写后端**：现有 `GET /api/market_position/history?limit=N`（market_position_api.py 第 38-53 行）直接返回 daily.jsonl 记录，字段路径已实测：`indices.{shanghai,hs300,chuangyeban}.pct_10y`、`breadth.{above_ma20_pct,above_ma60_pct,hl_spread}`、`turnover.{amount_yi,amount_pct_1y}`、`limit.{up,down}`、`indices.hs300.regime`。注意 2026-09-17 之后两天的记录指数字段为 null（采集缺口），前端要容忍 null（echarts 折线 null = 断点，正好如实呈现）。
2. **ERP 全历史（erp.jsonl 5208 行，2005 至今）没有出口**：`mpr._read_erp()` 是私有函数，`market_position_runner` 公开接口已满 8 个（铁律 8 上限）→ 新读口落在 `market_dashboard_runner`（现有 6 个公开函数，+1 = 7，不越线），函数内自行按行解析 jsonl（纯传输，5 行，注释指向 mpr._read_erp 为正典解析器，避免私有跨模块调用）。
3. **总分历史只有 1 天**（dashboard.jsonl）：五维堆叠面积图、事件甘特图**本轮不做**，预留空态（防欺诈性美观）。
4. **gauge/雷达数据源**：`/api/market_position/dashboard` 快照已有 `scores.final_total` 与 `scores.dimensions.{key}.{avg,weight}`，零后端改动。
5. **上线硬约束**：本次唯一改动的 Python 文件是 market_position_api.py + market_dashboard_runner.py（各加一个只读端点/函数）→ **server.py 需要重启才生效**（trade_main 不动，无 15:05 约束；重启前先查 /api/status 确认无回测在跑）。前端改动照旧刷新即生效。
6. **折叠区画图坑**：display:none 容器里 echarts 量出 0 宽 → 「只说现状」折叠区的图在 `<details>` 的 toggle 事件里首开才画（旧 market_position.js 的 `_lowEvidenceOpen` 同款模式，但该文件已不被页面引用，模式在 market_dashboard.js 重写一份并注明出处）。

## 2. WP1 后端明细

- `core/market_dashboard_runner.py` 新增第 7 个公开函数：
  ```python
  def erp_series() -> dict:
      """ERP 全历史序列 (2005 至今), 供仪表盘「股债性价比长卷」图。
      返回 {"success": True, "points": [[date, erp_pct], ...], "median_10y":…} ——
      中位/极值直接复用最新 daily 记录里 valuation 块的现成口径, 不重算。"""
  ```
  实现：读 `mpr.ERP_PATH`，逐行 json 解析取 date/erp（×100 转百分数、留两位）；文件不存在/空 → `{"success": True, "points": [], "reason": "…"}`（fail-soft，绝不抛）。中位/极值/当前分位从 `mpr.latest()` 的 valuation 块带出来（没有就给 null，前端藏标注线）。
- `market_position_api.py` 新增路由 `GET /api/market_position/dashboard/erp_series`，薄层转发 + 同款 fail-soft，注释写明「不 import trade」铁律不变。
- 不改调度、不写盘、不联网 —— 纯读本地文件。
