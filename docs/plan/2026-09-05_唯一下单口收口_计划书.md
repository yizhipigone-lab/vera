## 三、接口设计

### 3.1 PlaceRequest(小数据类,差异的合法表达)

```python
@dataclass(frozen=True)
class PlaceRequest:
    code: str
    direction: int          # DIRECTION_BUY / DIRECTION_SELL
    price: float            # 实际委托价: 发单/订单簿/落库都用它 (auto_buy 传
                            # order_price —— P0-6 入账口径)
    qty: int
    price_type: object = PRICE_TYPE_LIMIT
    risk_price: float | None = None   # 风控口径价; None=用 price。
                                      # auto_buy 传参考价(现状 271-273 风控先于
                                      # 定价, 金额闸吃参考价——审计 P1, 不得混用)
    intent_flags: dict | None = None  # {"rotation": True} / {"manual": True} / None
    remark_prefix: str = ""           # "L1"/"X"/"R"/"B" (进 V{mmdd}-{seq}{前缀})
    fill_payload: dict | None = None  # fill_ctx.register 的 {label, detail, ...}
    audit_kind: str = ""              # 成交审计 kind
    audit_message: str = ""           # 成交审计文案
    audit_extra: dict | None = None   # 成交审计附加; 需含 order_id 的路径以
                                      # "order_id": None 占位放历史键位, 脊柱
                                      # 回填 —— 键序与现状逐字节一致 (审计 P2)
    account_immediately: bool = True  # False = 人工买: 跳过订单簿+落库
```

### 3.2 place_order 签名与脊柱顺序(7 步)

```python
def place_order(self, req: PlaceRequest, *,
                risk_ctx: "RiskContext | None" = None
                ) -> tuple[str | None, str | None]:
    """唯一下单口: 风控→取号→发单→登记成交原因→订单簿→落库→审计。
    返回 (order_id, None) 成功;(None, why) 风控拒。
    风控拒时本方法**静默返回**——不写审计(风控层每道拒绝已自写 audit,
    risk.py:119)、不打 warning(五路调用方各自已有留痕, 再记会造成
    ladder/人工买双倍告警)。拒绝后的额外留痕(_sell 的 exit_risk_reject /
    rotation 的 rotation_risk_reject / auto_buy 的 _skip)由调用方按各自口径补。"""
```

脊柱内部顺序:
1. `OrderIntent(code, direction, req.risk_price if req.risk_price is not None else req.price, qty, **req.intent_flags)` → `self._risk.check(intent, risk_ctx or self._build_ctx())`;拒 → **静默** `return None, why`
2. `remark = self._next_remark(req.remark_prefix)`
3. `order_id = self._gw.order(code, direction, req.price, qty, req.price_type, remark)`
4. `self.fill_ctx.register(order_id, req.fill_payload)`
5. `if req.account_immediately:` → `self._book.apply_order_update(order_id, OS_REPORTED, code=…, direction=…, price=req.price, qty=…, remark=remark)`
6. `if req.account_immediately:` → `self._store.save_order({…, "created_ts": self._clock()})`(created_ts 单点,泰山石油注释收编于此)
7. `extra = dict(req.audit_extra or {})`;`if extra.get("order_id", "__missing__") is None: extra["order_id"] = order_id`(占位回填,保历史键位)→ `self._store.write_audit(req.audit_kind, req.audit_message, extra)`

**回填可用(_refresh_can_use)不在脊柱里**——executor 内部两路(_sell/place_ladder)作为调用方尾巴自做,位置语义见 §五.3(审计 P5/P6)。

### 3.3 五路调用对照表(收口后的参数映射)

| 路 | risk_ctx | 风控价 risk_price | intent_flags | remark_prefix | price_type | account_immediately | 调用后尾巴(留在调用方) |
|---|---|---|---|---|---|---|---|
| place_ladder | 缺省(self._build_ctx) | None(=委托价) | None | f"L{tier}" | PRICE_TYPE_LIMIT | True | mark_tier + tier_state.save + 回填可用 |
| _sell | 缺省 | None(=委托价) | None | "X" | 形参透传(含对手最优) | True | _pending 登记 + lock.rebind + 回填可用 |
| rotation | self._build_ctx() | None | {"rotation": True} | "R" | PRICE_TYPE_LIMIT | True | register_external_sell(卖单) |
| auto_buy | self._build_risk_ctx() | **参考价 price** | None | "B" | PRICE_TYPE_LIMIT(order_type) | True | cash 扣减 + dispositions |
| _cmd_buy | self._build_risk_ctx() | None | {"manual": True} | "B" | PRICE_TYPE_LIMIT | **False** | — |

**风控上下文归属**: 生产环境三路注入的 builder 最终同源于 `trade_main._build_risk_ctx`(trade_main.py:1153;:319/:425/:437 注入)。place_order 用 `risk_ctx` 参数(调用方传入已构建的 ctx)而非 builder——保留测试注入异构 ctx 的能力,行为零变。

**拒绝路径归属**: place_order 静默返回 `(None, why)`;各路拒绝后的额外动作保留在调用方——
- place_ladder: `_logger.warning` + `continue`(现状 318,不占 remaining)
- _sell: `write_audit("exit_risk_reject", …)` + `return False`(现状 558-561)
- rotation: `write_audit("rotation_risk_reject", …)` + `return None`(现状 686-691)
- auto_buy: `_skip(code, f"风控拒: {why}")` + `continue`(现状 275)
- _cmd_buy: `_logger.warning` + `return`(现状 1092-1093,注释"拒绝审计 risk 层已写")
