## 0. 阅读指引（先说大白话）

这次要干什么：把现在那个"满屏百分比、但一句结论都没有"的大盘页，重做成一个**打开就能看懂
"现在市场什么温度、比昨天变没变、最近有没有大事"** 的仪表盘。顶部一条状态栏告诉你数据更新到
什么时候、下次什么时候更新、还能手动刷新；下面四个页签：①总览（一眼结论）②指标明细（分数怎么来的）
③事件跟踪（最近有什么大事、影响还剩几天）④历史走势（总分曲线）。

**一句话原则**：这个仪表盘是个**温度计**，不是**天气预报**。它说"现在 38 度"（描述现状），
不说"明天会下雨"（预测涨跌）。所以最后那个分数旁边，会一直挂着它**历史上到底靠不靠谱**的证据，
你自己决定信几分。

## 1. 背景与目标

### 1.1 为什么现在那个页"水"

现有大盘页（前端 `#pageMarket`，`web/index.html:1438-1593`；渲染 `web/js/market_position.js:628` 的 `enter()`）其实塞了 6 张卡片：三大指数位置表、估值、历史照镜子、前期涨跌分桶、候选择时规则影子回放、低证据折叠区。**信息并不少。**

但它**一句结论都不给**。打开全是"十年百分位 90.9%""年化波动 28%"——全在描述现状，
没有一行回答"所以现在什么温度、该拿几成仓"。

而且这是**当初刻意的设计**，不是漏做：`[core/market_position_runner.py:1525]` 明确写着
"我们**不合成一个总分**，因为同一天、同一批数据，换一个判定口径就能得出相反结论"；
`:1904` 写着"它们只描述现状，不作预测依据（注意：我们不给它们权重、也不合成总分）"。

### 1.2 本次目标

用户要的东西（权重 + 总分 + 仓位映射）恰好是当初主动决定不做的那块。**本项目不推翻"谨慎"的
设计哲学，而是在它的地基上加一层"诚实的总分"**——总分照做，但：

1. 权重**按证据定**，不拍脑袋（见 §5.3）；
2. 总分**标注历史可信度**（它跟之后 20 个交易日走势的相关性是多少，如实给出来）；
3. 定位为**温度分**（描述现在），明确**不联入任何实盘仓位调度**（守业务铁律 1）；
4. 基准仓位改名**环境参照仓位**，只作参照。

### 1.3 交付范围（一次做完）

| 层 | 交付 |
|---|---|
| 打分引擎 | `core/market_score.py`（纯函数，14 指标，可单测） |
| 事件引擎 | `core/market_events.py`（分级/线性衰减/落库，初期支持人工录入） |
| 编排+取数+落库 | `core/market_dashboard_runner.py`（调度取数、打分、快照落 `dashboard.jsonl`） |

| 前端 | `web/index.html` 的 `#pageMarket` 改造为 4 子页签 + 顶部状态栏；新建 `web/js/market_dashboard.js` |
| 调度 | `scheduler/__main__.py` 新增 3 个 job（16:30 / 次日 08:30 / 月度宏观轮询） |
| 测试 | `tests/test_market_score.py`、`tests/test_market_events.py`、铁律 AST 断言 |

**分层原则（照本项目既有 `data_cache_api.py` 薄层 / `core/*` 深模块 的分工）：**

- `core/market_score.py`：**纯函数**，输入指标值 → 输出分数。**不联网、不读文件、不写盘、不 import trade**。可离线单测。
- `core/market_events.py`：**事件引擎**，管理事件列表（分级、衰减、落库、合计限制）。**不 import trade**。
- `core/market_dashboard_runner.py`：**编排**，唯一负责联网取数 + 调度上面两个 + 落库。**不 import trade**。
- `market_position_api.py`：**薄层**，只校验参数 + 转发（照 `[market_position_api.py:2]` 的既有注释）。
- 前端：**只读**，`fetch` API。

**铁律守护**：`core/market_score.py`、`core/market_events.py`、`core/market_dashboard_runner.py`
与 `core/market_position*.py` 一样，**都不得 import trade**（业务铁律 1：宏观与研判只出报告）。
由 `tests/test_market_position.py` 既有 AST 断言机制扩展守护（见 §10）。

### 5.2 阈值空白档补档说明（诚实记录）

需求书阈值表有两处**实测发现悬空的空白档**，本方案补档并如实标注，不属于"擅自修改标准"
（原档位全部保留，只在原档位**没覆盖到的区间**补一个合理档）：

1. **PPI 同比 3.8%**（2026 年 8 月实测值）：原档位“由负转正回升→8 / 0附近震荡→5 /
   持续通缩(<-2%)→0 / 高位过热(>5%)→1”——3.8% 哪个档都不落。本方案**保留**“近3个月由负转正→8”
   的趋势判断（月度数据易判定，不属过拟合），并在原档没覆盖到的 2~5% 区间补“温和扩张→6”。
2. **美元兑人民币汇率**：需求原档是按"美元指数量级（90~110）"写的（<100→8 等），
   换成人民币量级（约 6.7~7.3）后**原阈值完全不可用**，本方案按"偏离 250 日均线幅度"重定
   （《审计报告》§3.5 已说明为何用美元兑人民币替代美元指数）。

> 这两处补档在方案书送审时明确列出，等用户确认；用户若不同意，可按需求书"数据暂缺沿用历史得分"
> 处理，但那样 3.8% 的 PPI 会长期显示"暂缺"，更不可取。

### 5.3 维度权重（按证据定，不拍脑袋）

**权重是代码常量，出处写在常量注释里，可审查、可人工改。不做"每次根据体检动态调权"**
（那会让总分权重天天变，不连续、无法回溯）。

初始权重建议值（**送审，等用户确认**）：

| 维度 | 权重 | 证据依据（出处） |
|---|---|---|
| 估值与股权赔率 | **0.30** | 体检中**唯一同时通过 3/6/12 个月检验的正向指标**（见 `web/index.html:1477` 对估值区的说明 + `_dimension_validity` 结果），证据最强 → 提权 |
| 国内宏观与盈利 | **0.20** | 月度低频数据，对日频大盘的**短期**指导弱（长期有意义）→ 较需求降权 |
| 市场趋势与量价 | **0.20** | 趋势跟踪类指标短期有效（但注意：位置类指标方向与直觉相反，见 runner 体检结论）→ 持平 |
| 市场微观情绪 | **0.15** | 体检显示"资金层/广度层被证伪"（`_dimension_validity` 多项四个持有期均看不出相关性）→ 降权 |
| 海外流动性 | **0.15** | 外部约束，中期影响 → 持平 |
| **合计** | **1.00** | 由测试断言锁定 |

> 与需求书原权重（0.25/0.25/0.20/0.15/0.15）的差异：**估值 0.25→0.30、宏观 0.25→0.20**，
> 其余不变。理由如上表"证据依据"列。这是"按证据定权重"的具体体现。

> **诚实说明（自审第二轮发现）**：上表"证据依据"列里，**只有估值维度有现成的体检证据**
> （`_dimension_validity` 对现有指标的检验结论）。宏观、微观情绪、海外三个维度里的指标
> （M1-M2 / PMI / PPI、两融 / PCR、美债 / 汇率）是**本次新接入的，项目手里没有它们的历史体检数据**——
> 所以这三个维度的权重本质是"现有体检（广度层被证伪 → 情绪降权）+ 一般先验（宏观低频 → 降权）"，
> **不是纯证据**。**承诺**：等新指标积累满 3 年历史后，用同一套体检方法（Spearman + 双窗口一致性，
> 即 `_dimension_validity` 的口径）**重新校准这套权重**，并把校准结果写成独立审计报告。
> 在那之前，权重表以代码常量形式固定（不随体检动态漂移，保证总分可回溯）。

### 5.4 总分合成公式

```
基础总分 = Σ( 各维度内有效指标平均分 × 维度权重 )
最终总分 = clamp( 基础总分 + 事件修正分, 0, 10 )
事件修正分 ∈ [-1, +1]（见 §6.2）
```

**维度内平均分**：该维度下**所有有效指标**的算术平均（缺失指标按拍板决策 7，
用该维度**剩余有效指标**均分，不上收权重）。

**维度内指标全部缺失时**：若某维度所有指标都取不到数，该维度**沿用上一交易日该维度得分**并标注“数据暂缺，沿用历史得分”；若连上一日也没有（冷启动），按中性 5 分记并标注。

**总分校验（需求第一条第 3 款）**：每次计算完成后，
`|基础总分 - Σ(维度加权分之和)| ≤ 0.1`；超出则判异常 → 自动重试 1 次 →
仍失败则沿用前一交易日有效数据，**不保存异常结果**。

### 5.5 总分映射环境参照仓位（改名，只作参照）

| 总分区间 | 定性 | 环境参照仓位 |
|---|---|---|
| 8.0 ~ 10.0 | 极佳赔率，牛市环境 | 75%~100% |
| 6.5 ~ 7.9 | 偏乐观，趋势向好 | 50%~75% |
| 5.0 ~ 6.4 | 中性震荡，结构性行情 | 30%~50% |
| 3.5 ~ 4.9 | 偏悲观，磨底阶段 | 15%~30% |
| 0 ~ 3.4 | 高风险，熊市主跌段 | 0~15% |

**改名说明**：需求书叫"基准仓位区间"。本项目改为"环境参照仓位"，并在页面与报告里
固定附带一句铁律提示："只读参照，不联动任何实盘仓位调度（业务铁律 1）"。

### 5.6 总分可信度标注（本方案的关键增值）

总分旁边固定显示**这个总分历史上跟"之后 20 个交易日走势"的相关性**。

实现：用现有 `history(0)` 的历史快照，对每个交易日重算"当时的基础总分"，
再对之后的 20 个交易日实际收益做 Spearman 相关（复用 `[core/market_position_runner.py:605]` `_spearman`）。
页面如实显示：相关系数 + 一句大白话（如"这个分数跟之后 20 天的涨跌几乎没关系，只能当温度计看"）。

> 诚实前提：由于 14 个指标里 10 个是新接入的，**历史快照不足时此标注显示
> 「历史数据不足，暂不提供可信度」（需求第五条第 3 款兜底机制同款口径）**，不强行算。

### 6.1 `core/market_score.py` —— 纯函数打分引擎

**职责**：输入"14 个指标的原始值 dict"，输出"各指标分数 + 维度分 + 基础总分"。
**不联网、不读文件、不写盘、不 import trade**（可被离线单测，铁律）。

    ...

    "trend":     ("hs300_vs_ma200","turnover_amt","breadth_20d"),
    "sentiment": ("margin_trend","option_pcr"),
    "overseas":  ("us10y","usdcny_ma_dev"),

def score_indicator(key: str, value: float | None) -> float | None: ...

**关键实现要点**：

- 缺口径（社融/CME）**不出现在 THRESHOLDS**（直接没有这俩 key），从结构上保证不会被误算。

### 6.2 `core/market_events.py` —— 事件引擎

**职责**：管理事件列表（分级、线性衰减、过期移除、合计限制 ±1），输出"事件修正分"。
**不 import trade**。

**分级规则（照需求 §四，硬编码）**：

| 等级 | 有效期 | 单事件上限 | 判定关键词（初始） |
|---|---|---|---|
| 史诗级 | 30 天 | ±1.0 | 印花税、IPO 暂停、平准基金、924、5万亿 刺激 |
| 普通重大 | 10 天 | ±0.5 | 降准、降息、美联储加息/降息超50bp、数据大幅超预期 |
| 短期情绪 | 3 天 | ±0.2 | 常规月度数据、官员表态、小幅政策 |

**线性衰减**：`当日分数 = 初始分 × (剩余天数 / 总有效期)`，到期自动清零移除。

**合计限制**：所有生效事件修正分求和后 `clamp(-1, +1)`。

**落库**：`data/market_position/events.jsonl`，每行一条事件
`{id, level, title, initial_score, start_date, expire_days, logic, source}`。

**接口**（本期）：
- `add_event(...)`：人工录入（经 API，供用户在页面上加事件，或命令行）；
- `daily_tick(today)`：每日衰减 + 移除过期 + 返回当前合计修正分与生效清单；
- `list_active(today)`：当前生效事件（供 TAB3 渲染）。

**LLM 自动扫描**：**已落地（2026-09-19 改）** —— 不做"在打分引擎里嵌 LLM 调用"（那样分数不可复现），
改为**独立的 Agent 定时扫描**：Agent 用 WebSearch 抓近期事件 + 按 `core/market_event_scan.py` 顶部
`RUBRIC`（写死的判定标准，保证每次判断一致）归类 + 经 `core/event_cli.py add` 落库
（`source="agent_scan"`，`logic` 记判定理由与来源，可追溯可删）。每日 16:40 自动跑（WorkBuddy
自动化 id 0033f587…）。原 `scan_news()` 占位保留但未使用。

### 6.3 `core/market_dashboard_runner.py` —— 编排 + 取数 + 落库

**职责**：唯一的"联网 + 调度 + 落库"方。调 `market_score` + `market_events`，取 14 个指标数据，

**取数层三条硬规矩**（来自《审计报告》§3.7/§3.8，写成代码注释 + 测试）：
1. **重试**：每个源最多 3 次、间隔 1~2 秒；
2. **超时**：单次 25 秒（`socket.setdefaulttimeout`）；
3. **失败降级**：全失败则**沿用上一次有效值**，并在快照里给该指标标

| 版本 | 时点 | 两融/美债 | 动作 |
|---|---|---|---|
| A股收盘版 `refresh_close` | 交易日 16:30 | 用 T-1 值并标注滞后 | 全量取数 + 打分 + 落快照 |
| 全球补齐版 `refresh_fill` | 次日 08:30 | 用刚到的 T-1 两融 + T-1 美债 | **重取两融/美债/汇率 + 重算总分 → 覆盖同一交易日快照**（宏观轮询由 refresh_macro 单独负责，见下） |

**宏观轮询 `refresh_macro`**：每天 09:30 跑，内部判断"今天是否在月度发布窗口
（每月 9~15 日 + 月末 3 天）"；不在窗口 → 秒回 no-op；在窗口 → 抓 M1-M2/PMI/PPI，
有新数据就更新对应低频指标得分并重算，无新数据（源还没发）就跳过。

| **宏观轮询** | **每日 09:30** | 发布窗口内抓 M1-M2/PMI/PPI | 央行/统计局多在上午发 |

**非交易日/节假日**：`add_daily` 内部走交易日历（`scheduler/trading_calendar.py`），
自动跳过，沿用最近交易日有效数据（需求第一条第 1 款③）。
**长假复牌**：复牌日 08:30 的全球补齐把假期期间的海外变化一次性补齐（两融/美债取最新可得值）。

### 9.2 状态栏（顶部，对齐需求第四条）

  否则 → 下一交易日 08:30 全球补齐版）；
- **倒计时**：前端 `setInterval` 每秒减，归零时自动 `enter()` 重新拉取；

- **数据截止**：4 个标签（A股行情 / 两融 / 海外 / 宏观），取 `data_asof`，`stale=true` 或滞后的用警示色。

页面底部固定：

> ⚠️ 风险提示：本仪表盘仅量化大盘环境（温度分），不构成投资建议，不预测指数点位与未来涨跌。

## 13. 风险与降级

| 风险 | 应对 |
|---|---|
| 东财系端点不可用（实测已发生） | 取数层重试 3 次 + 失败沿用旧值并标注“数据暂缺”；核心源均非东财 |
| 成交额阈值时效性 | 需求阈值 8000亿/5000亿/4000亿 是 2024 年量级；若当前两市成交额系统性更高，该指标可能长期顶格 10 分。本期按需求固定阈值执行（不擅自改标准，需求第七条第 4 款），建议后续用分位数替代或请用户重定阈值 |
| `stock_market_pb_lg` 偶发失败（约 60%） | 重试 + 失败后 PB 指标标 stale 沿用旧分，不拖垮整页 |
| 两融/美债滞后 1 天 | 数据时序决定，页面如实标注"滞后 1 天"；08:30 补齐 |
| 新指标历史快照不足 30 日 | 30 日对比与可信度标注显示"历史数据不足"（需求兜底），不强行算 |
| LLM 事件扫描不稳定 | 本期不做自动扫描，只人工录入；LLM 扫描放二期且必须落库可复查 |
| 总分校验失败（误差>0.1） | 自动重试 1 次 → 仍失败沿用前一交易日快照，**不保存异常结果** |
| 任一模块异常 | 照本项目"松耦合"原则（`[market_position_api.py:33]`），本页挂了不影响其他页签 |
