2. **止损基准失真**：风险腿 `entry_high` 可能来自从未成交的委托价 `[trade/rotation.py:1082]`；
3. **告警噪声**：`_reconcile_lots` 只告警不改账 `[trade/rotation.py:969]`，幻影一直留着。

## 二、目标与非目标

**目标**
1. 买侧废单/部成后份簿记**自动纠正**到 QMT 实际成交，不再需要人工改库；
2. 当轮能发现的**当轮纠正**，当轮未终结的**隔夜核销**（自愈）；
3. 台账读写**与卖侧共用一份实现**（不写第二份）；
4. `rotation_lots_drift` 恢复"真出问题才响"的信号价值（§3.5 修正口径后可达）。

**非目标**
- 不做"用 QMT 持仓反推簿记"的第二套口径（铁律 1）；
- **不改卖侧既有核销语义**（只共用写侧函数 + 补"查询异常早退"这一条无风险加固），卖侧既有的"先改内存后写台账"顺序问题登记为遗留（§9 决策点 3）；
- 不接管人工单；不动份数/锚定热变更需重启的既有约束。

## 三、方案设计

### 3.1 数据：复用 `rotation_meta`，零 DDL

新键 `rotation_open_buys`，值 = JSON `{order_id: [份序号, 代码, 记录量, 已核销量, 委托时间]}`。
复用 `RotationMetaStore.get/set` `[trade/store.py:419]`、`[trade/store.py:426]` —— **不加表/列/schema/迁移**。

### 3.2 记账协议（核心，锁死"恰好一次"与失败方向）

**A. 下单时（逐笔，不攒批 —— 防 M4 的异常丢单）**
1. `_place_order` 成功返回 order_id（异常原样上抛，docstring 补明 `[trade/rotation.py:1103]`）；
2. **立即**写台账条目 `[份, 代码, 记录量, 已核销量=0, 委托时间=now]`；
3. **无论台账写成功与否**，都执行乐观记账 `lot["qty"] += qty`（保持现状语义）：
   - 台账写失败 → 写审计 `rotation_buy_ledger_write_failed`；幻影风险退回现状（对本代码，核销靠漂移告警 + §3.7 闸兜底）；
   - **绝不因为台账写失败而少记**（少记会补买）。

**B. 核销时（顺序倒置 —— 防 H2 双扣）**
1. 判定（见 §3.4）算出 `本次应扣 = (记录量 − 实际成交量) − 已核销量`（≥0）；
2. **先**把"已扣后"的台账状态落库（条目更新 `已核销量`，扣满则移除该键）。**写失败 → 整条跳过、不扣内存、写审计**；
3. 落库成功**才**改内存簿记（`_reduce_lot` `[trade/rotation.py:940]`）+ 扣到 0 时删行（§3.5）；
4. pass 末由 `_persist_lots()` `[trade/rotation.py:810]` 统一落库。

> **为什么这个顺序**：两种崩溃窗口都退化到"账本 ≥ 真实"——①台账未写成功就崩 → 什么都没变；
> ②台账写成功、内存未落盘就崩 → 重启后簿记是乐观值（偏多）、台账已无该条 → 幻影留存（**少赚**），
> 由漂移告警与 §3.7 闸可见。**没有任何一条窗口会走向"少记 → 补买 → 超配"**。

**C. 台账整表替换（防 H1 残留双扣）**
- 下单期：`merge=True` 只做"新增"；
- 核销期与 pass 末：一律 `merge=False` **整表替换**，写出的集合 = "上一轮在途且此刻仍非终态 ∪ 本轮新下且仍非终态"；
- **不变量**：条目的移除与其扣减在**同一步**（§3.2B 第 2 步）完成，`_settle_open_buys` 是唯一扣减点。

### 3.3 台账条目校验（防 M3 单号复用）

QMT 会复用 order_id（同仓先例：`[trade/executor.py:290]` 记 `created_ts` 单点收口即为此坑）。
核销取回报后校验：`o["code"] == 代码` 且 `o["direction"] == DIRECTION_BUY` 且（有 `ts` 时）与条目委托时间**同一交易日**；
任一不符 → 跳过该条 + 审计 `rotation_buy_ledger_mismatch`（不扣、不移除，留给人看）。字段现成：`[trade/gateway.py:761]`、`[trade/gateway.py:769]`。

### 3.4 买侧判定表（唯一真相源）+ 卖侧现状对照

**买侧（本方案）**

| QMT 回报 | 处置 | 理由 |
|---|---|---|
| 查询**抛异常** | 立即 return，台账不动 + 审计 `rotation_settle_query_failed` | 防 M2：一次超时不得清空台账 |
| 终态、`filled_qty > 0` | 扣 `记录量 − filled_qty`（部成/部撤） | 按实际成交核销 |
| 终态、`filled_qty = 0`（废单/已撤） | 扣**全部**记录量（幻影清零） | 按 0 成交核销 |
| 非终态（在途） | 台账留下，簿记不动 | 份额还冻在挂单里 |
| 成功查询但**查不到**该单 | 保留并计数，**最多 5 轮**，每轮审计；超期移除 + 审计 `rotation_buy_ledger_expired` | M1：不放弃自愈，也不无限留 |

**卖侧现状（本次不动，仅补"查询异常早退"）**：查不到 → 按全额扣（`[trade/rotation.py:931]`）；查询异常 → 并入"查不到"（`[trade/rotation.py:920]`，本次加固为早退）。

### 3.5 对账口径修正（防 H4：让漂移告警重新可信）

现状：`qmt_pos` 快照读在买入**之前** `[trade/rotation.py:744]`，对账在买入**之后** `[trade/rotation.py:811]` → 本轮买过就必然报警。
修正：
1. 对账前**重读**一次持仓（不再用旧快照）；
2. 期望值 = `QMT 持仓 + Σ在途买单量(该代码)`（在途卖单不需调整：份额仍被 QMT 计入 `volume`，只是冻结）；
3. 仅"解释不掉的差额"写 `rotation_lots_drift`（文案同步改：说明已计入在途）。

### 3.6 迁移交互（防 H3：先核销、后迁移）

现状顺序：`_migrate` `[trade/rotation.py:619]` → `_settle_open_sells` `[trade/rotation.py:625]`。
改为：**两侧核销 → 迁移**。并且 `_migrate` 结束时：
1. 清空两个台账键（`rotation_open_buys` / `rotation_open_sells`）；
2. **逐条写审计**列出被丢弃的在途条目（order_id/代码/数量），提示"若它们随后成交，簿记会偏小，由 `rotation_lots_understated` 闸与漂移告警暴露"；
3. 人工修账指引补一句："迁移会清空在途台账，无需手清" `[trade/rotation.py:986]`。

### 3.7 新增 fail-closed 闸（防"少记即补买"整类问题）

在买入循环之前（`qmt_pos` 重读之后 `[trade/rotation.py:744]`）逐代码比较：
`Σ份簿记(qty) < QMT volume` → **该代码本轮不补买** + 审计 `rotation_lots_understated`（含两者数量）。
理由：这一条同时兜住 H1/H2/H3 残余、M3、人工改库、外部手工买入等**一整类"少记"**情形，且误触发方向是"不买"（安全，符合"宁可不买不可瞎买"）。

### 3.8 买侧等待窗口（防 M6）

买侧独立短超时 `_wait_timeout_buy = 1.0`（卖侧维持 3.0 `[trade/rotation.py:193]`）：买侧等不到的代价只是核销推迟一轮（自愈），不值得把唯一写者堵更久；审计记实际等待耗时。

### 3.9 代码去重与注释同步

- 写侧泛化：`_save_open_sells` → `_save_open_ledger(key, entries, merge)`（key ∈ {`rotation_open_sells`, `rotation_open_buys`}），卖侧三处调用点改新名，**行为零变化**；
- 读侧保留两个 settle 方法（语义不同：卖=按成交减簿记、买=纠偏扣幻影），docstring 互相引用并各自指向 §3.4 的表；
- 同步模块头注释 `[trade/rotation.py:21]`、函数 docstring `[trade/rotation.py:946]` 的"在途卖单台账"措辞；
- 逐份状态生成加 `qty > 0` 过滤 `[trade/rotation.py:371]`（防 L1 的脏 `entry_high`）。

### 3.10 分层与接口检查（开工前深模块五问）

1. **放哪层**：轮动领域实现内部（`trade/rotation.py` 私有方法）；store 只提供通用 KV `[trade/store.py:409]` 与簿记整表读写 `[trade/store.py:328]`；

## 五、铁律合规核对

| 铁律 | 如何守 |
|---|---|
| 1 QMT 唯一真相源；对账只告警不改账、不重发 | 核销只依据**我们自己下的单**的委托回报；不重发、不反推持仓；人工单不碰 |
| 2 回调线程只入队 | 核销全在消费者线程执行 pass 内 |
| 3 唯一写者 = 消费者线程 | 台账与簿记只在执行 pass 内读写（同卖侧现状） |
| 5 重启先对账再交易；行情故障 fail-closed | 无行情不影响核销（只用委托回报）；核销失败一率"不扣"；§3.7 闸对"少记"拒绝买入 |
| 8 如无必要勿增实体 | 零新增表/进程/中间件；写侧收口一份；新增均私有方法 |

**失败方向总表（本方案的安全论证）**：台账写失败→不扣（账本偏多）；核销顺序崩溃→账本偏多；迁移丢弃在途→账本偏少**但**被 §3.7 闸拦买；查询异常→不动。→ 无一走向超配。
