# 选股缓存二期 (L1 池缓存 + L2 按日信号缓存) 计划书

> 日期: 2026-07-26
> 作者: VERA
> 状态: 草案 (待审)
> 前置: 一期已上线 (`selection/selection_cache.py`, 计划书 `docs/plan/2026-07-24_选股结果缓存_计划书.md`, 实测命中 32.7s→0.01s)

---

## 1. 背景与动机

一期把 `step1_select` 整段输出按"公式+池+**完整区间**+当天"缓存, 解决"同区间调参重跑"。遗留两个缺口:

| 缺口 | 现状 | 代价 |
|---|---|---|
| **换日期区间必 miss** | key 含完整 start/end, 改一天全算 | 每次 ~32s (实测: 用户一晚换 4 次区间跑 GP1014, 次次全价) |
| **tools/* 不受益 (R7)** | gs_run_one / sweeps / run_upn_baseline 直调 `StockSelector.run`, 不经 pipeline 接缝 | 批量场景每次全价 |

二期思路: **整单拆零件** — 股票池按天缓存 (L1), 选股信号按"每个交易日"缓存 (L2)。换区间时重叠部分免单, 只有没算过的连续区段补跑。

实测依据 (bench_phases + 一期实测): 选股 32s ≈ resolve_universe ~17s (拉池+ST过滤) + 公式 51 批 ~16s。L1 省前者, L2 按缺失比例省后者。

---

## 2. 目标与非目标

### 目标
- 换区间重跑同公式: 重叠部分零成本, 总耗时 ≈ 缺失区段比例 × 16s (+ L1 命中时 0s 池解析)
- tools 直调 `StockSelector.run` **自动受益** (R7 解决): 接缝放进 selector 内部, 不只挂 pipeline
- 口径不变: 合并结果与整段直跑**逐条一致** (测试钉死 parity)
- 盘后数据安全: 最近 2 个交易日永远现算 (盘后数据未到位风险)

### 非目标
- 周线/分钟级 selection period 的按日缓存 (粒度不匹配, 回退现有路径)
- 一期整段缓存的替代 (保留为 L0 快路径)
- 并发选算/公式并行 (另开任务)

---

## 3. 总体设计

```
请求 (formula, universe_cfg, start, end)
  │
  ├─ L0: 一期整段缓存 (pipeline step1)        命中 → 返回 (最快, 单文件)
  │   miss ↓
  ├─ L1: 池缓存 universe_cache                命中 → 池列表 (省 ~17s)
  │   miss → resolve_universe() 实算 → 存 L1
  │   ↓ 有池
  └─ L2: 按日信号缓存 signal_day_cache        (仅 period=1d)
      ├─ 区间内交易日 = 已缓存天 ∪ 缺失天
      ├─ 缺失天分组为连续区段 (按交易日相邻)
      ├─ 每区段整段调公式 (摊薄预热) → 按天拆分落盘
      └─ 合并缓存天+新算天 → 去重排序 → 返回
```

**接缝位置决定**: L1/L2 放在 `StockSelector.resolve_universe` / `StockSelector.run` 内部 —— pipeline、tools、MultiFormulaSelector 全部自动受益, 不需要每个调用方单独接。一期 L0 保留在 pipeline 层 (最快路径)。

### 3.1 L1 池缓存 (`selection/universe_cache.py`)
- key = blake2b(universe 完整配置归一化 + today_str + SCHEMA_VERSION)
- value = 股票代码列表 (json)
- 位置: `resolve_universe()` 开头查, 结尾存 (含 BJ/ST 过滤后的最终输出)
- LRU 10 份; 按日失效 (与一期同口径: ST 状态日内漂移由按日失效掩蔽 + force_refresh 兜底, 与一期 R8 一致)
- `custom` 类型池不缓存 (配置即数据, 无计算成本)

### 3.2 L2 按日信号缓存 (`selection/signal_day_cache.py`)

**组合 key**: `combo = blake2b(formula_name, formula_arg, pool_hash, period, dividend_type, SCHEMA_VERSION)`
- `pool_hash` = L1 缓存池列表的内容哈希 — L1 命中后算哈希**零成本**, 比一期 R8 的"按日失效掩蔽 ST 漂移"更精确: 池内容变了 combo 自动换

**存储**: `data/signal_day_cache/{combo}/{YYYYMMDD}.parquet` (列: stock_code, select_date)
- **空信号日也缓存** (稀疏公式大部分天无信号, 不缓存空天 L2 永远不命中) — 但**批次失败的天不缓存** (见 3.3)
- LRU: 全局文件数上限 20000, 超了按 mtime 最老先清 (单文件 KB 级)

**查询流程** `get_or_compute(selector, stock_list, start, end)` (e2e 实测修正版):
1. `pool_hash = hash(stock_list)`; 组合目录 = combo
2. 区间内交易日列表 (DataFetcher.get_trading_days)
3. **当日 (today) 永不缓存** (盘后数据可能未到位, 永远现算)
4. **最近 FRESH_DAYS=2 个交易日** (不含当日): 条目按文件 mtime 记 "computed_on",
   **仅当日命中** (当日数据已 settled), 跨日自动重算 — 既保盘后数据安全,
   又不扼杀"盘后反复重跑"主场景 (v1 曾"最近2天永不缓存", e2e 实测
   run4 同区间重跑仍全价 13.9s, 修正为此规则)
5. 超过 K=60 天前的旧天重算 (前复权除权漂移, `l2_max_age_days`)
6. **全命中** → 合并缓存天返回 (零公式调用, 子区间/历史并集覆盖免费)
7. **任一缺失** → **整段 [start,end] 一次算完** (与直跑同价), 按天拆分落盘
   (含空天; 当日天不落盘; 批次失败不落盘)

> ⚠️ **为何不按"缺失区段"补算 (v1 设计被 e2e 推翻)**: TDX 公式调用有
> ~51 批固定地板成本 (~16s, count 预热 300 根使扫描量在小区间几乎不变),
> 实测 17 天区段 (17.1s) ≈ 39 天整段 (16.6s)。按区段补算不省钱, 多区段
> 反而 N 倍于整段直跑。故 L2 的价值 = **按天粒度命中** (子区间/并集覆盖),
> 而非增量计算; 有缺失时与直跑同价, 永不更贵。

### 3.3 批次失败与空信号的区分 (正确性关键)
`formula_runner` 批次失败目前只记日志, 调用方无法区分"真空无信号" vs "失败导致空"。
**最小加法**: `FormulaRunner` 加类属性 `last_batch_errors: int` (每次 run 重置累加, 不改签名)。L2 只在 `last_batch_errors == 0` 时落盘区段天数; 有失败的区段**不缓存** (下次重试), 但当次结果照常返回合并 (与现行为一致)。

### 3.4 回退规则 (不破坏现有)
- `period != "1d"` → 跳过 L2 直跑 (周线/分钟粒度不匹配)
- 任一缓存异常 → 当未命中处理, 绝不中断选股 (同一期)
- `selection_cache.enabled=false` → 全关; `force_refresh=true` → 强制全 miss 重算并覆盖

## 4. 配置 (并入一期 selection_cache 块)

```yaml
selection_cache:
  enabled: true
  force_refresh: false
  l1_enabled: true        # 池缓存
  l2_enabled: true        # 按日信号缓存
  l2_max_age_days: 60     # 超过 60 天的旧信号重算 (除权漂移)
  l2_fresh_days: 2        # 最近 2 个交易日永远现算 (盘后数据)
```

selector 层开关用模块级 setter (`signal_day_cache.configure(...)`), pipeline `__init__` 读 yaml 应用; tools 用默认值 (全开)。默认配置与现行为一致。

## 5. 风险与对策

| # | 风险 | 对策 | 严重度 |
|---|---|---|---|
| R1 | 合并结果与整段直跑不一致 | parity 测试钉死: 同区间 L2 合并 vs 直跑逐条一致 (值+dtype) | 高 (测试锁) |
| R2 | 盘后数据未到位缓存了当天信号 | 最近 2 交易日永不缓存 (l2_fresh_days) | 中 |
| R3 | 除权除息 → 前复权历史价漂移 → 老信号失真 | 60 天滚动失效 + force_refresh 兜底; 文档明示"改 60 天前区间请 force_refresh" | 中 |
| R4 | 批次失败被当空信号缓存 | last_batch_errors>0 的区段不落盘 (3.3) | 中 |
| R5 | 并发写 (tools 批量) | tmp+os.replace 原子写 + Windows 退避重试 (照一期) | 低 |
| R6 | 文件膨胀 | 全局 20000 文件 LRU; 单文件 KB 级 (~5000 股 × 60 天 × 10 组合 ≈ 上限内) | 低 |
| R7 | 周线/分钟 period 误用 L2 | period 守卫, 非 1d 直跑 | 低 |
| R8 | L0/L1/L2 叠加顺序混乱 | 顺序固定 L0→L1→L2, 每层 miss 才下落; 测试覆盖三层命中路径 | 低 |
| R9 | tools 行为变化 | 缓存结果与直跑 parity 一致即无行为变化; force_refresh 环境变量/配置可关 | 低 |

## 6. 测试计划 (`tests/test_signal_day_cache.py` + `tests/test_universe_cache.py`)

1. L1 命中/失效: 同配置二次命中; 改 universe 任一字段 miss; today_str 跨日 miss
2. L1 并发原子写 (两线程同 key)
3. L2 全 miss → 全区段算 → 逐日落盘 (含空天)
4. L2 全命中 → 零公式调用 (mock FormulaRunner 计数)
5. L2 部分命中: 缓存 3 月, 请求 3~4 月 → 只算 4 月区段, 合并 parity vs 全直跑
6. 缺失区段分组: 缺口分散时分多个 span, 相邻交易日并一个 span
7. 最近 2 交易日不缓存 (第二次跑仍现算, 不落盘)
8. 超 60 天旧天重算 (l2_max_age_days 配置生效)
9. 空信号日落盘且命中 (不再调公式)
10. 批次失败区段不落盘 (last_batch_errors>0)
11. pool 变化 → combo 变 → 全 miss
12. formula_arg/dividend_type 变化 → miss
13. 合并去重: 跨区段同 (stock, date) 不重复
14. dtype parity: select_date datetime64 一致 (parquet round-trip)
15. period=5m → 跳过 L2 直跑
16. force_refresh → 强制重算并覆盖
17. LRU: 超上限最老文件被清
18. 回归: 一期 L0 命中优先 (整段命中时不走 L2)
