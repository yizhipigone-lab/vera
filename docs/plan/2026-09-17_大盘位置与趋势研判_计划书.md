# 2026-09-17 大盘位置与趋势研判子系统 计划书

> 入口: 用户 2026-09-17 在系统优化评估中点名「大盘所处位置 + 趋势研判（提升空间最大的方向）」
> 并拍板「这个可以做」。
> 一句话目标: 把研究大脑现在"每天一张大盘照片"升级成"连续录像 + 历史照镜子 + 每日体温表"。

---

## 1. 现状与缺口（先说人话）

现在大脑看大盘靠 `brain/market_panel.py` 的 `market_snapshot()`，它从 akshare 抓五个板块
（A股指数快照 / 港股指数 / 美股三大指数 / 南向资金 / 涨停池），再拼上一张
`market_health()` 体检表（4 指数 × 4 窗口收益 + 牛熊状态）。

这张表的三个缺口：

1. **没有"位置"概念**：只有"涨了多少"，没有"现在贵不贵"。
   指数 3891 点是高是低？要靠脑子里记住历史。
2. **没有连续序列**：`market_snapshot` 有 2 小时文件缓存（`data/brain_model_cache/`），
   但那是"当天快照"，隔天就被覆盖，攒不出时间序列。
3. **没有宽度**：指数是大市值股票的函数，指数涨不代表大多数股票在涨。
   实测 2026-09-16 就是一个活例子（见 §3 实测数据）。

## 2. 目标（可验收）

- **G1 连续录像**: 每个交易日盘后落盘一条结构化记录到
  `data/market_position/daily.jsonl`（一天一行 JSON），含位置/宽度/量能/波动四组指标。
- **G2 历史照镜子**: 给定今天的指标向量，自动找出历史上最像的若干天，
  并给出那几天之后 20 / 60 个交易日的实际走势（参照系，不是预测）。
- **G3 择时规则影子记录**: 三条候选择时规则每日记录状态，
  **只记录不交易**；并用历史序列回放算它们的假想成绩（T+1 口径）。
- **G4 每日体温表**: 每交易日盘后自动生成 Markdown 并推飞书
  （复用 `tools/send_report_feishu.py` 链路）。
- **G5 大盘位置页签**: PC 端新增独立页签，展示最新一条 + 近 250 日趋势 + 照镜子结果。

## 3. 实测数据（先把尺子摆出来）

**数据日期 = 2026年9月15日，不是 9月16日** —— 这是本子系统第一个实测发现（详见 §4.2）：
日线缓存里 9月16日那根是个股"空壳 bar"（文件写入时间 9月16日 09:16，开盘前抓的，
成交量 0），有效交易日判据把它挡掉了。下面全是最终交付版本（滚动 2430 个交易日窗口）
的实测值：

| 指标 | 实测值（数据日 2026年9月15日） | 读法 |
|---|---|---|
| 上证指数(代码 000001.SH) 十年百分位 | **90.9%** | 比过去十年 90.9% 的交易日都高 |
| 沪深300(代码 000300.SH) 十年百分位 | 73.0% | 偏高但没到极端 |
| 创业板指(代码 399006.SZ) 十年百分位 | 88.4% | 偏高 |
| 站上 20 日均线家数占比 | **21.2%** | 只有约五分之一的股票还在均线上方 |
| 创 60 日新高 / 新低家数 | 51 / **275** | 新低是新高的 5.4 倍（差 −224） |
| 全A成交额 | 16,037 亿元 | 处于过去一年的 **1.6% 分位**（一年中位数 23,581 亿元） |
| 涨停 / 跌停家数 | 32 / 33 | 本地日线推导，ST 股会漏计 |
| 上证指数近一年收益 | −0.2% | 一年白干 |
| 沪深300 近一年收益 | −1.6% | 一年小幅亏 |
| 沪深300 年化波动率（20 日） | 14.1% | 低波动 |

> **口径勘误（成文后修订）**：本节初稿写的是"2026年9月16日"，上证百分位 92.3%、
> 站上 20 日均线 19.7%、新高新低 52/299、成交额分位 62%。那组数字来自原型阶段，
> 有两处口径与最终交付不同：①日期用的是 9月16日（当时还不知道那根是空壳 bar）；
> ②百分位用「过去 3652 个自然日 + 严格小于」计算，最终交付改成「滚动 2430 个
> 交易日 + `rolling.rank(pct=True)`」，且历史不足十年时要求满 3 年才给数。
> 两套口径在数据日上也差一天，故不能逐项相减比较。**以本表为准。**

**这组数字本身就是最好的产品说明**：指数在十年 90% 分位的高位，
但个股层面八成已跌破 20 日均线、创新低家数是新高的 5.4 倍、成交额趴在一年最低的
1.6% 分位 —— 典型的"指数虚胖、个股挨打"。
只看指数会得出完全相反的结论。这就是本子系统的价值。

## 4. 数据源与口径（关键决策）

### 4.1 数据源 = 本地日线缓存，不用网络

`data/kline_cache/1d/` 已有 5761 个 parquet（5211 只沪深 A 股 + 指数 + ETF），
指数历史回溯到 2013-01-04。全量读取（只取 date/close/volume/amount 四列）
实测 **17~28 秒**，一次性放进内存后向量化计算 **3 秒**。

**决策**: 走本地缓存，不走 akshare。
理由：①复现性 —— 同样的输入永远得同样的数，方便测试与审计；
②离线可用 —— 不开 TDX / 断网也能算；③已有基础设施 —— 调度器每交易日 15:45
已经把这个缓存刷到最新（`core/kline_cache_maintenance.py`），不重复建设。

读取时置 `VERA_KLINE_READONLY=1`，让 `KlineCache._ensure` 直接返回，
**绝不触发任何网络补拉**（只读分析任务不该因为网络卡死）。

### 4.2 【踩坑实录】缓存最后一根可能是"空壳 bar"

实测发现：`000001.SZ`（平安银行）的日线最后一根是 2026-09-16，
但 `open=high=low=close=11.81、volume=0、amount=0`，文件写入时间是
**2026-09-16 09:16**（开盘前抓的）。

也就是说：盘前抓数会造出一根"有日期、无成交"的假 bar。如果直接拿它当收盘价算宽度，
会静默用盘前价冒充收盘价。

**对策（硬性）**: 定义"有效交易日"= 全市场成交量大于 0 的股票占比 ≥ 50% 的那一天。
快照的 `data_date` 取最后一个有效交易日，并在记录里写
`stale: true/false` 与 `expected_date`。数据滞后时照常落盘但打标 + 告警，
**绝不把滞后数据当新鲜数据推给用户**。

### 4.3 牛熊口径复用单一真相源

`core/index_regime.py::classify()`（价 > MA250 且 MA250 的 20 日斜率 > 0 为牛，
价 < MA250 且斜率 < 0 为熊，其余震荡）。**不写第二份**。

### 4.4 涨停家数：本地推导 + 已知偏差

用 `core/limit_ratio.py::limit_ratio()`（全项目唯一真相源）算每只票的涨跌停幅度，
再比对收盘价是否触及涨停价。**已知偏差**: 该函数需要 `st` 布尔标记，
而本地缓存里没有 ST 标记，故 ST 股（±5%）的涨停会被漏计 —— 这是**低估**，
方向安全（宁可少报不虚报）。记录里写 `limit_source: "kline_cache"` 标注来源。

### 4.5 不合成总分（沿用既有决策）

`docs/plan/2026-09-04_市场体检表与研究雷达_决策记录.md` 已拍板"四指数并行不合成"。
本子系统**沿用**：每个维度各给自己的百分位，**不给一个混合总分**，
避免用拍脑袋的权重掩盖分歧（指数高位 + 宽度崩塌这种分歧本身就是最有价值的信息）。

## 5. 指标定义

每条日记录（`data/market_position/daily.jsonl` 一行）：

```
{
  "date": "2026-09-16",              # 数据实际日期（最后一个有效交易日）
  "expected_date": "2026-09-16",     # 应有数据的交易日
  "stale": false,                    # date < expected_date 时为 true
  "indices": {                       # 三大指数，各 8 个字段
    "shanghai":    {"name":"上证指数","close":3891.60,"pct_10y":92.3,
                    "from_high_pct":-8.3,"vol_ann_20":9.2,"vol_ann_60":16.8,
                    "ret_1y_pct":0.8,"ma250_dev_pct":null,"regime":"range","samples":2428},
    "hs300":       {...},
    "chuangyeban": {...}
  },
  "breadth": {                       # 市场宽度（战场上有多少士兵在冲）
    "traded": 5204,                  # 当日有成交的股票数（分母）
    "above_ma20_pct": 19.7,          # 站上 20 日均线占比
    "above_ma60_pct": ...,           # 站上 60 日均线占比
    "new_high_60": 52,               # 创 60 日新高家数
    "new_low_60": 299,               # 创 60 日新低家数
    "hl_spread": -247                # 新高 − 新低
  },
  "turnover": {
    "amount_yi": 12345.6,            # 全 A 股成交额（亿元）
    "amount_pct_1y": 62.0            # 成交额在过去一年的百分位
  },
  "limit": {"up": 89, "down": 12, "source": "kline_cache"},
  "shadow": {                        # 三条候选择时规则的当日状态（只记录不交易）
    "ma20": "on", "breadth50": "off", "regime": "range"
  }
}
```

指标口径逐条：

| 指标 | 算法 | 白话解释 |
|---|---|---|
| `pct_10y` | 过去 3652 个自然日内，收盘价低于今天的交易日占比 × 100 | 现在的位置比过去十年百分之多少的日子高 |
| `from_high_pct` | 收盘 / 十年最高 − 1 | 距十年最高点还差多少 |
| `vol_ann_20` | 近 20 个交易日对数收益标准差 × √252 | 年化波动率，越大越颠 |
| `ma250_dev_pct` | 收盘 / MA250 − 1 | 偏离年线多少 |
| `regime` | `core/index_regime.classify()` | 牛 / 熊 / 震荡 |
| `above_ma20_pct` | 当日有成交且收盘 > 自身 MA20 的股票占比 | 多少人还在均线上 |
| `new_high_60` | 当日收盘 ≥ 自身近 60 日最高收盘 | 创近三个月新高家数 |
| `hl_spread` | new_high − new_low | 正数=扩张，负数=收缩 |
| `amount_pct_1y` | 全 A 成交额在过去 250 个交易日的百分位 | 现在的量能算大还是小 |

## 6. 历史照镜子（G2）

**特征向量**（6 维，全部是"当日已知"的量，不含任何未来信息）：
`[上证十年百分位, 沪深300十年百分位, 站上MA20占比, (新高−新低)/有成交家数, 沪深300年化波动20日, 成交额一年百分位]`

**算法**:
1. 用历史全序列对每个特征做 z-score 标准化（减均值除标准差）；
2. 算今天向量与每个历史交易日的欧氏距离；
3. 排除最近 20 个交易日（否则照出来的镜子全是"昨天、前天"，没有信息量）；
4. 贪心去重：已选中的日子前后 20 个交易日内不再选（否则一次照出 20 个连续的同一天）；
5. 取距离最小的 5 天，各自给出其后 20 / 60 个交易日的指数实际涨跌；
6. 汇总给出"这 5 次之后 20 日的涨跌分布"。

**诚实声明（必须写进报告与页面）**: 样本只有 5 个，且 A 股三十年只经历过
屈指可数的几轮周期，"历史相似"**不是预测**，只是提供一个参照系。
报告里必须原样带上这句警告。

## 7. 择时规则影子记录（G3）

三条候选规则，每日记录 on/off，**只记录不交易**：

| 规则名 | 多头条件（on） | 参照 |
|---|---|---|
| `ma20` | 沪深300 收盘 > 自身 MA20 | 最经典的均线择时 |
| `breadth50` | 站上 MA20 家数占比 ≥ 50% | 用宽度而非指数 |
| `regime` | `core/index_regime.classify()` = bull | 项目既有牛熊口径，作对照组 |

**回放评估口径（照抄 2026-08-24 的教训）**: 信号在 T 日收盘产生，
**T+1 日生效**（`docs/plan/` 与 `trade/shadow.py` 的既定纪律）。
原口径"T 日当天生效"对高频规则系统性乐观，本项目已经因此得出过一次假结论，
不得重犯。回放输出年化 / 最大回撤 / 夏普 / 卡玛 + 买入持有对照。

**铁律提醒**: 本节的输出是**研究报告**，绝不接进 `trade/` 的任何闸门或仓位计算。
测试里用 AST 静态断言 `core/market_position*.py` 与 `market_position_api.py`
不含 `import trade`（照 `tests/brain/test_sentiment_acceptance.py` 的守护写法）。

## 9. 落盘与幂等

- 路径 `data/market_position/daily.jsonl`（一天一行，按日期排序）。
- **upsert 语义**: 同一天重跑覆盖该行，不追加重复行（照 `trade/shadow.py::append_shadow_log`
  的按日去重思路，但用"读全量 → 合并 → 原子重写"实现，因为要支持回填覆盖）。
- 原子写：临时文件 + `os.replace`（照 `VeraScheduler._save_state` 的写法）。
- 采集窗口默认最近 90 个交易日，**一次算出窗口内所有有效日并全部 upsert** ——
  于是"停机三天后开机"会自动补上那三天，无需单独写补数逻辑。

## 10. 风险与边界

| 风险 | 处置 |
|---|---|
| 空壳 bar 污染（已实测存在） | 有效交易日判据 + `stale` 标记 + 告警 |
| 数据滞后时误报"今天很弱" | `stale: true` 时体温表抬头写明"数据截至 X 日" |
| 宽度样本含退市/停牌股 | 分母用"当日有成交"的股票数；停牌股自然排除 |
| 相似日样本极少被当预测用 | 报告与页面强制带警告文案（写成常量，不靠自觉） |
| 本地缓存被测试污染 | `conftest.py` 隔离 `data/market_position/` |
| 违反业务铁律 1（宏观联入仓位） | AST 断言无 `import trade` + 代码只写 JSONL/报告 |

## 12. 后续衔接：盘后复盘报告「合不合进大盘位置页签」的裁决（2026-09-17 用户提问）

用户问：盘后自动复盘报告（今日盘面 + 持仓表现 + 明日关注）是不是和大盘趋势的
TAB 合在一起比较好？

**裁决：用户看到的地方要「合」，代码里的模块要「分」，依赖单向朝下。**

三条理由：

1. **物理隔离不能破**。大盘位置模块的数据源是纯市场数据（本地日线缓存），
   本计划书 §7 给它立了 AST 守护「绝不 import trade」。复盘报告的「持仓表现」
   必须读 `data/trade/trade.db`（持仓/资产/成交），一旦塞进同一个模块，
   那条守护就废了 —— 而守护正是「大盘研判不会悄悄联进仓位」的**机械保证**
   （业务铁律 1 要求仓位由人工把关，机制比自觉可靠）。
2. **两者服务的使用场景不同**。复盘报告是「推」：早上在路上，飞书弹一张卡；
   大盘页签是「看」：坐到电脑前想往下钻（十年百分位 / 照镜子 / 趋势图）。
   硬合成一个页签会让「推」的文案变重、让「看」的页面变乱。
3. **但内容层次上确实是一家**。复盘的「今日盘面」直接复用
   `thermometer_md()`，**不写第二份盘面文案**。依赖方向：

   ```
   report/daily_review.py            复盘: 盘面 + 持仓 + 留意清单
        ├─ core.market_position_runner   ← 复用体温表(盘面段)
        └─ trade 域数据(trade.db)        ← 持仓段
   core/market_position_runner.py     大盘位置(绝不 import trade)
   ```

**页面落地**：大盘位置页签里加一个「今日复盘」折叠块，内容由复盘模块生成的
Markdown 全文注入，不由大盘模块生成。用户一个页签看全，代码边界干净。

**排期依赖（必须串成一条链，顺序不能错）**：

| 时刻 | 步骤 | 状态 |
|---|---|---|
| 15:05 | 交易端 EOD 归档 | 现有 |
| 15:45 | K 线缓存补尾段 | 现有 |
| 15:50 | 大盘位置采集 | **本次新建** |
| 09:05（次日） | 大盘体温表推飞书 | **本次新建** |
| 15:55 | 复盘报告生成 + 推送 | 待做 |

复盘必须排在大盘位置采集之后，否则会引用到昨天的大盘位置。

**「明日关注」的口径（待用户拍板）**：建议 v1 **只做规则事实，不做主观预测**，
并且把名字改成「需要你留意的清单」（原名承诺了预测，与铁律 1 冲突）：

- 持仓中当日触发或接近止损/止盈线的标的；
- ETF 轮动的当前目标腿与下一次锚定日；
- 当日公式出票（14:52 自动买入信号）；
- 大盘位置侧的状态提示（数据滞后 / 宽度跌破阈值）。

LLM 只允许做**一句话归纳**（可选开关，默认关）。理由：推到手机的报告一旦掺进
「我觉得明天会……」，就会被当成建议读，而铁律 1 要求仓位由人把关。
