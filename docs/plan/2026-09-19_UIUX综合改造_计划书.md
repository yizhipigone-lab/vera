## 0. 本次评估的侦察结论（计划的事实基础）

以下为写计划前逐行读码核实过、与报告有出入或报告未覆盖的事实，计划以本节为准：

1. **`web/js/market_position.js`（31KB）不是可删的孤儿文件**。页面确实不再引用它（index.html 第 1687-1703 行脚本清单无它、全部 JS 互引无它），但 `tests/js/test_market_position.js` 第 5 行 `require` 它，且它是**跨语言文案反向锁**的一部分（`tests/test_market_position_runner.py` 的 `test_band_words_match_frontend` 拿它锁 Python 侧体温表措辞）。→ 处理改为「保留 + 文件头加注」，不删除。**这是对评估报告 P2 第 15 条的修正。**
2. **农场停止按钮后端已支持任意闸门**：`core/farm_api.py` 第 57-60 行 `/api/farm/stop` 调 `farm.stop()`，作用于整个串行 FarmRunner，不按闸门区分。→ 闸门①③④补停止按钮是纯前端工作，可行。
3. **`decision_util.mjs` 第 309-318 行 `describeTradeError` 文案写死「交易服务 (端口 8081)」**，新 TAB 走的是 8080 页面服务，不能直接复用 → 需要泛化出一个可传服务名的底层函数，`describeTradeError` 委托它、默认行为不变（`tests/web/test_decision_util.mjs` 第 300-304 行锁了现有行为，必须保持绿）。
4. **trade.js 与 market_dashboard.js 要复用 decision_util.mjs / charts.js 的导出，必须从 classic script 转成 ES module**。时序已核实安全：模块按文档顺序延迟执行，trade.js（第 1690 行）先于 decision.js（第 1694 行）执行，`window.recordsPageEnter` 包装链不断；echarts.min.js、stock_link.js、recover.js 都是 classic 且排在前面，模块执行时全部就绪；两文件均为 IIFE 结构、无全局 var 泄漏、无 top-level await。
5. **现有测试基线**（改动前后都必须全绿）：`tests/js/test_tab_wiring.js`（页签接线四查）、`tests/js/audit_css_vars.mjs`（var(--x) 引用必须有定义）、`tests/js/test_market_position.js`、`tests/js/test_recover_integration.js`、`tests/web/` 下 10 个 mjs/js 测试（含 `test_decision_wiring.mjs` 假 DOM 真加载 decision.js、`test_ai_settings.js`）。
