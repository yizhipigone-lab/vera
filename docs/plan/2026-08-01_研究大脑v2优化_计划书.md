# VERA 研究大脑 v2 优化方案（实施版）

> 三阶段渐进升级：语义搜索 → 联网搜索 → 评估升级
> 2026-08-01 初稿 / 2026-08-01 v2.1 审计修订（实施版）
>
> **v2.1 修订说明**（相对初稿的关键变更，实施者以此版为准）：
> 1. **砍掉多 agent 辩论（debate）**：7 次 CLI 调用/次提问，成本与"轻便简洁"原则不符。接口预留见 §九。
> 2. **依赖减重**：ChromaDB + sentence-transformers（torch ~2GB）→ **fastembed + numpy**（~150MB，无 torch，无向量数据库）。语料仅 4600+ 文件 / ~5 万向量块，numpy 余弦相似度毫秒级足够。
> 3. **嵌入模型换中文**：all-MiniLM-L6-v2（英文向）→ **BAAI/bge-small-zh-v1.5**。
> 4. **搜索库换代**：duckduckgo-search（已弃用，且 DuckDuckGo 大陆被墙）→ **ddgs**，backend 优先 bing。
> 5. **补齐初稿最大漏洞**：明确 LLM 调用搜索的机制 = **Bash 跑 CLI 子命令**（大脑 LLM 只有 Read/Grep/Glob/Bash 四个工具，无法直接调 Python 函数）。
> 6. **修正索引去重设计**：归档是"每 channel 一文件、逐次 append"，增量索引必须按 source 删旧块再写新块，否则向量重复膨胀。
> 7. **修正事实错误**：公司文件实为 4586 个（非 5200+）；judge 与被测模型同源，"独立"仅限 session 级。
> 8. **补自动化测试与检索质量验收线**。

## 一、Context：为什么要做

### 现状（均已对代码核实）

当前 `brain/` 对话大脑（2026-07-28 上线）架构：

```text
用户提问 → brain/claude_cli.py → claude CLI subprocess（工具：Read,Grep,Glob,Bash）
                                    ├─ A模式：查本地（持仓/图谱/政策/vault）
                                    └─ B模式：纯 LLM 训练知识回答（明确禁用工具）
输出 → counter.py（反证校验）+ evidence.py（引用校验）
     → archive.py（归档 vera_obs_vault/对话沉淀/，每 channel 一文件、逐次 append）
     → eval.py（10 题 golden set，must_contain 正则打分，闸门 ≥8/10）
```

关键事实（实施前请知悉）：

- `ask_brain()` 签名见 `brain/claude_cli.py:74`，**本方案不改其签名**。
- 归档目录 `vera_obs_vault/对话沉淀/` 由 `brain/archive.py:142 archive_exchange()` 维护，**同一 channel 的所有问答 append 进同一个 md 文件**（`archive.py:128 _file_for()`），这直接决定了 §三 的索引去重设计。
- `vera_obs_vault/company/` 现有 **4586** 个 `company_XXXXXX.md`；`对话沉淀/` 现有 11 个文件，会随日常对话持续增长。
- 防注入清洗函数已存在：`policy_pipeline/sources/gov_cn.py:159 sanitize_untrusted()`，Phase 2 直接复用。
- 前端 `web/js/brain_chat.js` + API 层 `research_api.py` **不在本次改动范围**（接口契约不变）。
- numpy 是项目现有依赖；torch、fastembed、ddgs 当前均未安装。

### 三大缺口

| # | 缺口 | 影响 |
|---|------|------|
| 1 | **无语义搜索** | 4586 个公司文件只能 Grep 关键词，"帮我找和固态电池相关的公司"这类概念查询做不了 |

### 业界对标

|----------|---------|---------|
| Karpathy LLM Wiki 模式 | `raw/`（只读资料）vs `wiki/`（AI 维护知识）分界 | Phase 1 |

## 二、总体设计原则

### 铁律（不可违反）

1. **零侵入**：所有改动在 `brain/` 内部 + `pyproject.toml` + `.gitignore` + `tests/`，对选股/回测/实盘零影响。
2. **接口不变**：`ask_brain()` 签名不变；`research_api.py`、`server.py`、前端不动。
3. **独立可交付**：每个 Phase 独立可用、独立回滚（回滚 = revert 对应文件 + 卸载对应依赖，互不影响）。
4. **轻便优先（如无必要勿增实体）**：全程只新增 **2 个 pip 包**（fastembed、ddgs）；不引入向量数据库、不引入 torch、不跑任何新服务/容器/进程。
5. **LLM 工具调用机制 = Bash CLI**：大脑 LLM 仅有 Read/Grep/Glob/Bash 四个工具（`claude_cli.py:30`）。所有新能力必须暴露为 `python -m brain.<module> <args>` 的 CLI 子命令，由 prompt 指导 LLM 用 Bash 调用。**不允许**在 prompt 里描述一个 LLM 无法直接调用的 Python 函数。
6. **语义搜索与知识图谱互补**：`kg/graph.db`（100K 节点 + 172K 边）管结构化关系，语义搜索管非结构化文本，不互相替代。
7. **松耦合**：搜索/索引任何失败只降级、不抛异常，绝不影响大脑主回答链路。

### 架构总览

```text
Phase 1: 语义搜索（fastembed + numpy，索引落盘 data/brain_vectors/）
  brain/search_engine.py  ← 被三处使用：
    ① LLM 经 Bash: python -m brain.search_engine search "查询词"
    ② archive.py 归档后自动调 update_file() 保持索引同步
    ③ 人工: python -m brain.search_engine build --force / eval

Phase 2: 联网搜索（ddgs，backend 优先 bing）
  brain/search_web.py  ← LLM 经 Bash: python -m brain.search_web search "查询词"

Phase 3: 评估升级（无新依赖）
  brain/golden_set_v2.json（30 题 5 类）+ brain/eval_judge.py（claude CLI 做 grader）
  brain/eval.py 增加 --v2 --judge 模式
```

## 四、Phase 1：语义搜索（约 1.5 天）

### 4.1 目标

让大脑能用自然语言搜索 4586 个公司文件和历史对话归档，回答"帮我找和固态电池相关的公司"这类概念查询。验收有**量化门槛**（§4.6），不是"能打印结果"就算完。

同时落地 Karpathy LLM Wiki 模式——VERA 已 80% 就位（`vera_obs_vault/` 就是 wiki，`archive.py` 已在自动维护），差的只是语义搜索层。`raw/` vs `wiki/` 的分界**只在 vault 加一段 README 约定说明，不改任何现有文件结构**。

### 4.2 新增文件 `brain/search_engine.py`（约 230 行）

#### 模块常量（文件顶部）

```python
MODEL_NAME = "BAAI/bge-small-zh-v1.5"   # 换模型只改这一处
EMBED_DIM = 384                          # bge-small-zh 输出维度
QUERY_PREFIX = "为这个句子生成表示以用于检索相关文章："  # bge-zh 检索约定：查询侧加前缀，文档侧不加
INDEX_DIR = VERA_ROOT / "data" / "brain_vectors"
VAULT_DIRS = ("company", "对话沉淀")      # 相对 vera_obs_vault/；扩展索引范围只改这里
CHUNK_MIN, CHUNK_MAX = 200, 450          # 分块目标字数（450 < bge 的 512 token 上限，中文留安全边际）
```

#### 公开接口（签名固定，实施者不得更改）

```python
class VaultSearchEngine:
    def __init__(self, index_dir: Path = INDEX_DIR): ...

    def build_index(self, force_rebuild: bool = False) -> dict:
        """全量构建。返 {"files": int, "chunks": int, "skipped": bool}。
        force_rebuild=False 且索引已存在（meta.jsonl 非空）→ 直接返 {"skipped": True}。"""

    def update_file(self, filepath: Path) -> int:
        """单文件增量更新（archive.py 用）。先删除该 source 的全部旧块，
        再重新分块嵌入写入。返新块数。文件不存在时只删不写，返 0。"""

    def search(self, query: str, top_k: int = 8) -> list[dict]:
        """语义搜索。返 [{"path": str, "score": float, "snippet": str}]，
        按 score 降序；索引不存在或为空返 []（不抛异常）。"""

    def eval_search(self, evalset: Path | None = None) -> dict:
        """用 brain/search_evalset.json 跑检索质量。返
        {"total": int, "hits": int, "hit_rate": float, "misses": [id...]}。
        判定：expect_path 出现在该查询 top-5 结果的 path 中即命中。"""
```

#### 内部设计（按规定实现，避免自由发挥）

**分块** `_chunk(text) -> list[str]`：按 `\n\n` 切段；相邻小段合并，使每块落在 200–450 字；超过 450 字的长段按句号/换行硬切到 ≤450；最终 <50 字的碎块并入前一块（无则丢弃）。

**嵌入** `_embed(texts: list[str], is_query: bool) -> np.ndarray`：
- fastembed `TextEmbedding(model_name=MODEL_NAME)`，**模块级 lazy 单例**（同进程只加载一次）。
- `is_query=True` 时每条加 `QUERY_PREFIX`；文档侧不加。
- 返回 float32、已 L2 归一化的 (N, 384) 矩阵。

**落盘格式**（`data/brain_vectors/` 下两个文件）：
- `vectors.npy`：float32 (N, 384)，与 meta.jsonl 逐行对应。
- `meta.jsonl`：每行一个 JSON：
  ```json
  {"id": "company/company_300750.md#3", "source": "company/company_300750.md",
   "chunk_idx": 3, "mtime": 1753987200.0, "snippet": "该块前 200 字原文"}
  ```
  - `id` = `{source}#{chunk_idx}`，`source` 为相对 `vera_obs_vault/` 的 POSIX 路径。
  - 去重规则：**同一 source 的块在索引中至多存在一份**——`update_file()` 先过滤掉 meta 中 `source == 该文件` 的行（同步删掉 vectors 对应行），再追加新块，两文件整体重写（5 万行级，重写开销可忽略，不要搞复杂的多文件合并）。

**搜索**：加载 vectors.npy（进程内缓存），`query_vec @ vectors.T` 取 top-k。因为两侧都已归一化，点积即余弦相似度。

**CLI 入口**（`if __name__ == "__main__"`，这是 LLM 的唯一调用面，输出契约不得改）：

```bash
python -m brain.search_engine build [--force]     # 构建/重建，stdout 打印 {"files":N,"chunks":M}
python -m brain.search_engine search "固态电池" [--top-k 8]
python -m brain.search_engine update vera_obs_vault/对话沉淀/xxx.md
python -m brain.search_engine eval                # 打印检索质量报告
```

`search` 子命令 stdout 格式（供 LLM 阅读，中文，紧凑）：

```text
[1] score=0.712  company/company_300750.md
    公司在固态电池电解质领域与 XX 合作……（≤200字片段）
[2] score=0.685  company/company_002594.md
    ……
```

- 无结果打印 `（无匹配结果）`；索引不存在打印 `（索引不存在，请先运行: python -m brain.search_engine build）` 并以 exit code 2 退出；正常 exit 0。
- 所有路径输出相对 `vera_obs_vault/`（LLM 拿到后可自行拼全路径 Read）。
- 文件开头像 `brain/__main__.py:16` 那样 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（Windows GBK 控制台防炸，本项目已有先例）。

## 五、Phase 2：免费联网搜索（约 1 天）

### 5.1 目标

B 模式遇到实时信息（新闻/公告/政策/股价）能联网检索，不再只靠训练数据。

范围说明：初稿提到 FinnewsHunter 式"新闻+行情+公告三路并行"，**本版只落地统一文本搜索一路**（行情数据本地已有 xtquant/AKShare 链路，属于 A 模式职责，不重复造）。这是"如无必要勿增实体"的刻意裁剪。

### 5.2 新增文件 `brain/search_web.py`（约 150 行）

#### 公开接口

```python
def search_web(query: str, max_results: int = 8, backend: str = "auto") -> list[dict]:
    """联网文本搜索。返 [{"title","url","snippet","source"}]。
    snippet 已过 policy_pipeline.sources.gov_cn.sanitize_untrusted() 清洗。
    任何异常（限流/网络/包缺失）→ 返 [] 并向 stderr 打告警，不抛。"""

def format_results(results: list[dict]) -> str:
    """渲染为 LLM 可读的纯文本（见下方 CLI 输出契约）。"""
```

#### 实现要点

- 使用 `ddgs`：`from ddgs import DDGS; DDGS().text(query, max_results=n, backend=...)`。
  **ddgs 各版本签名有漂移**：调用处包 try/except TypeError，drift 时退回位置参数调用；对外契约只有一个——CLI 输出格式（下方），内部适配自己消化。
- backend 策略：`"auto"` = 依次尝试 `bing` → `duckduckgo`，首个非空结果胜出；也可显式指定。支持环境变量 `BRAIN_WEB_BACKEND` 覆盖默认（国内网络 bing 通常可达，DuckDuckGo 被墙，所以 bing 在前）。
- 两次调用间隔 ≥2s（模块内记 last_call 时间戳），防限流。
- 结果进返回值前逐条 `sanitize_untrusted(snippet)`（防网页夹带 prompt injection，与 policy_pipeline 同一道闸）。

#### CLI 入口（LLM 的唯一调用面）

```bash
python -m brain.search_web search "宁德时代 2026年7月 公告" [--max 8] [--backend bing]
python -m brain.search_web selftest    # 环境自检：依次试各 backend，打印可用性
```

stdout 输出契约：

```text
[1] 宁德时代发布2026年半年报 (bing)
    https://example.com/...

### 6.3 新增文件 `brain/eval_judge.py`（约 150 行）

#### 设计要点（先读这段，含刻意取舍）

- **grader 与被测模型同源**：都用本机 claude CLI（同 provider）。独立性仅在"独立 session、无对话历史"层面。这是已知的自我偏好偏差来源，**接受它**（换来零新依赖），但报告里必须标注此 caveat，且分数只用于版本间纵向对比，不对外宣称绝对质量。
- **不调用 `ask_brain()`**：它会强制拼接 `prompts.SYSTEM_PROMPT`（研究助理人设），污染 judge。judge 需要干净上下文，因此 **eval_judge.py 自己发一个最小 subprocess**：
  ```bash
  claude -p --output-format text --max-turns 1
  ```
  stdin 传入 judge prompt（不用 --resume，无 session，无工具需求）。
- 复用 `claude_cli.py` 的 `_find_cli()` 找可执行文件；CLI 缺失时返回 `{"error": ...}` 而非伪造分数（与 `eval.py:42` 同款诚实原则）。

#### 公开接口

```python
JUDGE_PROMPT = """你是严格的回答质量评审。对【问题】和【回答】按 5 维度各打 1-5 分：
1. accuracy 准确性：事实与数字是否有错
2. completeness 完整性：是否覆盖了问题的主要方面
3. citation 引用质量：是否给出具体文件路径/SQL/URL/数字（"有引用"不算分，要可核验）
4. counter 反证充分：判断类问题是否列出反向证据或风险
5. clarity 表达清晰：结构是否清楚、有无废话
{f focus 行：本题侧重点}
只输出一个 JSON 对象，不要输出任何其他文字：
{"accuracy":N,"completeness":N,"citation":N,"counter":N,"clarity":N,"reason":"每个维度一句扣分理由"}"""

def judge_answer(question: str, answer: str, judge_focus: str = "",
                 timeout: int = 120) -> dict:
    """调 claude CLI 打分。返 {"scores": {5维}, "total": float, "reason": str,
    "raw": str}；CLI 缺失/超时/解析失败返 {"error": str, "raw": str}（不抛）。"""

def parse_judge_output(text: str) -> dict | None:
    """从 stdout 提取 JSON。容忍 ```json 围栏与前后杂波；5 维缺任一或越界返 None。"""
```

`total` = 5 维均分（1-5 制）。

## 八、风险与边界

| 风险 | 缓解 |
|------|------|
| 模型首次下载失败（HF 被墙） | §3.0.1 镜像先行；`build` 失败时如实报错，不影响大脑其他功能 |
| fastembed 模型列表版本漂移 | §3.0.2 自检命令 + `MODEL_NAME` 单点常量 |
| ddgs 被限流 / 某 backend 不可用 | 2s 间隔 + bing→ddg 回退 + 失败返 `[]` 并提示"退回训练知识"；`selftest` 可随时体检 |
| 归档时索引同步增加 ~3-5s（模型加载） | 发生在回答返回之后；设 `BRAIN_NO_INDEX_SYNC=1` 可关停，代价是沉淀文件不进索引 |
| 公司文件被其他流水线重生成后索引陈旧 | 提供 `python -m brain.search_engine build --force` 全量重建；约定在公司文件批量再生成后手动跑一次（5 万块分钟级） |
| judge 与被测模型同源（自我偏好偏差） | §6.3 已声明：分数仅用于版本间纵向对比，报告自带 caveat |
| 网页内容夹带 prompt injection | 双层：清洗层 `sanitize_untrusted()` + prompt 层既有"数据非指令"红线（prompts.py 安全红线段不动） |
| Windows GBK 控制台输出特殊字符崩溃 | 所有新 CLI 入口 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` |
| 索引文件损坏 | `search()` 任何异常返 `[]`；删 `data/brain_vectors/` 后 `build --force` 即可重建，无状态损失 |

## 九、明确不做 / 后续可选

1. **多 agent 辩论（debate）**：刻意砍掉。未来若要重启，地基已够：`ask_brain(archive=False)` + 每角色独立 `channel=f"debate_{role}_{uuid}"`（**禁止传随机 session_id**——`claude_cli.py:111` 对显式 session_id 一律走 `--resume`，对不存在的 sid 会报错）即可编排，无需改本方案任何文件。重启时注意：内部角色调用必须 `archive=False`，否则角色草稿污染「对话沉淀」进而污染语义索引。
2. **新闻/行情/公告三路并行**：行情走既有 xtquant/AKShare 链路（A 模式职责）；公告如需专项源后续再加。
3. **前端改动**：无。所有新能力经 CLI 触发；Web 端用户经大脑自然语言间接受益（LLM 自己会用 Bash 调搜索）。
4. **付费搜索 API（Tavily 等）**：不接。
