## 一、目标

把 8-28 架构报告标记的 16 项"浅模块/接口债"中**进范围的 13 项**落地，让 VERA 的交易系统达成三个可验证结果：

1. **资金口径单点**：ETF 池 vs 股票池的预算帽、在途回款、市值计算收进一个深模块，对账/预算帽/日亏闸三道保命闸读同一份口径。
2. **接口完整**：消灭"调用方必须知道内部事实才能用对"的隐性契约（rotation 绕过 executor、last_batch_errors 侧信道、trading_days/dates 反义双胞胎、_UNSET 哨兵）。
3. **组合根归位**：trade_main.py 只做组装+事件接线，业务规则全部下沉到可单测的纯函数模块。

## 三、原则与纪律（沿用治理 I + 补充）

1. **纯移动不改行为**：所有下沉/迁出是代码搬家，行为逐字节不变；e2e 测试作为行为锁，搬迁前后必须全绿。
2. **先红后绿**：每个 Task 先写失败测试 → 跑红 → 写实现 → 跑绿 → 提交。禁止先写实现再补测试。
3. **每 Task 独立提交**：commit 粒度 = 一个 Task，`git add` 只挑计划内文件，不批量提交（工作区含他人未提交改动，见 §十）。
4. **改核心函数前先 grep 调用方**；新功能优先独立新文件，不塞进跑得好好的脚本。
5. **行号引用机器校验**：计划书/报告里的 `[file.py:line]` 必须过 `python -m docs.audit._verify_references`（行号随代码漂移，执行前重新核对锚点函数名）。
6. **新代码纪律**（沿用治理 I 附录 B）：公开面 ≤6 个符号；单函数参数 ≤6；业务计算不进 API 层/组合根；删除测试不过的模块不单独成文件。
7. **实盘安全**：所有改动在工作日收盘后做，改动当天跑完 `pytest tests/trade/` 全绿才合入；热更相关改动（A1 的 _apply_config）额外跑 test_e2e_trade 配置热更用例。
