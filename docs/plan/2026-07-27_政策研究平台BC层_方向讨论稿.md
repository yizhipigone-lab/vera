## 0. 一句话方向

把 VERA 从「选股 + 回测 + 实盘」升级为「**政策研究平台**」：以**十五五规划**为底层逻辑，建一个**持续更新**的政策-行业-个股知识图谱，对**选股候选 + 实盘持仓**做研判，定期出**阶段复盘报告**（这段时间买了啥、和大方向关联如何、赢率如何、内在规律）。

**铁律不变**：纯研究、纯展示、**绝不联入仓位调度**（CLAUDE.md 业务铁律 1）。

## 1. 为什么这么走

### 1.1 用户的真实想法（2026-07-27 升级，5 点）

1. 研判对象 = **选股候选 + 实盘持仓**（不只是回测池）
2. 知识底座要 **UPTODATE**：底层是十五五规划，持续刷政策/行业变化
3. **政策-行业-个股知识图谱**（关联网络）
4. 用 **Obsidian** 做双向链接 + graph view 可视化
5. **阶段复盘报告**：买了啥 × 大方向关联 × 赢率，发现内在规律

### 1.2 6 路研究汇总（每路最值钱的一句话）

| 路线 | 最值钱的发现 |
|---|---|
| **B 层业界** | A 股概念抽取无现成轮子；AKShare 东财概念板块免费召回 100%，做底盘零 LLM |
| **C 层业界** | 2026 国产 LLM 降价 6 次，云 API 单股研判 ¥0.01-0.05，年成本 < 2000 元，自建不划算 |
| **ValueCell 本地** | 借 research_agent 范式（YAML 配置 + fallback + XML prompt + 引用溯源），但**不引 agno 框架** |
| **TrendRadar 本地** | 两阶段筛 + 三层 hash + change_ratio 智能失效是省 token 利器；GPL3.0 只看不 fork |
| **TradingAgents-CN** | 30k star，多智能体辩论架构（LangGraph），但 graph 是流程图**不是知识图谱 KG**；**app/frontend 专有需授权**；v3.0 的复盘/持仓/知识图谱**未开源** |
| **知识图谱/Obsidian** | **SQLite 存图不引 neo4j**（几十万边够）；Obsidian 当只读渲染层；ChainKnowledgeGraph 做产业链种子；NBER w33814 四步法做政策抽取 |

### 1.3 TradingAgents-CN 的启示（重点）

- **契合点**：集成通达信、A 股本土化、纯研究不调仓——和 VERA 三条一致
- **版权红牌**：`app/`（FastAPI）+ `frontend/`（Vue）**专有，商业使用必须授权**；v1.1.0 个人免费商业授权。VERA 实盘后台有商业属性 → **只看思路，不搬代码**（与 TrendRadar 同等待遇）
- **方向验证**：它的 v3.0 路线图（复盘研究 / 持仓研究 / 知识图谱）= 用户想法，说明**方向被 30k star 团队市场验证**，但也意味着它在做竞品（v3.0 内测中）→ VERA 要么等它开源抄、要么自研差异化抢先

## 2. 我的思考迭代（透明展示，3 版）

### 🔄 迭代 1（原 4 路研究结论）：B 层加概念标签 + C 层加个股研判

格局小了——只是"加两列"，没抓住用户"知识底座 + 复盘"的核心意图。

### 🔄 迭代 2（看清用户想法 + TradingAgents-CN 后）：重构为四层

```
① 政策知识底座（持续更新）→ ② 政策-行业-个股图谱 → ③ 个股研判引擎 → ④ 阶段复盘报告
```

把"复盘报告"提前（用现有数据就能做、价值验证最快）。这一版方向对了，但**图存储选型 / Obsidian 介入度 / 政策底座怎么 UPTODATE** 三点没定。

### 🔄 迭代 3（Obsidian/知识图谱调研回来后）：定稿选型

- **图存储 = SQLite**（不引 neo4j）：政策-行业-个股图谱规模几十万边，SQLite + 递归 CTE 秒查；neo4j 千万边才赢，运维负担（JVM/Docker/2GB）违反「如无必要勿增实体」
- **Obsidian = 只读渲染层**：数据真相在 SQLite，Python + Jinja2 自动生成 vault markdown，用户在 Obsidian 看 graph view + Dataview 查询；**不让 Obsidian 当数据主人**（markdown 无 schema、查询弱）
- **政策 UPTODATE = RSSHub + AKShare + LLM 抽取**：不自己写爬虫，走现成轮子；抽取仿 NBER w33814 四步法（最权威中文政策抽取范式）
- **产业链种子 = ChainKnowledgeGraph**（刘焕勇，4654 公司 × 511 行业 × 95559 产品）做冷启动

## 3. 终版架构

### 3.1 四层 + 数据流

```
[政策源]                              [公司公告/研报]
  │ RSSHub (国务院/发改委/工信部)        │ AKShare / Tushare / 巨潮
  ▼                                    ▼
[政策流水线]                          [公司事件流水线]
  ├─ 内容哈希去重                       ├─ 公告分类(财报/重大事项/重组)
  ├─ LLM 抽取(Haiku 4.5, NBER 四步法)  └─ 关联股票代码
  └─ 入 kg_edges(AFFECTS 边)
         │
         ▼
[知识图谱底层 = SQLite（VERA 已有栈）]
  ├─ kg_nodes(node_id, node_type, payload_json)
  ├─ kg_edges(src, dst, edge_type, valid_from, valid_to, weight)
  └─ 索引: (src,dst,type), (node_type), (valid_to)
         │
         ├──────► [VERA 引擎消费]（松耦合接缝，None-on-failure）
         │          pipeline.py 调 policy_kb (现有 A 层 + 新 B/C)
         │          AFFECTS 边可作为新因子维度
         │
         └──────► [Obsidian 渲染层]（只读快照，定期 refresh）
                    Python + Jinja2 模板 → ~/vera_vault/*.md
                    Graph view 看全局 + Dataview 查询
```

### 3.2 图结构（5 类节点 + 8 类边，别贪多）

| 节点 | 主键 | 关键属性 |
|---|---|---|
| **Policy** 政策事件 | policy_id（发文字号/URL哈希） | title, 发文日期, 机关, 时效, 力度, 原文摘要 |
| **Industry** 行业 | sector_code（VERA 现有 881.SH） | name, P1/P2/P3/AVOID（继承 A 层） |
| **Stock** 个股 | stock_code | name, 市值, 财务快照 |
| **Product** 产品（产业链） | product_name | 上下游链 |
| **Theme** 题材（后期） | theme_id | 强弱档, 时效 |

**核心边**：`AFFECTS`(Policy→Industry，带方向/力度/传导延迟/时效) | `BELONGS_TO`(Stock→Industry) | `MAIN_PRODUCT` | `UPSTREAM_OF` | `SUPPLY_CHAIN` | `POLICY_THEME` | `CO_MOVEMENT` | `HOLDING`(运行时临时边)

### 3.3 知识分层（L1-L4，对应 VERA 已有缓存哲学）

| 层 | 内容 | 更新频率 | 失效机制 |
|---|---|---|---|
| **L1 稳定** | 行业分类、产业链骨架（ChainKnowledgeGraph）、公司基础信息 | 季度 | 退市/重组触发 |
| **L2 半稳定** | 十五五政策主轴（现有 `tongdaxin_priority.json` 的 P1/P2/P3/AVOID） | 年度 | 五年规划换届 |
| **L3 时效** | 具体政策事件、个股关联强度、研报观点 | 日/周 | `valid_to` 到期软归档 |
| **L4 运行时** | 当前持仓、近期交易、阶段报告 | 实时 | 报告生成完即冻结 |

> 复用 VERA `selection_cache` / `signal_day_cache` 的按日失效 + mtime 判定逻辑（2026-07-26 二期已落地）。

### 3.4 和 VERA 现有模块的接缝

| 层 | 现状 | 本次要做 |
|---|---|---|
| **A 层（已建）** | 行业→P1/P2/P3/AVOID 静态映射 | **不动**，作为 Industry 节点的 `static_priority` 属性 |
| **B 层（新建）** | - | Policy→Industry 动态 AFFECTS 边（政策事件驱动） |
| **C 层（新建）** | - | Industry→Stock 全量反向索引扩展 + Product 产业链穿透 |

**接缝不变**：`pipeline.py` 现 `tag_selections()` → `{票: P1/P2/P3}`，扩展为 `{票: {static_priority, dynamic_score, latest_policy_hits}}`；`serialize`「None 不加 key」松耦合规则不变（A 层已趟通）。

## 4. MVP 路线（P0-P3，每步带验证闸门）

> **铁律**：每步都有验证闸门，上一步不过下一步不投入（防过度建设）。

| 阶段 | 做啥 | 工期 | 成本 | 验证闸门 |
|---|---|---|---|---|
| **P0** | SQLite 存图 + ChainKnowledgeGraph 导入 + 持仓-产业链穿透查询 | 1-2 天 | 0 | 拿一只持仓票能查到它的产业链上下游吗？ |
| **P1** | RSSHub 自建（Docker）+ 政策流水线 + Haiku 抽取 + AFFECTS 边入库 | 3-5 天 | ~50 元测试 | 一条新政策能自动抽出来影响哪些行业吗？ |
| **P2** | Obsidian vault 生成器（Jinja2 模板）+ Dataview 查询模板 | 2-3 天 | 0 | 用户能在 Obsidian graph view 看到政策-行业-个股关联吗？ |
| **P3** | 阶段复盘报告生成器（选股+交易+赢率 × 大方向关联） | 3-5 天 | 0 | 报告能回答"这段时间买的票和十五五方向合不合、赢率如何"吗？ |

**P0-P3 合计 ~10-15 个工作日**，成本 < 100 元测试费。每步可独立交付价值、独立验证。

## 5. 关键决策（待用户拍板）

### 决策 1：本地 Ollama vs 云 API（DeepSeek 代理）
- **推荐**：**云 API**（DeepSeek 走硅基流动/腾讯云代理，避开官方 42% 可用性）。年 < 2000 元 vs 自建 ¥70 万；公告公开不泄密；schema 严格约束云 API 才真硬（Ollama 不真 schema-enforced，pydantic-ai issue #4917）
- **反方**：「本地部署优先」铁律——但本意是策略/资金机密不外发，公告是公开信息，发出去不违反本意；真正机密是 prompt 里的策略意图，那个不发
- **折中**：研判走云，持仓/资金/策略全本地；prompt 脱敏（中性表述，不暴露意图）

### 决策 2：个股研判深度
- **推荐**：**简化版**（1-2 个 agent：基本面 + 政策关联），砍掉 TradingAgents-CN 的辩论/交易员（VERA 只要研判不决策）
- **反方**：TradingAgents-CN 的多智能体辩论（5 分析员 + 看多看空 + 风险三派）更全面——但太重，且它的 app/frontend 专有不能搬

### 决策 3：Obsidian 介入程度
- **推荐**：**只读渲染层**（VERA SQLite 是真相源，Python 生成 vault 给 Obsidian 看）
- **反方**：双向编辑（用户在 Obsidian 改 markdown 回写 SQLite）——但 markdown 无 schema，回写易脏数据，不推荐

### 决策 4：TradingAgents-CN 借鉴边界
- **推荐**：**只看 `tradingagents/`（Apache 2.0）的 agent 角色设计思路**，不搬 `app/`/`frontend/`（专有），不 fork 整体
- **理由**：VERA 实盘后台商业属性 + 版权红牌

## 6. 铁律与风险

### 6.1 铁律（不动摇）
1. **纯展示不调仓**（业务铁律 1）——政策图谱只生成报告提示
2. **松耦合**——政策/研判模块崩了超时了，选股/回测/实盘零感知（None-on-failure，A 层已趟通）
3. **不引重型框架**——agno / langgraph / neo4j 都不引，自研薄壳
4. **版权**——TradingAgents-CN / TrendRadar 只看思路不搬代码
5. **不写第二份规则定义**——AFFECTS 边和现有 stop_config 一样，只一份

### 6.2 风险
| 风险 | 控制 |
|---|---|
| 政策爬虫稳定性（RSSHub 实例挂） | 松耦合降级；爬虫失败不影响已有图谱；多源兜底（AKShare+Tushare） |
| LLM 抽取幻觉（政策影响错行业） | NBER 四步法 + Haiku 抽 + Sonnet 复核 + 引用溯源（evidence_quote 必填）+ A 层行业锚点冲突告警 |
| ChainKnowledgeGraph 数据滞后（2022-2023） | 产业链骨架稳定；公司层用 VERA `selection/selector.py` 实时 ST/退市过滤兜底 |
| 成本失控 | Haiku 抽取（3x 省钱）+ 内容哈希去重 + batch + max_news 硬阈值 |
| 版权污染 | 不 fork 不拷贝；提示词模板属通用工程可参考改写 |
