# ETF 轮动动量改造 —— 工作计划书 (2026-08-20)

> 目标：把现有「MA20方向 + 250日回撤三态」的 ETF 轮动，改造为
> 「4周动量择腿 + 日频15%移动止损 + 空仓买黄金」的动量轮动，相关变量全部可配置。
> 回测依据：`research/etf_momentum_*.py` 系列（黄金版全窗口 +4415%/回撤 -31.7%/Calmar 1.21）。

## 一、现状梳理

### 1.1 现有信号规则（`trade/rotation.py`）
- `compute_signal(closes, ma_window=20, high_window=250, drawdown_threshold=0.20)`：
  纯函数，输入**单只指数**（signal_index=399673）收盘序列，输出三态：
  - `full_cyb`（MA20向上 且 回撤≥-20%）
  - `half`（MA20向上 但 回撤<-20%）
  - `full_gold`（MA20向下）
- `STATE_RATIOS`：三态 → (主腿比例, 避险比例) = (1,0)/(0.5,0.5)/(0,1)。

### 1.2 现有执行链（`RotationFeature`）
- `start(source)` → 开工作线程 `_worker` → `_fetch_closes(signal_index)` 取指数收盘
  （QMT→TDX→腾讯三级降级）→ `compute_signal` → `put(EVENT_ROTATION)`。
- 消费者线程 `on_signals` → `_execute(signal)`：
  查 QMT 持仓 → 回填 can_use（2026-08-19 修复）→ 算目标市值 → 换档卖/买。
- 调度：`execute_time=14:54` 每日一次（trade_main.py 定时 + 启动补偿）。

### 1.3 现有配置（`RotationConfig`）
| 字段 | 默认 | 作用 |
|---|---|---|
| enabled | False | 总开关 |
| etf_ratio | 0.5 | ETF 池占总资产比例 |
| signal_index | 399673.SZ | 信号用的指数 |
| cyb_etf | 159949.SZ | 主腿（创业板50） |
| gold_etf | 518880.SH | 避险腿1（黄金） |
| hedge_etf2 | "" | 避险腿2（空=单避险） |
| hedge_ratio | 1.0 | 黄金在避险篮子占比 |
| ma_window | 20 | MA20 窗口 |
| high_window | 250 | 250日高点窗口 |
| drawdown_threshold | 0.20 | 回撤阈值 |
| execute_time | 14:54 | 每日算信号+调仓时点 |

## 二、新规则精确定义

### 2.1 动量信号（周频）
- 风险腿两只：`cyb_etf`（创业板50）、`risk_etf2`（纳指，新增）。
- 每只算动量：`m = 今日收盘 / N个交易日前收盘 − 1`（N = `momentum_window`，默认 20 = 4周）。
- 择腿：动量最高 且 > 0 的那只 → 目标持仓；两只都 ≤ 0 → 目标 = 避险篮子（黄金）。
- 信号日：`signal_day`（默认周五），尾盘 14:54 算动量并**当日直接执行**（T 日执行，
  对齐回测「信号日 T 日收盘价买入」铁律；见 §八 更正）。
- ⚠️ 回测/实盘口径差：回测用 399673 指数代理创业板50（159949 上市前无数据），实盘用 ETF 本身。
  动量策略每周换腿，指数 vs ETF 的跟踪价差会累积，预期有 ±1~2%/年 的口径差，标注不消除。

### 2.2 日频移动止损
- 持仓风险腿期间，每日收盘后更新「持仓期最高收盘价 H」。
- 若当日收盘 < H × (1 − `trailing_stop_pct`)，即从高点回撤超阈值 → **当天切换避险篮子**。
- 避险篮子（黄金）**不设止损**（它是"躲"的位置）。
- H 在「换腿」时重置为当日收盘。

### 2.3 调仓执行
- 周频信号：signal_day（每周最后一个交易日）尾盘 `execute_time` 算动量并**当日执行**目标切换。
- 日频止损：每个交易日收盘后检查，触发即切避险篮子。
- 换腿成本万10（0.1%，**双边合计**：一次换腿=卖旧腿+买新腿，两笔共扣 0.1%，与回测口径一致；ETF 免印花税，仅佣金），沿用现有 `_place_order` 下单路径。

## 三、配置设计

### 3.1 新增字段
| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| risk_etf2 | str | "513100.SH" | 第二风险腿（纳指），空=单腿退化 |

- 迁移：`trade.yaml` 删除这 4 个字段，新增 4 个字段；`_coerce_rotation` 同步改校验。
- `hedge_etf2`/`hedge_ratio`：保留，作为「避险篮子」的拆分（空=单黄金，与"空仓买黄金"一致）。

## 四、代码改造清单（按文件）

### 4.1 `trade/rotation.py`（核心，改动最大）
1. **新增纯函数 `compute_momentum_signal(closes_by_leg, momentum_window)`**：
   输入 `{代码: 收盘序列}`，输出 `{"target": 代码 或 None(避险), "momentum": {...}}`。
   逻辑：逐腿算 `closes[-1]/closes[-1-momentum_window]-1`，取最高且>0 的腿；全≤0 → None（避险）。
2. **删除/保留 `compute_signal`**：旧 MA20 函数保留但标记 deprecated（供测试对照），
   生产路径不再调用。`STATE_RATIOS`、三态常量、`target_values` 相应替换。
3. **`_worker` 取数改造**：从「取单指数」改为「取两只风险腿的收盘序列」。
   `_fetch_closes` 已是单代码降级链，循环调用两次即可（QMT→TDX→腾讯每腿各走一遍）。
4. **`_execute` 改造**：
   - 输入信号从「三态 state」改为「目标代码 target」。
   - 目标市值：target=某风险腿 → 100% 池；target=None → 100% 避险篮子
     （复用 hedge_ratio 拆分黄金/避险2）。
   - 换档判断从 `_derive_state` 改为「当前持仓代码 ≠ 目标代码」。
   - 保留 can_use 回填逻辑（2026-08-19 内联于 `_execute` 持仓读取后, rotation.py:383-401,
     非独立方法；注：`_enrich_sell_quotes` 是 daily_report.py 日报卖飞字段，与此无关）。
5. **新增日频移动止损**：
   - `RotationFeature` 增加 `self._entry_high: dict[str, float]`（当前风险腿的持仓期最高收盘）。
   - 每日 `_execute` 前（或独立 `_check_stop`）先判止损：当前持仓是风险腿 且 收盘 < H×(1-pct)
     → 切换避险篮子。
   - H 持久化到 `rotation_state` 表（新字段或并入 signal_json），重启不丢。

### 4.2 `trade/config.py`
- `RotationConfig` 加 4 字段（见 3.1），删 4 个 MA20 字段。
- `_coerce_rotation`：新字段校验（risk_etf2 6位代码、momentum_window≥2、trailing_stop_pct∈(0,1)、signal_day 枚举）。
- `serialize`（to_dict）同步增删。

### 4.3 `trade_main.py`（调度）
- 现有 `execute_time` 每日定时 + 启动补偿，改造为：
  - 每个交易日 `execute_time`：先做**日频止损检查**；若今天是 signal_day（每周最后一个
    交易日）则**当日算动量并执行目标切换**（T 日执行），非信号日只维持当前目标。
- 信号日「算动量 → 当日执行」需要把当前生效目标持久化到 `rotation_state`（存 `pending_target`），
  供非信号日止损检查与冷启动恢复用（不再是「存 target → 次日执行」）。

### 4.4 `trade/store.py`
- `rotation_state` 表：signal_json 里增 `entry_high`（当前风险腿持仓期最高价）与 `pending_target`。
- 冷启动 `load` 时恢复这两个字段，防重启丢失移动止损基准与当前生效目标。

### 4.5 Web（`web/index.html` + `web/js/trade.js` + `trade/api.py`）
- 设置面板：新增 4 个输入（第二风险腿、动量窗口、止损阈值、信号日），移除 4 个 MA20 输入。
- 信号展示：`rotation/last` 的信号结构从「三态」改为「目标代码 + 各腿动量」。

## 八、自审记录（两遍）

### 第一遍：架构/设计缺口（6 处，已修正）

1. **信号数据源**：原计划沿用 `signal_index`，错。动量规则应直接用**风险腿 ETF 自己的收盘**
   （159949/513100），`signal_index` 彻底废弃。修正已并入 §四.4.1。
2. **execute_time 口径**（用户拍板 14:54 尾盘）：保留 execute_time=14:54 尾盘执行，贴近回测的
   收盘价口径；信号日**当日尾盘算动量并执行**（T 日执行，非「次日」——见 §八.第三遍纠正）。
3. **信号日 ≠ 固定周五**：节假日休市时周五无信号。改为「每周最后一个交易日」判定。
4. **止损 vs 周频信号优先级**：明确 **日频止损优先**（收盘后立即切避险，target 置 None），
   信号日执行时若持仓已触发止损则切避险、不按新 target 换腿。
5. **移动止损 H 生命周期**：进入风险腿 → H=当日收盘；持仓期每日 H=max(H,close)；
   切回避险 → H 清空。切回风险腿 → H 重置为当日收盘。
6. **避险篮子默认**：默认 `hedge_etf2=""`（=单黄金，即"空仓买黄金"），hedge_ratio 仅
   hedge_etf2 非空时生效。与用户规则逐字一致。

### 第二遍：边界/正确性（7 处，已修正）

1. **数据不足 warmup**：动量窗口历史不足（停牌/新股）→ 该腿动量算不出 → 不参与择腿；
   两腿都不足 → fail-safe 到避险。测试锁死。
2. **跨腿取数降级不一致**：每腿独立降级（QMT→TDX→腾讯），可能一腿 QMT、一腿 TDX。
   动量是"相对自身 N 日前"，同腿内前复权口径一致即可，跨腿差异影响小，接受并文档标注。
3. **自愈机制**：现系统 `_derive_state` 从持仓派生状态做"换档半途失败次日自愈"。
   动量规则下自愈 = 「当前持仓代码 == 目标代码 即已就位，否则再换」，比三态更简单，保留该语义。
4. **旧测试不是 parity 而是重写**：`test_rotation.py` 大量锁的是 MA20 三态行为，规则本质变了，
   应**重写**为新规则用例（不能声称"parity 保持"），仅保留 can_use 回填等与规则无关的测试。
5. **momentum_window 口径**：计划用「交易日数=20」，回测用「4个周五前」，两者有节假日细微差异。
   实盘用 20 交易日更稳健（不依赖周五对齐），文档标注此差异，不作为 bug。
6. **止损后踏空 V 型反弹**：日频止损会漏掉急跌急涨的 V 型反转（已知取舍，回测已暴露，
   文档标注为策略固有代价，不额外处理）。
7. **黄金避险腿自身下跌无保护**：避险腿不设止损（它是"躲"的位置），黄金若走熊则避险期亏钱。
   已知取舍，后续可选加"黄金跌破 N 日均线才避险"的增强，本期不做。

### 自审结论
- 13 处问题全部修正/标注，无阻塞项。
- 用户已拍板：**execute_time 保持 14:54 尾盘**（贴近回测收盘价口径）。

### 第三遍纠正（用户 2026-08-20 后期，执行时点语义）
- **原 §2.1/§2.3/§4.3 写的「次日执行」是错的**：用户澄清当时沟通的是「每周最后一个交易日
  尾盘 14:54 算信号 → **当日直接执行**」（T 日尾盘执行，非 T+1 次日）。
- 这与回测铁律一致：CLAUDE.md「信号日(T日)收盘价买入」。此前「次日执行」偏离了回测口径。
- **落地修正**：`_worker` 信号日分支直接执行（不再 signal_only 延迟）；`pending_target` 语义从
  「待执行目标」改为「当前生效目标」（供非信号日止损检查 + 冷启动恢复）；`execute_time` 默认
  值 14:56→14:54，线上 `config/trade.yaml` 同步 14:55→14:54。
