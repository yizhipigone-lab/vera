## 1. 背景与目标

对话大脑(`brain/`)目前是**"日报型 + 被动触发"**:`tools/daily_brief.py` 每日产出高质量热点简报(见 `docs/brief/2026-08-12_今日热点追踪简报.md`),但要用户主动跑;没有盘中实时监控、没有异动推送、新闻情绪只有 LLM 定性 emoji(🔥⚡❄️)没有量化分。

用户要求增强为两件事:
- **B 实时监控 + 飞书推送**:盘中盯指定板块,异动主动推送
- **C 情绪量化**:给新闻/板块算情绪分

### 2.2 调仓边界(铁律 1,最高优先级)
- 情绪/舆情**只报告显示,绝不影响任何买卖决策**
- **不接入选股打分、不触发自动下单、不联入仓位调度**(用户 2026-08-12 明确选"只报告显示")
- 纯研究/提示层,人工把关
- 本模块不读不写 `trade/` 目录、不碰 `data/trade/trade.db`(沿用 brain 安全红线)

### 2.3 推送渠道
- **飞书**(参考 `trade/notifier.py` 的 webhook + daemon worker 架构,**独立实现** `research/sentiment_notifier.py`,不 import trade/——守 §2.2 物理隔离),不加微信

### 2.4 "实时"的精确定义
- **盘中(09:25–11:30 / 13:00–15:00 交易日)**:每 10 分钟轮询一次(平衡及时性与 akshare 限连/LLM 成本)
- **盘后 15:05**:舆情日报(当日情绪聚合 + Top 异动复盘)
- **非交易日**:只跑突发新闻监听(财联社电报 7×24 有更新),降频到每 30 分钟
- 不追求秒级"实时"(akshare 限连 + LLM 延迟做不到,也没必要)

## 4. 新建模块(缺口)

### 4.1 情绪量化器 `brain/sentiment_judge.py`(最大缺口,完全空白)
**职责**:给一条新闻文本打情绪分。
**方案**:复用 `ask_brain_sync` 调 Claude,套 `eval_judge.py` 的"取结构化 JSON 评分"范式(项目已有,不引新依赖)。

输出结构:
```json
{
  "polarity": -0.8,      // -1(极空) .. +1(极多)
  "strength": 2,          // 0 弱 / 1 中 / 2 强
  "confidence": 0.85,     // 0..1
  "evidence_quote": "原文关键句",  // 可追溯
  "hit_pool": [{"type": "concept", "value": "算力"}, {"type": "industry", "code": "881319.SH"}]  // 命中的监控标的(分类型,不混字符串)
}
```

**降本**:只对"新增 + 命中股票池"的新闻打分(§4.2 去重后),不全量喂 LLM。单条约 1 次 LLM 调用。

**v2 备选**:规则词典 + 少样本 LLM 校准(降本,但精度降),v1 先不做。

### 4.2 增量去重层 `brain/news_dedup.py`(空白)
现有 fetcher 全是全量拉。需三件:
- **url/content hash 缓存**:SQLite 存已处理新闻 hash(仿 `selection_cache` 的 `SCHEMA_VERSION` 模式),命中跳过
- **时间窗口过滤**:只取最近 N 分钟的(盘中增量)
- **股票池过滤**:复用 `concept_tagger.tag_stocks` + `policy_tagger.tag_stocks`,只保留命中监控池的新闻

表结构(新建 `data/sentiment/news_seen.db`):
```sql
CREATE TABLE news_seen (
  content_hash TEXT PRIMARY KEY,
  url TEXT, code TEXT, polarity REAL, ts INTEGER, pushed INTEGER DEFAULT 0
);
```
**SCHEMA_VERSION 铁律**(memory: 改选股/缓存逻辑必 bump):此表加 `SCHEMA_VERSION`,逻辑变更必 bump。

### 4.3 盘中周期调度 `scheduler/vera_scheduler.py` 加 `add_interval`(半成品)
现状 `VeraScheduler` 只支持 `add_daily/add_monthly`,**不支持"每 N 分钟"**。新增:
```python
def add_interval(self, name, func, every_seconds, trading_hours_only=True):
    # every_seconds: 轮询间隔(默认 600=10min)
    # trading_hours_only: True=仅 09:25-11:30/13:00-15:00 交易日; False=全天
```
`is_due` 加交易时段判定(复用 `trading_calendar.is_trading_day`,加 hours 判断)。**跨时段边界行为**(审计 LOW-3):interval 在交易时段内连续计时,**跨时段重置**(11:30-13:00 午休不算 elapsed),**时段开始首 tick 立即触发一次**(09:25 / 13:00 开盘即扫,不等满 600s)。

**部署形态(关键决策)**:舆情任务**挂到现有 `scheduler` 进程**(`python -m scheduler`,已跑 notes_gen/evolution),**不新建进程**(守铁律 8"如无必要勿增实体"),**不嵌入 trade_main**(避免拖交易线程,守铁律 2/3)。scheduler 进程本就不碰交易,天然隔离。

### 4.4 飞书 alert 入口 —— 独立 `research/sentiment_notifier.py`(守死 §2.2 隔离铁律)

**决策(审计 HIGH-2 修复,口径定死)**:用**独立薄封装,不 import trade/ 包**。理由:§2.2 承诺"不读不写 trade/ 目录"是业务铁律 1 的硬隔离。虽然 `trade/__init__.py` 经核实是懒加载(import trade.notifier 不会拖出 xtquant/gateway/book),但**物理隔离比逻辑隔离更经得起审计**——不留"它 import 了 trade 包"的把柄,也免得未来 trade/ 加了 eager import 把 sentiment 任务拖下水。

### 4.5 异动规则引擎 `brain/alert_rules.py`
判定"什么算异动,该不该推"。**触发规则 4 条**(可配置,放 `config/sentiment.yaml`):
1. **个股情绪突变**:命中池的新闻 `|polarity| ≥ 0.6 且 strength ≥ 2` → 推
2. **板块急涨急跌**:某 P1 行业涨停数 / 全市场涨停数 `≥ 30%`,或较前 5 日该占比均值偏离 `≥ 10pp` → 推
3. **大盘指数阈值**:主要指数(上证/深成/创业/科创)涨跌幅 `≥ ±1.5%` → 推
4. **量能异常**:两市成交额较前 5 日均值放量或缩量 `≥ 1.5 倍` → 推

**推送抑制策略(独立于触发规则,噪声控制层,不计入"规则条数")**:
- 同一标的 30 分钟内只推一次(防刷屏)
- 单次 tick 推送上限 3 条(按 `|polarity| × strength` 排序取 Top)
- 盘后日报不受此抑制(全量汇总)

```

  │
  ├─ add_interval("intraday_sentiment", every=600s, trading_hours_only=True)
  │     │
  │     ▼ [抓取层] (fail-soft, _call_with_timeout 包裹)
  │     data_tools.market_snapshot(fresh=True)   ← 指数/涨停池/南向
  │     ak.stock_info_global_cls                  ← 财联社电报(实时主力)

  │     ▼ [过滤+去重层] news_dedup
```

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **akshare 限连**(东财/腾讯盘中高频撞限) | 抓取失败、漏新闻 | 复用 `_call_with_timeout` + 多源降级链(财新→央视→财联社)+ 自节流(10min 间隔,不更密) |
