# 2026-08-16 float32 价格矩阵（回测提速）方案书

> 成文日期 2026-08-16 · 回测引擎侧 · 药2（单次回测提速首选）

## 一、目标（大白话）

把回测引擎里**价格矩阵**（现价/最高/最低/开盘）从 float64 降到 float32，
内存减半、CPU 缓存更友好，单次回测提速约 1.5~2x（1m 全 A 场景额外解决
"内存装不下"的问题）。

**铁律**：价格数据才降 float32；**资金/权益账（cash/equity/trade buffer）保持
float64**，绝不降——钱要精确到分，价不用精确到小数点后 15 位。

## 二、为什么安全（精度论证）

float32 ≈ 7 位有效数字，float64 ≈ 15 位。价格 float64→float32 的误差约
`1e-7` 相对量级：40 元的股票差 0.000004 元。这远小于已有的滑点（默认千1）
和手续费近似。对盈亏/夏普的影响肉眼不可见。

## 三、精确改动点（已核对代码）

价格矩阵进入核心循环的唯一收口是 `_resolve_stop_and_build_loop`
（`run()` 与 `run_cached()` 两入口都走这里，`engine.py:563/737` 调用）。

| 位置 | 现状 | 改法 |
|---|---|---|
| `_resolve_stop_and_build_loop` 顶部 | 无 | 新增：`close.values` + `high/low/open_np` 统一 `np.asarray(..., dtype=np.float32)` |
| `engine.py:358`（ATR 输入） | `close.values.astype(np.float64)` | 改用上面算好的 `close_np`（float32） |
| `engine.py:391`（loop 的 price_np） | `close.values.astype(np.float64)` | 改用 `close_np`（float32） |

**为什么只改这一个收口**：`run()`/`run_cached()` 都经它，改一处即两入口一致，
不产生 run vs run_cached 漂移（parity 测试有专门守卫）。

## 四、已知影响与风险

1. **数字轻微漂移**：float32 会让回测结果在 `~1e-7` 量级微移。`tests/test_snapshot_parity.py`
   的 engine 层快照会失配 → 需 `python -X utf8 tools/gen_snapshot_parity.py` 重生成。
   loop 层快照（合成数据直喂 `build_backtest_loop`）不受影响。
2. **内存非严格减半**：本次只改核心循环入口，`close` 等 float64 DataFrame 在循环期间
   仍存活（源未释放）。要"严格减半"，后续再在数据加载处转 float32（第二阶段，暂不做）。
3. **实际提速待实测**：引擎主循环是纯 Python 逐元素访问，float32 的缓存收益约
   1.2~1.5x；向量化段（信号/公式/reindex/ffill）约 2x。真实 1m 提速需真机量，
   不在此环境吹数字。

## 五、验收标准

1. `pytest tests/test_snapshot_parity.py` 重生成快照后全绿。
2. `pytest tests/test_loop_parity.py` + 相关 backtest 测试全绿。
3. 抽样对比同一回测 float64 vs float32 的 equity/trades，确认差异在 `1e-6` 量级内。
