## 1. 背景与动机（实测驱动，非推测）

用户痛点: 网页点一次回测等得久（日线 + 5m 都久）。通读全链路 + 本机实测（[bench_phases.py](../../tools/bench_phases.py)）后定位真凶:

**5m 回测各阶段实测（QUANTQQ 公式，全 A 选股 5001 只 → 52 信号，20 天）:**

> ⚠️ **日线未被 bench 直接证实**: current.yaml 公式名 `TEST` 在通达信不存在, bench 两轮日线全失败 ([bench_phases.log:113,225](../../bench_phases.log)); 日线"等久"按 resolve_universe ~17s + 公式 ~16s 外推同量级 ~33s。**优化落地时应换真实公式补测日线**（审计 LOW）。

| 阶段 | 冷缓存 | 热缓存 | 占比 |
|---|---|---|---|
| **选股 step1** | **32.78s** | **33.32s** | **~92%** |
| 取数 step2 内 | ~1.7s | ~1.7s | ~5% |
| 核心循环 | 0.01s | 0.01s | 0.03% |
| 基准对比 step3 | 0.22s | 0.20s | <1% |
| 报告画图 step4 | 0.29s | 0.10s | <1% |
| 总计 | 35.49s | 35.65s | |

**结论: 92% 的时间在选股，核心循环占 0.03%。** 用户最初问的"核心循环 numba 20-50 倍"被实测彻底否决（0.01s 优化无感知）。真正的肉在选股，且 [formula_runner.py](../../core/formula_runner.py) / [selector.py](../../selection/selector.py) grep `cache` 零匹配——**选股零缓存，每次回测都全付 ~32s**。

选股 32s 拆解（log 时间戳推得）:
- **~17s**: [resolve_universe](../../selection/selector.py#L45) 拉全 A 5206 只列表 + ST/退市过滤
- **~16s**: [run_stock_selection_with_dates](../../core/formula_runner.py#L81) 分 51 批（[BATCH_SIZE=100](../../core/formula_runner.py#L129)）串行调 `tq.formula_process_mul_xg`

## 2. 目标与非目标

### 目标
- 改止盈止损参数重跑同一公式: **35s → ~2-3s**（选股 32s 命中缓存 → ~0.3s）
- 零策略风险: 不动选股/回测口径，纯加缓存层
- 不破坏现有: 保留直跑路径，缓存层独立新文件

### 非目标（明确不做）
- **numba / 核心循环优化**: 0.01s，实测否决
- **公式批次并行**: 需先验证 TDX 是否支持并发调用，另开任务
- **改选股公式逻辑 / ST 过滤 / 回测买入口径**: 铁律禁区（CLAUDE.md: 尾盘选股→T 收盘买入）
- **改 universe 配置语义**: 缓存只读配置，不改配置

## 3. 现状分析

### 3.1 选股完整路径
```
Pipeline.step1_select (pipeline/pipeline.py:64)
  └─ StockSelector.run (selection/selector.py:122)
       ├─ resolve_universe (selector.py:45)         ← ~17s: DataFetcher.get_stock_universe + filter_stocks
       └─ FormulaRunner.run_stock_selection_with_dates (formula_runner.py:81)
            └─ 51 批 × tq.formula_process_mul_xg (formula_runner.py:144)  ← ~16s
  → 返回 DataFrame[stock_code, select_date, formula_name]
```

### 3.2 缓存现状: 两段都零缓存
- [selector.py](../../selection/selector.py) grep `cache`: 无匹配
- [formula_runner.py](../../core/formula_runner.py) grep `cache`: 无匹配
- 选股每次回测从头跑

### 3.3 matrix_cache 的空洞
[backtest/matrix_cache.py](../../backtest/matrix_cache.py) 已缓存"选股**之后**的矩阵产物"（取数+矩阵准备），key 含 selections 哈希（[matrix_cache.py:85](../../backtest/matrix_cache.py#L85)）。但它管不到选股本身——**选股是它上游的空洞**。两层缓存叠加后，改参数重跑: 选股命中 + 矩阵命中 + 循环 0.01s ≈ 秒级。

## 4. 方案设计

### 4.1【推荐】整段选股缓存（selection_cache）

**思路**: 在 `Pipeline.step1_select` 外包一层缓存，整段缓存 `StockSelector.run()` 的输出（selections DataFrame）。不分层，因为用户每次只跑一个公式（分层无额外收益但复杂度翻倍 → KISS）。

**新建** `selection/selection_cache.py`（结构照 [matrix_cache.py](../../backtest/matrix_cache.py)）:
- `build_key(formula_name, formula_arg, universe_cfg, start, end, period, dividend_type, today_str)` → blake2b hex
- `load(cache_root, key)` → 命中返回 DataFrame，未命中 None
- `save(cache_root, key, selections, keep=N)` → 落盘 + LRU 清理
- `_prune(root, keep)` → 照 matrix_cache LRU

**接缝**（不破坏现有，保留旧路径）——在 [pipeline.py step1_select](../../pipeline/pipeline.py#L64) 内:
```python
# 伪代码 (实现时照此结构, 不改 selector/formula_runner)
def step1_select(self):
    ...
    use_sel_cache = self.config.get("selection_cache", {}).get("enabled", True)
    force_refresh = self.config.get("selection_cache", {}).get("force_refresh", False)
    today_str = datetime.now().strftime("%Y%m%d")   # build_key 参数注入 (审计 LOW), 测试可传常量绕过真实跨日
    cached = None
    if use_sel_cache and not force_refresh:
        from selection.selection_cache import build_key, load, save
        key = build_key(formula_name, formula_arg, universe_cfg, start, end, period, dividend_type, today_str)
        cached = load(cache_root, key)
    if cached is not None:
        logger.info("选股缓存命中: %s (%d 条)", key[:12], len(cached))
        selections = cached
    else:
        # 旧路径 (直跑, 不动 selector.run)
        selections = self.selector.run(...)
        if use_sel_cache and not selections.empty:
            save(cache_root, key, selections)
    # raw CSV 始终写 (命中/miss 都写, 保持调试产物连续 — R9 对策, 审计 MEDIUM)
    if not selections.empty:
        ...原 {strategy}_raw_{TS}.csv 保存逻辑 (pipeline.py:82-87) 不动...
    return selections
```

**落盘格式**: parquet（selections 是 DataFrame，照 [kline_cache.py](../../core/kline_cache.py) 的 parquet 用法；比 pickle 稳，跨版本安全）。
**目录**: `data/selection_cache/`（照 `data/matrix_cache/`、`data/kline_cache/`）。
**LRU**: 保留最近 10 份（selections KB 级，比 matrix_cache 的 GB 级宽松）。

### 4.2【备选】分层缓存（L1 股票池 + L2 公式选股）

- **L1**: 缓存 `resolve_universe` 输出（List[str]），key = universe 配置 + 日期。跨公式共享（多公式场景省更多）。
- **L2**: 缓存 `run_stock_selection_with_dates` 输出，key = 公式 + L1 列表哈希 + 区间 + period。

**何时选它**: 若未来跑多公式批量（MultiFormulaSelector），L1 跨公式共享省 17s×N。
**现在不选的理由**: 用户每次只跑一个公式，L1 跨公式价值为零，但两层 key/失效复杂度翻倍。**先上 4.1，多公式成为常态再升 4.2**（YAGNI）。

## 5. 缓存 key / 失效 / 命名

### 5.1 key 构成
```
blake2b(
  formula_name, formula_arg,
  universe_cfg 哈希 (type + exclude_st + include_etf + etf_only + sectors 排序),
  start_time, end_time, period, dividend_type,
  today_str (YYYYMMDD 当天日期),          ← 按日失效
  SCHEMA_VERSION,
)
```

> **为何 key 不含 resolve_universe 实际输出列表哈希（R8 决策，审计 MEDIUM）**: ST 过滤（[filter_stocks](../../selection/selector.py#L106) 走 TDX IsSTGP）是**数据驱动**而非配置驱动——配置不变，输出也会漂移（bench 实测 33 秒内 5206→5001/5002 差 1 只，[bench_phases.log:231,346](../../bench_phases.log)）。理论上 key 应纳入实际列表哈希才精确，但**算列表哈希必须先跑 resolve_universe（~17s）**——整段缓存省 32s 的意义就打折到只省公式 ~16s（35s→19s）。权衡：**接受按日失效掩蔽日内 ST 漂移**（实盘每日盘后单跑，日内 ST 极少变；若漂移恰为命中股，selections 漏 1 条，force_refresh 可纠正），换取省满 32s（35s→3s）。详见 §6 R8。

### 5.2 失效策略（关键决策点）

**选股输入 = 公式 + 池 + 区间 + period + 复权 + 通达信盘后数据状态**。前 5 项进 key，第 6 项（盘后数据）是失效关键。

| 策略 | 机制 | 优 | 劣 |
|---|---|---|---|
| **按日失效（推荐）** | key 含当天日期，次日自动 miss | 简单可靠，盘后数据日级更新天然匹配 | 同一天内重下盘后数据会用旧结果; **掩蔽日内 ST 过滤漂移**（filter_stocks 数据驱动，bench 实测 5001↔5002） |
| 通达信目录 mtime 指纹 | 扫 E:\NEW_TDX\Vipdoc 下 .day 文件 mtime | 更准 | 文件巨多扫描慢，依赖通达信目录结构（脆弱） |
| kline_cache mtime 指纹 | 照 matrix_cache.data_fingerprint | matrix_cache 验证过 | **不可用**: 选股直调 TDX 公式不经 KlineCache，kline_cache mtime 不反映选股输入 |

**推荐按日失效 + force_refresh 开关**（用户主动刷新兜底）。理由: 选股用历史 bar（[count 参数](../../core/formula_runner.py#L136) 扫历史），非实时行情；盘后数据不变则结果不变，按日失效成立。force_refresh 给"今天重下了盘后数据想立刻重跑"的场景。

### 5.3 配置开关命名（与现有缓存一致）
- `use_kline_cache`（K 线）、`matrix_cache`（矩阵）→ **`selection_cache`**
- yaml 结构: `selection_cache: {enabled: true, force_refresh: false}`
- 默认: **enabled=True**（pipeline step2 已默认开 matrix_cache，选股缓存同理默认开，server 前台路径受益）

## 7. 测试计划（tests/test_selection_cache.py）

守卫式 + parity + 命中/失效，照 tests/ 现有风格:

1. **命中 parity**: 同配置第二次 load → DataFrame 与直跑值一致; **显式断言 select_date dtype 一致**（审计 INFO: parquet round-trip 可能 datetime64 ns↔us，不能只靠 `equals`，用值比较 + dtype 断言）
2. **配置失效**: 改 formula_name / formula_arg / universe.type / start_time / end_time / period / dividend_type 任一 → miss
3. **日期失效**: 注入不同 today_str → miss（绕过真实跨日等待）
4. **force_refresh**: 标志为 True → 强制 miss，重新落盘
5. **universe 完整哈希**: 改 exclude_st / include_etf / sectors → miss（防 R5）
6. **空选股不缓存**: selections.empty → 不落盘（防缓存空帧误导）
7. **LRU 清理**: 写入 N+1 份后最老的被清
8. **不破坏回归**: 现有 Pipeline.run / matrix_cache 流程回归（selections 缓存命中后 matrix_cache 仍能正常 build_key + 命中）
9. **并发原子写**: 模拟两进程同时 save 同 key（tmp+replace 不互踩，照 kline_cache 的 Windows 重试逻辑）
10. **CSV 写入行为（R9）**: 缓存命中时 raw CSV 仍写入（与 miss 一致），文件存在且内容与 selections 对应
11. **today_str 注入（审计 LOW）**: build_key 接 today_str 参数；生产侧 `datetime.now()` 传入，测试传常量绕过真实跨日
