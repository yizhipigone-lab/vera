# 2026-08-16 K线缓存读取提速 方案书

> 成文日期 2026-08-16 · core/kline_cache.py · 1m 回测"取数+建矩阵"瓶颈治理

## 一、目标（大白话）

1m 回测慢在"读本地缓存"这条链上，不在核心循环（循环只占 18%）。本方案把
`core/kline_cache.py` 读路径的重复劳动去掉，让热跑（缓存命中）从 **~1.3s
（20 只股）压到 ~0.4s**，全 A 规模按比例受益。

## 二、实测证据（`research/profile_backtest_e2e.py`，20 只股真实 1m）

| 段 | 耗时 |
|---|---|
| 冷跑（含 TDX 网络取数） | 2.99s |
| 热跑（缓存命中） | 1.31s |
| 其中核心循环 loop.run | 0.24s |
| 其中 kline 缓存读（缺口检测+parquet 读+时间戳） | ~1.0s |

cProfile 热点（热跑）：`_detect_and_fill_gaps` 0.51s（20 次）、`_read_parquet`
0.40s（40 次）、`to_datetime`+`should_cache`+`_maybe_cache` ~0.53s、
`nt.stat` **17402 次**、`execute` 0.215s。

## 三、四个病根（均已核对源码）

### 病根1：每次 manifest 查询都新开 SQLite 连接

`_conn()`（`core/kline_cache.py:69`）每次 `sqlite3.connect` + 两条 PRAGMA；
`_manifest_get`/`_cooldown_elapsed`/`_manifest_set_intact` 每只股每次 get 要
开 2~3 个新连接 → 上万次文件 stat + 建连开销。

### 病根2：读 parquet 时逐 bar 重复做 datetime 计算

- `_read_parquet`（`:546`）：`df.index.normalize()` 在 `:560` 被调**两次**（每次全索引遍历）。
- `_detect_and_fill_gaps`（`:466`）：`:473` 逐 bar `d.strftime("%Y%m%d")` 建集合、`:479`
  的 `_warn_partial_bars_intraday` 又 `groupby(df.index.normalize())`。
- 实测 parquet 的 `date` 已是 `timestamp[us]`，读回即 `datetime64`，无需 `to_datetime` 猜格式。

### 病根3：同一只股 parquet 读两遍

`_ensure` 里的缺口检测读一次（`:469`），`get()` 拼宽表又读一次（`:166-167`）。

### 病根4：缺口检测每次都全量重做，不看 `intact` 标记

`_detect_and_fill_gaps` 每次 get 都重读 parquet + 重读日历 + 重算日期集合，
哪怕 manifest 已记 `intact=True`（上次查过无缺）。缺口不会凭空出现。附带
`_get_calendar()`（`:126`）无缓存，每次现读日历 parquet。

## 四、修复方案（对照病根，按风险递增排序）

### Fix A · 持久 SQLite 连接（病根1）

`__init__` 建一条 `self._db = sqlite3.connect(..., check_same_thread=False)` +
一次性 PRAGMA；`_conn()` 改为返回 `self._db`（不再新建）。现有 `with self._conn()
as c:` 语义不变（`with` 管的是事务不是连接生命周期）。写路径已有 `self._lock`
串行，读路径在回测 fetch 阶段单线程，安全。

### Fix B · datetime 计算去重 + 向量化（病根2）

- `_read_parquet`：`normalize()` 算一次存局部变量复用；`to_datetime` 改为定点
  `.astype("datetime64[ns]")`（parquet 已是 timestamp，无需格式推断）。
- `_detect_and_fill_gaps`：逐 bar `strftime` 改向量化 `df.index.strftime("%Y%m%d")`。
- `_warn_partial_bars_intraday`：`groupby(df.index.normalize())` 改按 `df.index.date`
  或预计算 key。

### Fix C · 交易日历缓存（病根4 的一部分）

`_get_calendar()` 加模块级/实例级 memoize（交易日历一天内不变，进程内缓存即可）。

### Fix D · `intact=True` 且区间覆盖时跳过缺口检测（病根3+4 核心，敏感）

在 `_ensure` 里，当 manifest `intact=True` **且**请求区间完全落在缓存
`[first_date, last_date]` 内时，跳过 `_detect_and_fill_gaps`（自然免去第二次
parquet 读 + strftime + 日历读）。**任何区间扩展 / intact=False / 只读模式外
一律照查**，缺口兜底逻辑不丢。

## 五、代码改动清单

| 文件 | 改动 |
|---|---|
| `core/kline_cache.py` | Fix A：`__init__` 持久连接 + `_conn()` 返回它 |
| 同上 | Fix B：`_read_parquet`/`_detect_and_fill_gaps`/`_warn_partial_bars_intraday` datetime 去重向量化 |

| 同上 | Fix D：`_ensure` 里加"intact 且覆盖则跳过检测"守卫 |

## 六、风险与正确性边界

- **Fix D 最敏感**：缺口检测是治"TDX 临时缺数据"（002008 类事件）的兜底网。
  守卫只放行"manifest 已确认 intact 且区间被完全覆盖"，绝不静默吞缺口；
  `force_invalidate` 置 intact=False 后仍会强制重查。补拉后仍缺 → intact=false
  的既有告警路径不变。
- **Fix A 并发**：单进程内 fetch 阶段单线程读，写已锁；跨进程各持各的 KlineCache
  实例（subprocess 并行），互不影响。保持锁纪律即可。
- 四步全部是**读路径提速，不改取数/合并/补拉/告警逻辑**，回测数值零变化。

   tests/test_parquet_cache.py tests/test_degrade_5m.py -q` 全绿。
2. 缺口兜底不破：构造"缓存有缺日"用例，确认仍补拉 + 告警 + intact=false。
