# ETF 轮动「避险腿两只可配」实施记录 (2026-08-18)

## 目标

避险腿从"固定单只黄金"扩展成"可配两只 ETF + 滑条调比例"(如黄金+纳指 50/50 或 30/70)。
默认仍是单黄金，向后完全兼容 —— 老 `trade.yaml`、老测试行为逐字节一致。

## 新配置字段 (`RotationConfig`)

| 字段 | 类型/默认 | 语义 |
|---|---|---|
| `hedge_etf2` | `str = ""` | 第二只避险 ETF；空串=单避险(现状只买黄金) |
| `hedge_ratio` | `float = 1.0` | 黄金ETF在避险篮子里的占比 [0,1]；1.0=纯黄金, 0.5=各半, 0.3=黄金30/避险ETF2 70；仅 `hedge_etf2` 非空时生效 |

## 核心逻辑

信号层(`compute_signal`)与三态(`STATE_RATIOS`)完全不动 —— 信号只挂主腿, 与避险腿无关。

新增纯函数 `trade/rotation.py::target_values(cyb_etf, gold_etf, hedge_etf2, hedge_ratio, target_state, pool)`:
1. 取三态 → (主腿占比, 避险总占比);
2. 避险总再按 `hedge_ratio` 拆两只: 黄金 = ratio×避险总, 避险ETF2 = (1−ratio)×避险总;
3. `hedge_etf2` 为空时 ratio 强制 1.0 (单避险)。

`_execute` 从"硬编码两腿(创/金)"泛化成"`legs = [(代码, 目标市值), ...]` 循环"，
复用原有 `_sell_to / _buy_to / _etf_value / _fetch_quotes / _place_order`(本就按代码通用)。
`_derive_state(v_cyb, v_hedge)` 第二参数语义改为"避险腿总市值"(避险两只求和)。

## 改动文件

- `trade/config.py` — dataclass 加 2 字段 + `_coerce_rotation` 校验(代码格式/去重/比例范围) + 序列化导出
- `trade/rotation.py` — 新增 `target_values` + `_execute` 两腿→N腿泛化 + `_derive_state` 语义
- `trade/api.py` — `/api/trade/rotation/last` 配置摘要补 2 字段
- `trade_main.py` — `_stock_pool_value` 识别"轮动 ETF"集合补 `hedge_etf2`(防纳指被误算进股票池预算)
- `web/index.html` — 轮动区加"避险ETF2"输入框 + "避险腿黄金占比"滑条(0–100%, 步进5)
- `web/js/trade.js` — 新增 `_rotHedgeLabel` + 滑条 wiring + fillSettings/gatherSettings 读写两字段
- `tests/trade/test_rotation.py` — 加 `target_values` 纯函数测试 + config 校验 + 各半端到端首买测试

## 测试

## 关键决策 (用户拍板)

1. 滑条语义 = **黄金占比**(默认 100, 左拉纳指变多)。
2. 字段名保留 `gold_etf` 不改名, 新增 `hedge_etf2` / `hedge_ratio`。

## 待办 / 边界

- 换两只避险腿时 `_sell_to/_buy_to` 顺序为主腿→黄金→避险ETF2, 与旧两腿顺序一致。
- 未动风控闸/对账/下单路径; `_place_order` 走同一套。
- 税费/滑点仍未计(P2 回溯补算, 与现状一致)。
