# ETF 轮动「资金三份错峰」改造计划书

> 日期: 2026-09-16 ｜ 状态: v3 (两轮逐行审阅均已修订, 审阅记录见附录 A/B)
> 依据: `research/2026-09-16_ETF轮动周频vs每日双负保险丝_10年回测研究报告.md`
> (10 年回测: 三份错峰 周三/四/五 = 年化 25.86% / 回撤 -22.4% / 夏普 1.03 / Calmar 1.16,
> 全面优于现状全押周五的 23.08% / -20.6% / 0.93 / 1.12, 且总交易金额不增加)
> 用户拍板: 2026-09-16「出项目计划书」

## 一、目标与边界

**做什么**: ETF 轮动池从「一份资金、统一周五信号日」改为「N 份资金 (默认 3 份)、
各份独立按各自信号日 (周三/周四/周五) 跑同一套 20 日动量择腿 + 日频 15% 移动止损」。

**不做什么 (边界)**:
- 不改择腿规则本身 (动量窗口 20、两腿皆负→黄金、止损 15% 全部照旧, 三份共用参数);
- 不上「双负保险丝」(回测已被错峰全面压制, 2026-09-16 研究报告 §一.4);
- 不动股票池/auto_buy/regime_filter/影子三态;
- 不改取数降级链 (QMT→TDX→腾讯)——但见 §九 已知问题 O1 (TDX 级前复权口径, 另案处理);
- 不加「双负保险丝」之类的每日择腿逻辑 (保持各份纯周频, 与回测 D 口径一致)。

**铁律红线**: QMT 是持仓唯一真相 (份内簿记漂移只告警不改账); 交易状态唯一写者 =
消费者线程 (份簿记也只能在消费者线程写); 回测与实盘同一份规则 (单一代码路径,
N=1 即现状退化, 不写第二份实现); 模型B 比例是上限不是目标 (每份独立适用)。

## 二、核心设计决策 (D1~D8)

### D1 单一代码路径: N 份 = 通用实现, 现状 = N=1 退化
配置 `signal_day` 由单字符串扩为「字符串或字符串列表」: `'friday'` = 1 份 (现状),
`[wednesday, thursday, friday]` = 3 份。代码里只有「按份循环」一种实现,
不存在「单份旧逻辑 + 多份新逻辑」两条路径 (如无必要勿增实体; 防两份规则漂移)。
**N=1 的「零行为变化」准确含义** (第二轮审阅修订): 除 D6/D7 两处**有意的安全修复**
(冷启动有持仓时止损照跑 / 落库注入实例状态) 外, 交易决策行为与现状一致 ——
Phase 1/2 的 parity 验收同此口径, 不写「完全一致」免得验收扯皮。

### D2 份内虚拟持仓簿记 (rotation_lots 表) —— 本改造的心脏
QMT 里同一 ETF 代码只有一笔合并持仓, 分不清哪股是哪份的。新增表按份记虚拟持仓:

```sql
CREATE TABLE IF NOT EXISTS rotation_lots (
    tranche    INTEGER NOT NULL,        -- 份序号 0..N-1 (顺序 = signal_day 列表顺序)
    code       TEXT NOT NULL,           -- 持仓代码 (限轮动池 4 代码)
    qty        INTEGER NOT NULL,        -- 该份虚拟持有量 (份; 碎股归属见 D4)
    entry_high REAL NOT NULL DEFAULT 0, -- 该份该腿的持仓期最高价 (每日运行时点实时价推高)
    updated_ts REAL NOT NULL,
    PRIMARY KEY (tranche, code)
);
```

- 只有 rotation 的消费者线程路径写本表 (唯一写者铁律);
- 每交易日与 QMT 对账: 按代码 Σ各份 qty vs QMT volume, 不一致 → audit 告警,
  **绝不自动改账** (铁律 1); 漂移期间卖出量以 `min(份内 qty, 剩余 can_use)` 兜底防废单;
- entry_high 随表持久化 —— 天然免疫 9-10 事故那类「单条信号 blob 被覆盖 → 全系统失忆」
  (状态从单条 JSON 升级为结构化表, 见 D7)。

### D3 统一执行 pass: 一次运行、算三遍、下一遍单
每日 `execute_time` (不变, 默认 14:54) 触发一次运行, 顺序:
1. **信号 (工作线程)**: 逐份判定「今天是否该份的信号日」(各自 anchor 复用
   `_is_signal_day`); 是 → 拉两腿收盘算动量 (取数结果三份共享, 同一天只拉一次);
2. **执行 (消费者线程, 现行 `_execute` 改造)**:
   a. 读 QMT 资产/持仓 + 行情 + rotation_lots。
      **持仓与止损的判定对象从「QMT 账户级持仓」改为「lots 份内持仓」**
      (QMT 账户级持仓只剩两个用途: 对账告警 + can_use 可用量) —— 现状
      `_execute` 的止损 held 是从账户级查的 ([trade/rotation.py:485], [trade/rotation.py:488] 的 len(held)==1),
      多份下必须按份内 lots 判, 否则两份同持一码会互相干扰 (第二轮审阅修订);
   b. 逐份做日频移动止损 (止损优先, 口径同现状: 实时价 vs 份内 entry_high);
   c. 逐份定目标 (信号日择腿 / 止损→黄金 / 否则维持);
   d. **卖**: 某份对某代码目标为 0 → 卖该份的 qty (逐份独立卖单, 各自过风控);
      目标腿超配绝不主动削 (模型B 逐份适用)。**全清时允许卖非整手碎股**
      (沿用现状 `_sell_to` 语义, 碎股来源见 D4 迁移归属)。
      选「分单」不选「并单」的第二个理由 (第一是免回填复杂度): 成交回报按 order_id
      归属, 份簿记扣减无歧义; 并单遇部分成交时回填归属要靠比例分摊, 易错;
   e. 等卖单回款 → 重读持仓/现金;
   f. **买**: 逐份按「份预算帽 = etf_ratio×总资产/N − 份内市值」与自由现金的小者补目标腿;
      份内市值口径走 `pool_money.position_value` 单一真相源 (最新价优先, 无价回退成本);
      目标为避险篮子且配了 hedge_etf2 时, 逐份按 hedge_ratio 拆两腿
      (复用 `momentum_target_values`, 无新逻辑);
      现金按份序号顺序分配 (确定性, 先到先得不偏袒);
   g. 写 rotation_lots (卖减买加、entry_high 更新)、逐份落 rotation_tranche_state、
      逐份写 rotation_summary 审计 (人话带「第几份/信号日」)。
3. `clear_external_sells()` 每次运行**只在开头调一次** (现状每次调仓调一次;
   若按份各调一次会把前一份的在途卖单登记抹掉, 对账降级网出盲区)。
4. 影子三态 `_shadow_tick` ([trade/rotation.py:296], [trade/rotation.py:323-345]) 照旧每日落盘, 与份数无关
   (它只用 cyb_etf 单腿, 不交易)。

### D4 启动日迁移 (从单份到三份的唯一一次初始化)
`rotation_lots` 为空且**未打过「已初始化」标志**且 QMT 有轮动池持仓时触发
(boot 一次性, 写审计; 标志存 store —— 第二轮审阅修订: 防 lots 表被误删/损坏后
重启把运行中的真实份归属重新均分、entry_high 被重置):
- 现有持仓按代码**按手 (100 份) 轮转分发**给三份 (第 0,1,2,0,1,2… 手依次归属):
  ≥300 份时自然近似三等分; <300 份时也能分匀 (如 250 份 → 100/100/50),
  不接受「整手向下除三」那种小持仓全堆尾部的分法;
  **不足一手的零头碎股全部归入最后一份** (该份将来「全清」时按 D3d 允许卖非整手),
  不留「无份归属」的持仓 (否则对账天天告警且无人认领);
- entry_high: 旧 `rotation_state` 里同代码有值则继承 (保住现有止损保护);
  继承失败 → **取近 20 交易日最高收盘** (走取数降级链), 再失败才退到迁移日收盘。
  理由: 止损基准宁紧勿松 —— 直接用迁移日收盘会抹掉「已从高点跌了一截」的记忆,
  等于偷偷放宽止损线 (fail-safe 方向反了);
- 无持仓 → 三份空仓起步, 各自由现金在自己的信号日建仓;
- 迁移结果逐份写审计, 页面可查; 完成即打「已初始化」标志。
回滚: 配置改回单 `'friday'` 并**清 rotation_lots + 清「已初始化」标志** →
下次启动按 N=1 重新初始化 (全部持仓归第 0 份), 行为回到现状。

### D5 状态持久化: rotation_tranche_state 取代单行 rotation_state
新表 `(tranche INTEGER PRIMARY KEY, signal_json TEXT, updated_ts REAL)`,
逐份存最近信号 (UI 回看 + 重启恢复「该份算没算过信号」)。旧 `rotation_state`
表停写保留 (供迁移读取 entry_high, 见 D4); 恢复逻辑改为「读 N 行 + rotation_lots」。

职责划分要如实 (第一轮审阅修订): **持仓与止损基准以 rotation_lots 为准**;
但「该份是否已算过首个信号」(has_target 语义) 只能从 tranche_state 派生
(空仓起步阶段 lots 全空, 分不清「没算过」与「算了该持有黄金/未成交」) ——
所以 tranche_state **仍然驱动交易**, 并非纯展示。其一行丢失的最坏后果 =
该份当周内不动作、等下个信号日自愈 (fail-safe 方向, 可接受)。
[trade/store.py:124] 旧注释「不驱动交易」名不副实的问题随之**部分**根治
(止损/持仓类状态挪进结构化表, 不再被单条 blob 覆盖全军覆没)。

### D6 信号日/冷启动语义微调 (顺带修掉「失忆停摆」类)
- 某份首个信号未算过但已有持仓 (迁移而来) → 每日止损检查照常跑 (守得住),
  只是不择腿 —— 修掉现状「_has_target=False → 连止损都不查」的停摆漏洞
  (2026-09-15 实锤: 当天 14:54 `rotation_skip 首个周频信号未算`, 止损检查一并罢工);
- 某份无持仓且信号未算 → 等信号日 (同现状语义)。

### D7 Phase 0 先行: signal_only 状态覆盖 bug 修复 (不等大改造)
现状 `on_signals` 的 finally 无条件 `save(self._last)` ([trade/rotation.py:271-276]),
跳过执行的路径 (盘后手动触发被「非连续竞价」拦下、非交易日、首信号未算) 会把
不含 `pending_target/entry_high` 的信号盖到好状态上 (9-10 事故)。

修法 (第一轮审阅修订, 比「从上一条继承」更直接): **实例内存里的
`_pending_target`/`_entry_high` 本来就是真相, 落库前统一注入** ——
`on_signals` 在 save 前对 signal dict 强制写入
`entry_high=dict(self._entry_high)`、`pending_target=self._pending_target`、
并新增显式 `has_target=self._has_target` 键; 这样任何路径 (正常执行/跳过/盘后)
落库都带最新实例状态, 不存在「忘了写键」的路径。
配套: `__init__` 恢复判定从 `"pending_target" in sig` 改为
`sig.get("has_target", "pending_target" in sig)` (兼容旧记录, 否则注入后
该键恒存在、冷启动「等首信号」语义被破坏)。注意正常执行后
`pending_target=None` (避险) 是「键存在值为 None」, 恢复语义保持不变。
配回归测试。此修复独立于三份改造, 先上线先止血。

## 三、配置变更 (trade/config.py)

```yaml
rotation:
  signal_day: [wednesday, thursday, friday]   # 列表 = N 份错峰; 单字符串 = 1 份 (现状)
```

- `_coerce_rotation` ([trade/config.py:470-552]): signal_day 接受 str | list[str];
  列表 1~5 项、逐项 ∈ {monday..friday}、不允许重复; **dataclass 字段类型相应改为
  `tuple[str, ...]`** (str 输入在 coerce 时归一化为单元素 tuple; 冻结 dataclass
  用 tuple 不用 list, 防可变默认值与 str/list 混用漂移 —— 第二轮审阅修订),
  所有读 `cfg.signal_day` 的消费点统一按序列处理 (D1 单一代码路径);
- 其余字段 (etf_ratio/momentum_window/trailing_stop_pct/execute_time/各 ETF 代码) 不变,
  **N 份共用** (与回测 D 同口径);
- `to_dict` ([trade/config.py:726-737]) 输出列表形态; 设置面板 signal_day 输入改多选框
  (或逗号分隔输入), 保存走同一 `_coerce_rotation` 校验;
- 默认配置仍 `'friday'` —— 未显式改配置 = 零行为变化 (fail-safe 默认)。

## 六、回测-实盘口径对照

回测 D 与本设计的对应: 份独立择腿=D3c / 份独立止损=D3b / T 收盘≈实盘 14:54 实时价
(已知 6 分钟级口径差, 研究报告 §六.1) / 份间不再平衡=D3f 现金顺序分配。
**口径差一 (第二轮审阅补充)**: 回测里三份的现金各自独立 (一份的卖出回款另一份用不到),
实盘是共享账户现金 (回款实时可用, 按份序号顺序竞争) —— 实盘资金利用只会更灵活,
该口径差方向安全 (实盘不劣于回测)。
**口径差二 (有意)**: 回测费用按万 1/边, 实盘逐份独立卖单若券商有最低佣金,
N 份同卖一码会多交 (D3d 选择不并单的理由: 并单要按比例回填成交, 部分成交时
归属复杂; 三只 ETF 流动性好、佣金万 1 通常无最低消费 —— **上线前需人工核对
开户券商 ETF 佣金有无最低 5 元/笔**, 有则改并单)。

## 七、风险与对策

| 风险 | 对策 |
