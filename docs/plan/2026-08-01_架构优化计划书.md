## 三、批次计划

### 批次 1 · 正确性收尾 (A 层, 估 1 天)
**目标**: 补上实盘保护网剩余的洞, 全部在 trade/ 内, 不改架构。

| 任务 | 改动 | 验收 |
|---|---|---|
| A1 `_quotes` 日期戳 | `self._quotes[code]` 存 `{..., date}` (tick 本地日期); `on_quote` 跨日时重置 high/prev_close 再累计; `_prev_close` 读缓存先校验 date==今日, 过期强制 `query_quotes` | 新增: 跨日 high 不混入/e2e day2 预埋用当日昨收; 全量绿 |
| A2 队列丢关键事件 | EventEngine put 时 tick 可驱逐 (满时丢最老 tick 腾位), 非 tick 事件永不丢 | 新增: 灌满 tick 后 put reconcile 必入队; 0731 场景回放测试 |
| A3 save_trade 自愈 | reconciler 补记路径: book 幂等命中但 trades 表查无此行时重试 save (查询先行, 不依赖异常) | 新增: kill 首次 save 后 sync_reports 自愈测试 |
| A4 update_order_filled 终态守卫 | SQL 加 `WHERE status NOT IN (53,54,56,57)` 或 CASE 保持终态 | 新增: 53 终态后补记不回退测试 |
| A7 ack 阈值 | `_CANCEL_ACK_POLL` 窗口 2s→5s (实测分布 87% 超 2s), 或分"受理慢/未受理"两级 | 告警噪声下降, 全量绿 |

**风险**: 低-中。A1 改变跨日行为是**回归设计意图** (注释自称"当日最高"), e2e day2 用例必须同时加。
**顺序说明**: A2/A3/A4 互不依赖; A1 独立。一天内可完成。

### 批次 2 · 缓存原语 + .tmp 竞态修复 (B 层, 估半天)
**目标**: 抽 `utils/parquet_cache.py` (~80 行): `blake2b_key` / `tmp_path_for` (pid+uuid) / `atomic_replace` (Windows 退避) / `prune_lru` / `cache_root` 注册表; 四个缓存模块接入, 三个 selection 缓存顺带获得 pid+uuid 修复 (B1)。

**关键决策**:
- 放在 `utils/` 而非 `selection/` —— matrix_cache (backtest/) 也用, 跨层依赖方向应为 底层←上层。
- conftest 改为一行注册表覆盖 (`pcu.set_root(name, tmp/name)`), 替代 4 处 monkeypatch —— 根治 07-27 缓存投毒类事件。

**验收**: 全量绿 + 新增并发写测试 (两线程同写一 key 不抛 FileNotFoundError) + conftest 不再 import 四个缓存模块。

### 批次 3 · 回测一致性 (A5/A6/C2, 估 1 天)
**目标**: 重建回归保护网 + 消双入口漂移。

| 任务 | 改动 | 验收 |

| A5 parity 快照基线 | 按 docs/architecture/loop.md §7.7: 固定 2-3 个策略 × 固定区间 × 固定种子数据, 产出 equity/trades 快照入仓 (json), 测试逐字段对比 | 故意改一处策略逻辑 → 测试必报警 (阴性验证) |

### 批次 4 · 组合根瘦身 (C1, 估 1 天)

**关键决策** (采自 html Card1, 本会话复核同意):
- 事件缝已经天然存在 (EVENT_COMMAND "auto_buy" / EVENT_SIGNALS), 组合根只留两行接线。

## 四、不做清单 (范围纪律)

1. **不动 trade/ 的组合根 + 依赖注入架构** —— 它是全项目最好的部分, 只做瘦身不做改造。
2. **不重写缓存/存储引擎** —— 不换 DuckDB/不引入新依赖, parquet+SQLite WAL 够用 (计划书 §5.4 反过度设计传统)。
3. **不动回测成交价口径** —— 信号日 T 收盘成交是明示的设计决策; LiveBiasEstimate 接线属独立评估, 不在本计划。
4. **不改 git 历史** —— 历史中的账号/webhook 痕迹走轮换+运维决策, 不 force-push。
5. **不做前端框架迁移** —— 现有 JS 组织 (module + 全局混用) 记录为 P3, 不在本计划。
6. **每批次独立可合** —— 任何一批做完系统处于更好且完整的状态, 不产生"必须下一批才闭环"的半成品。
