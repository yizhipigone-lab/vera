## 0. 结论先行

1. **不新建对账系统**。现有 reconciler（对账器）只调 `gateway.query_*` 通用接口，通道无关，同花顺通道插上即用；字段级已逐行核对兼容（成交编号/合同编号/时间戳三个认账关键字段网关均已供给）。
2. **不做新页签**。通道是水管不是水龙头；用户可见增量收进现有交易页状态条（通道徽章 + 武装灯 + 探针时间 + 断线灯），切换操作用模态向导承载。
3. **武装（armed）采用"意图持久 + 探针生效"双层态**：配置记住意图（重启免重新确认），但武装实际生效的唯一钥匙是探针通过；探针不过自动降级为"武装悬空"（黄灯），自动重探、过则自动生效。
4. **急停保持现状**（用户拍板 2026-09-07）：三重态拒新单，不加"自动全撤"档。
5. **盘中轮询兼任探针**：不单独设活性探针节奏；sync_reports 轮询成功即存活证据，连续 3 轮失败判断线。非交易时段不轮询（防验证码、省无谓 GUI 操作）。
6. 全案落地拆 T1~T8 八步，每步带验收标准，全程不破坏现有 QMT 链路（回滚 = 配置切回 `qmt`）。

## 1. 背景与目标

### 1.1 背景

VERA 当前实盘唯一通道是 QMT（`RealGateway`，走 xtquant/miniQMT 终端）。同花顺 GUI 网关（`ThsGuiGateway`，走 easytrader 模拟键鼠操作同花顺下单客户端）已于 2026-09-06 完成开发与只读实测，代码入库但未接线——组合根 `trade_main.py:274` 仍是 `FakeGateway if fake else RealGateway` 二选一。

### 1.2 目标

1. 让"通道选择"成为配置项 + 前端可操作项，支持 QMT / 同花顺GUI / 模拟 三选一。
2. 切换过程有仪式（探针 → 打字确认 → 武装），摩擦与危险成正比；解除武装零摩擦。
3. 同花顺通道下，对账、急停、风控、监控四套保命体系语义不变、行为可预期。
4. 全程保留 QMT 通道能力，可随时切回。

### 1.3 非目标（明确不做）

- 不代登录同花顺客户端（账号密码不进系统、不落盘；登录永远人工完成）。
- 不做多通道并行/主备路由（当前无此场景；若未来出现再单独立项，届时才配独立页签）。
- 不做"急停自动全撤在途"（用户 2026-09-07 拍板保持现状）。
- 不做只读默认态、不做限额武装档（用户 2026-09-07 拍板：系统本身每日实盘，无需只读过渡；限额无要求）。
- 不新建对账系统、不改 Executor.place_order 唯一下单口。

## 2. 术语白话表

| 术语 | 大白话解释 |
|---|---|
| 通道（channel/gateway） | 下单指令走出 VERA 的"路"。QMT 是一条路，同花顺客户端是另一条路 |
| 武装（armed） | 真钱开火许可。未武装 = 保险锁着，系统拒下任何真实委托 |
| 武装悬空 | 用户想要武装（意图在），但探针没过，保险暂时合着——"弹药已就位，保险自动合上，路况一好自动打开" |
| 探针（probe） | 上路前验车：连上客户端，读资金/持仓/委托并和客户端显示核对，全对才放行 |
| 对账（reconcile） | 会计查账：VERA 本地账本 vs 券商实际持仓/委托/成交，三方互比 |
| sync_reports | 增量同步：定时把券商侧的成交/委托状态拉回本地补记，QMT 时代是回调推送的兜底网，同花顺时代升级为唯一主力 |
| 急停（kill switch） | 总电闸：内存+DB+文件三重态，任一生效全面拒新单，只许人工解除 |
| 占位号 | 同花顺下单没拿到合同编号时，本地发的临时编号（`THS{mmdd}-{seq}`），账不会错但需事后回填认亲 |
| UIPI | Windows 权限隔离墙：非管理员进程读得到管理员窗口、发不了操作消息——所以操作同花顺客户端需要同级或更高权限 |
| 验证码弹窗 | 同花顺客户端的反机器人机制：GUI 操作太频繁会弹验证码，决定轮询不能太密 |

## 4. 总体架构

### 4.1 通道选择与生效链路

```
配置意图 (channel, ths_armed)          运行时状态
        │                                    │
        ▼                                    ▼
┌─────────────────┐   启动/切换    ┌──────────────────┐
│ 组合根三选一      │ ───────────▶ │ 探针 (完整版)      │
│ qmt/ths/fake    │              │ 连接+三查+行情源    │
└─────────────────┘              └────────┬─────────┘
                                          │
                          通过 ◀───────────┼───────────▶ 失败
                          │               │               │
                          ▼               │               ▼
                  ┌───────────────┐       │       ┌───────────────┐
                  │ 武装生效 (绿灯) │       │       │ 武装悬空 (黄灯) │
                  └───────┬───────┘       │       └───────┬───────┘
                          │               │               │ 每60s重探
            轮询连续3轮失败 │               │               │ 过则自动生效
                          ▼               │               │
                  ┌───────────────┐       │               │
                  │ 断线 (红灯+告警)│ ──────┴───────────────┘
                  └───────────────┘   恢复 = 轮询/重探通过，自动回绿
```

要点：**armed 生效 ⇔ 意图为真 且 最近一次探针通过**。意图存配置（重启免重新打字确认）；生效状态是运行时的，探针是唯一钥匙，无任何跳过后门。

### 4.2 探针节奏三档

| 场景 | 节奏 | 理由 |
|---|---|---|
| 完整探针（连接+资金+持仓+委托+行情源） | 事件触发：启动、切通道、点"启用实盘" | 上路前验车，跑一次即可 |
| 武装悬空重探 | 每 60 秒（可配 `ths_probe_retry_sec`） | 客户端未登录时查询秒级失败，负担可忽略；登录好后最多 1 分钟自愈 |
| 盘中活性探针 | **不单独设，由 sync_reports 轮询兼任**：交易时段 60~180 秒一轮（复用 `sync_interval_sec`，建议同花顺通道设 60），连续 3 轮失败判断线 | 一次查询干两份活，不额外敲客户端的门；失败退避不硬戳（客户端弹窗卡死时越戳越糟） |
| 非交易时段 | 不轮询——**现有行为，零改动继承**：`_on_sync_reports` 消费者侧已做时段过滤，仅 auction/continuous/lunch 三个时段执行（`trade_main.py:824-833`），其余时段事件直接丢弃 | 盘后数据静态，轮询纯白敲；降低验证码触发面 |

## 5. 详细设计

### 5.1 配置层（`trade/config.py` TradeConfig 增量）

| 新字段 | 类型/默认 | 说明 |
|---|---|---|
| `channel` | `str = "qmt"` | `"qmt" / "ths" / "fake"`。兼容：`fake_sdk=True` 时视同 `"fake"`（旧配置行为不变） |
| `ths_exe_path` | `str = r"D:\thsstio\xiadan.exe"` | 同花顺下单客户端路径 |
| `ths_title_re` | `str = ".*网上股票交易系统.*"` | 窗口标题正则（换客户端版本只改这里） |
| `ths_armed` | `bool = False` | **武装意图**（持久）；实际生效还需探针通过 |
| `ths_probe_retry_sec` | `int = 60` | 悬空态重探间隔 |
| `ths_disconnect_rounds` | `int = 3` | 连续失败几轮判断线 |

约束：这些字段进入 `_FIELD_TYPES`（`trade/config.py:212+`），随 `PUT /api/trade/config` 深合并语义自然获得热更新能力。

### 5.2 组合根（`trade_main.py:274` 改造）

```python
# 现状
gw_cls = FakeGateway if fake else RealGateway
# 目标（伪代码）
gw_cls = {"qmt": RealGateway, "ths": ThsGuiGateway, "fake": FakeGateway}[cfg.channel]
gw_kwargs = 按通道组装 (ths: exe_path/title_re/armed=False 启动态, 运行时由通道管理器按探针结果置位)
```

启动预检（`:282-288`）扩展：`channel=ths` 时校验 `ths_exe_path` 存在、`ths_title_re` 非空，缺失给能看懂的报错。

### 5.3 通道运行时管理器（新模块 `trade/channel_manager.py`）

职责单一：持有"意图 vs 生效"双层态，驱动探针与重探，向事件总线发通道事件。

- 状态：`armed_intent`（读配置）、`armed_effective`、`last_probe`（ts/ok/失败原因）、`consecutive_failures`
- 方法：`full_probe()`（完整探针）、`on_poll_result(ok)`（轮询结果喂入，兼任活性探针）、`arm(confirm_text)`、`disarm()`、`switch(channel)`
- 铁律：`armed_effective = armed_intent and last_probe.ok`；网关构造仍 `armed=False`，管理器在探针通过后调用网关武装置位——**探针不过，谁也别想让 order() 放行**（网关层 `:197-200` 的 raise 是最后一道物理防线）
- 断线事件：连续 `ths_disconnect_rounds` 轮失败 → 发 `EVENT_CONNECTION_LOST`（复用现有断线语义与告警链路，不新造）

### 5.4 探针内容（完整版）

1. 连接：attach 已登录客户端（标题正则优先，实测依据见 `gateway_ths.py:167-171` 注释）
2. 三查：`query_asset` / `query_positions` / `query_orders` 全部成功返回
3. 数值合理性：总资产 = 可用+冻结+市值 重算自洽（`:247-258` 已实现）
4. **行情源检查**：同花顺通道无行情腿（`query_quotes` 返回空 fail-closed 是设计如此），探针必须验证替代行情源可用，否则不允许武装——monitor 的止盈止损没行情就是瞎子
5. 结果落 `audit` 留痕，供前端展示"上次探针：时间+结果+失败原因"

### 5.5 API 设计（全部遵循 `submit_command` 命令队列纪律，`api.py:325`）

| 端点 | 方法 | 语义 |
|---|---|---|
| `/api/trade/status` | GET（既有，扩字段） | 新增 `channel` / `armed_intent` / `armed_effective` / `last_probe`（ts/ok/失败原因）/ `channel_connected` 五字段——前端轮询零新增负担，状态条四件套全部由此驱动 |
| `/api/trade/channel` | GET（新增） | 静态信息：可用通道列表、各通道配置摘要、当前通道——配合 status 使用 |
| `/api/trade/channel/probe` | POST | 立即跑一次完整探针（只读，盘中允许） |
| `/api/trade/channel/switch` | POST `{channel}` | 切换守卫：**盘中（continuous/auction）403**（仿 `reload_view` 时段门禁 `api.py:153-159`）；**有在途委托拒绝**（先撤或等成交）；切换即解除武装（换枪重验保险）；切换后必须重新探针+确认 |
| `/api/trade/channel/arm` | POST `{confirm: "确认实盘"}` | 打字确认；前置：通道=ths 且探针 N 秒内刚通过；确认串不匹配 422 |
| `/api/trade/channel/disarm` | POST | **零摩擦**，立即解除（从危险回安全永远一键，类比紧急制动阀一拉就停） |

### 5.6 前端设计（交易页状态条增量，**不开新页签**）

现状锚点：`web/index.html:387-395` 已有 9 页签；`trade.js:95` 已有 `tdConn` 连接徽章；`trade.js:103-110` 已有急停按钮及二次确认文案。

增量四件套，全部加在交易页状态条：

1. **通道徽章**：`QMT` / `同花顺GUI` / `模拟`——三个通道速度/可靠性/口径差异大，用户必须一眼知道走的是哪条路（尤其同花顺秒级慢，不知情会以为系统卡死）
2. **武装灯**：绿=武装生效 / 黄=武装悬空（意图在、探针未过，附原因） / 灰=未武装
3. **上次探针**：时间 + 结果，过期变灰
4. **断线灯**：复用 `tdConn` 断连语义（`trade.js:136` 已有）

切换向导为模态弹窗（三步：选通道 → 自动跑探针 → 打字确认），武装按钮黄灯时也承载"重试探针"入口。解除武装=状态条上一键，confirm 文案沿用急停按钮的二次确认风格（`trade.js:686-692` 范式）。

### 5.7 对账适配（不重建，补一处认账逻辑）

**天然继承（零改动）**：三方对账主流程、UNKNOWN/CRITICAL 语义、CRITICAL→急停、手工单认领（traded_id 判重 + order_id 归因 + 跨日守卫——同花顺网关字段已核对齐备，§3.2）、成本 book 优先、reconcile_log 落表与 `/api/trade/reconciles` 展示。

**唯一新逻辑——占位号回填认亲**：
- 场景：下单时 easytrader 弹窗未返回合同编号，网关发本地占位号 `THS{mmdd}-{seq}`（`gateway_ths.py:221-228`）。下一轮 `_sync_orders`/`_adopt_manual_trades` 按 order_id 归因时查无此号，系统的单会被误标"手工"
- 设计：`_sync_orders` 归因增加一路回填匹配——本地占位号订单按（代码 + 方向 + 委托价 + 数量 + 时间窗 ±N 分钟）在券商当日委托中认亲；**唯一命中**→ 回填合同编号替换占位号，audit 记 `ths_entrust_backfill`；**多笔歧义**→ 不猜，记 WARN 交人工（同价同码重复委托是已知限制，界面声明）
- 性质：自愈逻辑，账的正确性不依赖它（数量金额恒以券商硬事实为准），它只修策略归属标签

**节奏调整**：同花顺通道无推送，`sync_reports` 从兜底网升级为唯一主力。机制已在跑（`trade_main.py:164-166` 按 `sync_interval_sec` 发事件，`:826-832` 消费者侧时段过滤——盘前/盘后天然停摆，**零改动继承**），只需：该通道下建议 `sync_interval_sec=60`（QMT 默认 180）。**代价明示**：成交发现从秒级（推送）变分钟级（轮询），盘中接力（卖出回款再买入）慢半拍。

**断线检测路径切换（审计第 1 轮补强）**：QMT 时代的断线主触发源是**行情心跳**——`_on_scan` 里 `monitor.has_tick()` 守卫 + 连续 N 次扫描不健康才判活断（`trade_main.py:798-809`，P0-③ 实测结论：on_disconnected 回调不可靠）。同花顺通道无行情腿、无 tick，该守卫天然不成立——**轮询失败计数不是补充，而是该通道下唯一的断线检测路径**，§5.3 的哨兵因此是必选项而非可选项。

**验证码节流**：轮询间隔不低于 60 秒、失败退避不硬戳、非交易时段停摆——三条都是对 easytrader 源码中验证码机制（§3.4）的直接回应。

### 5.8 行情腿

- 同花顺通道 `query_quotes` 返回 `{}`（fail-closed，monitor 视陈旧）是刻意设计
- 切换同花顺通道的**前置条件**：替代行情源（akshare/tushare 等）可用，纳入探针检查项（§5.4 第 4 条）
- `quote_stale_sec=60`（`config.py:204`）的陈旧判活在无行情源时会令 monitor 不健康——探针挡在前面，不让系统进入这种状态

## 6. 安全设计

1. **探针是武装的唯一钥匙**：无后门、无"跳过探针强行武装"选项，向导里也不留。
2. **网关层物理防线**：`armed=False` 时 `order()` 直接 raise（`gateway_ths.py:197-200`）——即使上层管理器出 bug，下单也打不穿。
3. **命令队列单写者**：所有变更（切换/武装/解除/配置）走 `submit_command`（`api.py:325` 纪律），API 层不做任何交易动作。
4. **盘中不动结构**：切换通道仿 `reload_view` 时段门禁，continuous/auction 一律 403。
5. **解除永远零摩擦**：disarm 一键即达；武装必须过仪式。摩擦方向与危险方向一致。
6. **急停语义不变**（用户拍板）：三重态拒新单（`risk.py:33-67`），通道上游，换通道零影响。
7. **权限部署约束（UIPI）**：操作同花顺客户端要求 VERA 进程权限不低于客户端（2026-09-06 实测：非管理员可只读、写操作被拒）。部署方案二选一：计划任务以最高权限托管（一次性 UAC，之后静默），或客户端与 VERA 均非管理员运行。写入部署文档，不进运行时逻辑。
8. **登录永远人工**：系统不接触账号密码，不落盘凭证。

## 9. 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 同花顺改版致控件 ID/列名失效 | 中 | 探针启动即拦；`ths_title_re` 等配置化；失败现象是"探针不过"而非"下错单"——失败方向安全 |
