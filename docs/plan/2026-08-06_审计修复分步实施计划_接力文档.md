## 4. 深/浅模块评价（背景知识，指导第 1.2 与第 4 批的修法）

**结论：核心交易链路是深模块正面教材，配置链路是浅模块反面教材——HIGH #5 就是浅层叠孵出来的。**

（深模块 = 小接口藏大量行为，调用方学一点用很多；浅模块 = 接口和实现一样大，只是搬运。）

### 深模块（保持）

- `trade/risk.py` 全场最深：`check()` 一个 yes/no 后面藏内存/DB/文件三重态 + 异常 fail-safe。删掉它拒单逻辑会散落到每个下单点。
- `trade/store.py`：小接口藏 SQLite 幂等 + traded_id 判重 + JSONL 双写 + 锁。HIGH #1 能 ~5 行修，正因为写路径只此一个入口。
- `trade/gateway.py`：xtquant 重连/超时/查询包装在小接口后。
- selection 缓存族：SCHEMA bump + atomic replace + 投毒防线藏在 get/put 后。扣分项：`signal_day_cache.py:198` "今天永不缓存"漏给调用方——含今日区间每次白付 ~16s。

### 浅模块（治理方向：不做大重构，手伸进去时顺手收敛）

- **配置链路是最大浅模块集群**：一个 `cost_stop=-0.12` 跳 7 层（config.js:108,134 → config_mapper.py:48,138 → config_loader.py（纯透传）→ stop_config.py:47,90 → config.js:171 回显）。删除测试：删掉 config_loader，复杂度不消失也不重现——纯搬运工。
- 代价实证：ladder 默认值 `"6:30,15:30"` 一路搬运，**没有任何一层拥有这个值的语义**，6.0=600% 静默潜伏。
- `core/formula_runner.py:66,203` `last_batch_errors` 类属性：内部状态漏到接口，调用方被迫知道"并发会串"。
- `core/dividend_type.py:69,91` 静默兜底：未知值悄悄返回 `"front"`，接口没把兜底写进承诺。
- **治理动作（并入 1.2）**：把值的语义拥有者收敛到 stop_config 一处（解析归一化 + validate 下沉 /api/run），三层浅模块压成一个深模块入口。
