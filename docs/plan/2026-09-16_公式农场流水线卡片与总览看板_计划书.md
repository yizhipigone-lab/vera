# 2026-09-16 公式农场流水线卡片与总览看板 计划书

## 背景与目标

公式农场页面当前四张卡片各只有一行状态字（「上次 ✅ 时间」），信息量太低；历史工作成果（采集了多少、入库多少、复核过多少、哪些达标、成绩如何）散落在 `runs/`、`output/`、`reports/` 各处，页面上看不到全貌。

本计划做两件事：

1. **流水线卡片**：四张卡片连成 ①→②→③→④ 箭头流，每卡显示状态灯（🟢过/🔵跑/🔴败/⏹停/⚪未跑）+ 一句话成绩单；上一步无产物时下一步按钮置灰并提示（**方案 B：宽口径**，④ 只要求有入库产物，未过复核时显示提醒不锁死——2026-09-16 用户拍板）。
2. **总览看板**：页面顶部新增「农场总览」区——漏斗带（采集→入库→复核→粗扫→达标的全程转化）+ 达标榜（每条达标公式的成绩一览），让历史工作一目了然。

**已拍板决策（2026-09-16）**：置灰用方案 B（宽）；允许动 `farm_verify.py` / `farm_backtest.py` 两个闸门脚本（各加"跑完写成绩 json"的增量代码，不动判定逻辑）。

## 逐行复核勘误（2026-09-16 开工前核验，全部实读代码/真实文件确认）

1. **③就绪判据修正**：原文「存在有 ok 记录的 onboard.json」改为「**最新批次** onboard.json 有 ok 条目」——`farm_verify._latest_batch_formulas` 只认 mtime 最新的一份 onboard.json（复核范围=最新一批），判据写宽了会放出"点了也白点"的按钮。④不受此限（粗扫是跨批次补扫，"任意 ok"即可）。
2. **③md 兜底正则须容忍两种装饰**：真实历史报告 `data/formula_farm/reports/2026-09-11_定量复核_公式农场.md` 第 9 行原文为 `结论: 通过 2 · **未通过 0** · 无法判定(复核失败/未解析/零信号) 0`——"未通过"带 markdown 星号、"无法判定"带括号尾巴，正则不按纯数字写。
3. **④md 兜底行已核实真实存在**（同目录 `2026-09-11_粗扫报告_公式农场.md`）：第 9 行 `批次: 本批入库 20 条 · 本轮粗扫 20 条 · 余 0 条待扫 (本批已扫完)`、第 11 行 `本轮判定: 达标 0 · 未达标 14 · 样本不足 6 · 无有效组合 0`，与计划格式一致 ✓。
4. **采集量实数更正**：intake 目录 md 实数 **1235 条**（讨论中曾误用 1348——那是 data/formula_farm 全目录含产物的路径数，计划与看板一律以 intake 目录 md 数为准）。
5. 其余逐行核验**全部通过**：`check.json`/`onboard.json` 字段结构、`farm_rules.pick_best/verdict/describe` 签名、sweep CSV 列（annret/maxdd/trades/winrate/calmar/key/error）、`_onboard_index`/`_latest_check` 的"取最新/取最早"语义、`archive.json`/`verify.json`/`backtest_summary.json` 三个新文件名无撞名、status 响应直通（farm_api 零改动成立）、轮询 2 秒、报告文件名模式。

## 侦察结论（2026-09-16 实读代码确认，计划的事实基础）

| 数据 | 位置 | 格式 |
|---|---|---|
| ①检查产物 | `data/formula_farm/runs/<日期>/check.json` | `{date, intake, dup[], vetted[], excluded[]}` 三个数组数长度即是「可入库/重复/淘汰」 |
| ②入库账本 | `runs/<日期>/onboard.json`（同日多轮合并写） | `{date, items:[{gs,file,url,ok,msg}]}`；`farm_backtest._onboard_index()` 已有全库去重索引逻辑 |
| ③复核结论 | 只在报告 md 的「结论: 通过 X · 未通过 Y · 无法判定 Z」一行 | 需新增结构化 `verify.json`（本计划给 farm_verify 加） |
| ④粗扫结果 | 每公式 `output/gs_5m_sweep/<GS>/sweep_*.csv`（36 组明细）；报告 md 有本轮判定统计 | 判定/最优组合走 `core/farm_rules`（单一真相源，直接复用）；需新增 `backtest_summary.json` + 累计 `archive.json` |
| 终审收割总榜 | `data/formula_farm/winners/index.md` | **人工维护**（精调/样本外/终审层面，如 GS0607 终审可用池）——本看板**不重复建设**，只到"粗扫达标"层，页面给文字指路 |

**防漂移收口项（顺手做，铁律"同一条规则手写 N 份必然漂移"）**：

- `farm_onboard.main` 内联的 done_files 逻辑（已入库+编译失败跳过）与看板"剩余待入"是**同一条规则** → 抽成 `tools/formula_farm/common.py::load_done_files(runs_dir)`，两处共引；
- `farm_backtest._onboard_index()` 与看板"全库入库索引"同理 → 抽成 `tools/formula_farm/common.py::load_onboard_index(runs_dir)`，两处共引。

## 详细设计

### 一、闸门脚本增量（阶段 1）

**`farm_verify.py`**：`summarize()` 之后新增写 `runs/<日期>/verify.json`：

```json
{"date": "...", "cutoff": "...",
 "stats": {"total": N, "pass": X, "fail": Y, "unknown": Z},
 "formulas": {"GS0001": {"repaint_ok": true, "future_ok": false,
                         "concl": "未通过", "repaint_verdict": "...", "future_verdict": "..."}}}
```

抽小函数 `write_verify_json(path, merged, ctx)` 便于单测。

**`farm_backtest.py`**：报告写完后新增两个产物：

1. `runs/<日期>/backtest_summary.json`：`{date, batch_date, stats:{pass,fail,insufficient,invalid}, remaining, total, done}`——卡片④的成绩单；
2. `data/formula_farm/archive.json`（累计档案，达标榜的数据源）：**增量更新**——本轮扫过的公式按最新 sweep 结果重算最优组合与判定（走 `farm_rules.pick_best/verdict`）后并入；归档条目：

```json
{"GS0607": {"file": "...", "url": "...", "onboard_date": "...",
            "best": {"key": "...", "annret": 0.244, "maxdd": -0.034,
                     "calmar": 7.16, "winrate": 0.61, "trades": 58},
            "verdict": {"code": "pass", "label": "达标", "reason": "..."},
            "window": ["2024-09-11", "2026-09-16"], "updated_at": "..."}}
```

另加 `--rebuild-archive` 开关：全量重建（首次/怀疑档案漂移时用，耗时数十秒，打日志说明）。停牌（NO_SIGNALS）公式也入档，verdict 记「无有效组合」，达标榜归入折叠区。

### 二、后端汇总模块（阶段 2）

新建 `core/farm_summary.py`（纯函数，无全局状态，符合"计算下沉纯函数"规矩）：

- `gate_summaries(data_root) -> dict`：四张卡片各自的成绩单文本 + 就绪标志（`ready`/`hint`）：
  - ① 最新 `check.json` →「9月16日 · 新增可入库 X / 淘汰 Y / 重复 Z」；②就绪 = 存在任意 check.json；
  - ② 最新批次 `onboard.json` 数 ok/失败 + 全库累计入库数（`load_onboard_index`）+ 剩余待入（最新 check.json 的 vetted − `load_done_files`）；
  - ③ 最新 `verify.json` →「通过 X / 未通过 Y / 无法判定 Z」；无 json 时正则兜底抓最新复核 md 的结论行（容忍星号与括号，见勘误 2），再抓不到 →「暂无成绩单（跑一轮即生成）」；③就绪 = **最新批次** onboard.json 有 ok 条目（勘误 1）；
  - ④ 最新 `backtest_summary.json` →「达标 X / 未达标 Y / 样本不足 Z / 余 K 待补」；同样 md 正则兜底；④就绪 = 存在任意有 ok 记录的 onboard.json（方案 B，勘误 1），无 verify 产物时附 hint「本轮还没过定量复核」。
- `overview(data_root) -> dict`：
  - 漏斗五项（全部唯一键口径，诚实不虚报）：已采集（intake 目录 md 文件数）→ 已入库（onboard 索引唯一 GS 数）→ 已复核（所有 verify.json 并集数，含复核通过数）→ 粗扫有结果（archive 有 best 的条数）→ 达标（archive verdict=pass 数）；
  - 达标榜：archive 全量条目，按判定分三组——达标（绿）/ 样本不足（黄）/ 未达标+无有效组合（灰，默认折叠），组内按年化降序；
  - 淘汰原因 Top3（最新 check.json 的 excluded reasons 聚合）——「这批货主要死在哪儿」。
- 性能：status 轮询 2 秒一次，汇总读的都是小 json； onboard 索引/归档按 (路径, mtime) 做进程内缓存，没变不重读。

**接线**：`FarmRunner.status()` 响应加 `summary` 与 `overview` 两个键（复用现有 2 秒轮询，不加新接口不加新轮询）。`farm_api` 薄层零改动。

### 三、前端（阶段 3）

**流水线卡片**（改现有四卡，结构不动、加三件套）：

- 标题前状态灯 `<span class="farm-dot">`：🟢done / 🔵running（CSS 呼吸）/ 🔴failed / ⏹stopped / ⚪未跑；
- 状态行下加成绩单行（`farmSumCheck` 等四个 id），内容来自 `summary`；
- 卡片间加居中 ↓ 箭头连接（纯 CSS，`.farm-arrow`）；
- 按钮置灰：`summary[gate].ready === false` 时 `disabled` + `title` 悬停人话提示（「先跑① 检查增量」）；④ 有 hint 时卡片内显示一行小字。

**总览看板**（页面顶部，四卡之上，两个新卡片）：

1. **「农场总览」卡**：漏斗五条横向条形（纯 CSS div 宽度比例，不上 echarts——轻、快、主题色一致），每条带数量+白话标签：进货（已采集）→ 上架（已入库）→ 抽检（已复核·通过 X）→ 试穿有结果 → 达标。旁边小字：淘汰原因 Top3。
2. **「达标榜」卡**：达标组默认展开（绿），样本不足组默认展开（黄），未达标+无有效组合默认折叠（灰，点击展开）。列：GS 编号 / 公式名（来源文件）/ 最优组合 / 年化 / 卡玛 / 最大回撤 / 胜率 / 笔数 / 入库日期 / 来源（可点开的股旁网链接）。
3. 卡底两行小字：口径提醒（照抄 `farm_rules` 的轻仓提醒：300 万本金 + 单票 2 万，年化主要在排"出票多不多"）+ 终审指路（「精调/样本外/终审结果见人工收割总榜 `data/formula_farm/winners/index.md`」）。

**人性化细节**：

- 空态：一次都没跑过时显示「农场还没开张——点『① 检查增量』进第一批货」；
- 看板渲染做签名比对（JSON 串没变不重绘），防 2 秒轮询闪屏；
- 数字带单位/百分号，时间「9月16日 21:09」格式；颜色语义全页统一（绿过/黄不足/灰未达/蓝跑/红败）；
- **不动手机版 `/m`**（铁律：手机版功能独立维护，不自动跟随 PC）。
