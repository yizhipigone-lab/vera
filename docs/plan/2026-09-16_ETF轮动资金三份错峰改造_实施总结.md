## 二、第一轮自审 (代码级, 写完即审) — 6 处发现全部修复

| # | 发现 | 处置 |
|---|---|---|
| 1 | **废单误核销**: 卖单终态回查 `int(o.get("filled_qty") or 0) or qty` —— 废单 filled_qty=0 会被 `or qty` 当成全成交, 份簿记平白少一笔 (下次不再补卖, 与 QMT 永久漂移) | 改 explicit 判定: 只有 `filled_qty` 真值 >0 才减, 否则进在途台账 |
| 2 | **D6 维持可能误卖风险腿**: 「首信号未算有持仓」分支 `held[0]` 按 dict 序取首个 —— 换档残留 (黄金+风险腿同在) 时可能选中黄金 → 目标=避险 → 把好的风险腿卖掉 | 改 `held_risk` 优先 (与 `_maintain_target` 同口径) |
| 3 | 冷启动 `_last` 不恢复 → 重启后轮动卡显示「尚未运行」 (旧版从单行 blob 恢复 UI 回看) | `__init__` 从 tranche_state 重建 `_last` (只组装不回写) |
| 4 | skip 份 (首信号未算) 在执行 pass 里无任何审计痕迹 | 补逐份 `rotation_skip` 审计 |
| 5 | `_execute` 中途异常 → 内存 lots 已变但未落库, 重启回滚到旧簿记 | `on_signals` finally 统一 `_persist_lots()` |
| 6 | signal_only 跳过事件 note 兼容: 旧形态 note 内嵌在 signal dict 里 | note 三级回退 (顶层→内嵌→默认) |

验证: 修复后 49/49 绿; 其中 #1 是会造成真实簿记错误的 P0 级。

## 三、第二轮自审 (计划书 D1-D8 逐条对照) — 全对齐, 3 个实现期决策留痕

逐条核对计划书 D1~D8、§三配置、§八测试清单, 全部落地 (对照表略, 见计划书)。
三个**有意偏离/新增**, 如实记录:

| # | 决策 | 理由 |
|---|---|---|
| R2-a | 迁移时机: 计划书写「boot 一次性」, 实现为**首个执行 pass 开头** (lazy) | `__init__` 在接线期不宜调 gateway (QMT 未就绪); 首个执行 pass 必在任何信号执行之前, 时序安全性等价, 且天然拿到 quotes/qmt_pos |
| R2-b | Phase 0 (D7 修复) 未按计划在旧架构上独立先行, 并入重写一次交付 | 同会话连续作业, 旧架构上先修一遍再重写是双份工; D7 语义 (统一注入 + has_target 显式键 + 恢复兼容) 完整落在新架构, 回归测试照配 (test_skip_paths_preserve_state) |
| R2-c | **计划外新增机制: 在途卖单台账 `rotation_open_sells`** | 测试 test_swap_sell_filled_then_buy_next_run 暴露: 卖单隔夜才成交时, 份簿记不会自愈 (旧架构从 QMT 持仓派生天然自愈, 簿记制不行)。计划 D2「漂移只告警」盖不住**自己挂出去的单**——必须按 order_id 台账核销; 人工单仍不动簿记只告警, 铁律 1 不破 |

另: 测试期发现三个新测试断言被「维持补仓」买入侧干扰 (行为本身符合模型B, 非 bug) → 测试改 cash=0 隔离卖出侧语义。

## 四、第三轮自审 (上线/运维视角) — 首日推演 + 回滚 + 验收

1. **生产现状衔接**: 当前 `rotation_state` 是 9-15 的 note-only blob (无 entry_high) →
   迁移 entry_high 走「近 20 日最高收盘」回退 = 2.236 (513100, 9/7) —— 与现行止损基准
   恰好一致, 止损线 1.90 不变, 衔接平滑。
2. **首日行为推演** (收盘后部署 + 信号日配三份): 首个执行 pass 先把 ~24 万份 513100
   按手轮转成 ≈8万/8万/8万; 当天只有「当天是信号日的那份」会择腿 (双负 → 只切它那
   1/3 进黄金), 其余两份维持 + 止损检查 —— **错峰不是三份一起动**, 灰度首日预期
   最多 1/3 仓位变动。
3. **部署窗口**: 必须非连续竞价时段 (收盘后) 改代码重启; 面板改多选后**需再重启**
   (份数/锚定热更只告警重建, 计划书 §七口径)。
4. **回滚**: 面板改回单选 → 清 `rotation_lots` + 清 `lots_initialized` 标志 → 重启
   → 按 N=1 重新初始化 (全部持仓归第 0 份), 行为回到改造前。
5. **灰度验收 (Phase 4, 一周)**: 每日 `rotation_summary` 三份齐全;
   `rotation_lots_drift` 零告警 (人工买卖轮动代码除外); 迁移首日人工核对份分配审计
   (`rotation_migrate`)。
6. **上线前人工核对**: 券商 ETF 佣金有无最低 5 元/笔 (逐份分单 ×3, 有则改并单,
   计划书 §六口径差二)。
