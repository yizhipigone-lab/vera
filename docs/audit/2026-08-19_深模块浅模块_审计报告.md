## 二、判定框架与测量方法

**深模块** = 小接口 + 大实现:调用方每学一个单位接口,能换回大量行为(杠杆)。
**浅模块** = 大接口 + 小实现:接口复杂度 ≈ 实现复杂度,基本是转发层(漏抽象)。

**测量维度**:
1. **接口面**:公开方法/函数数、单函数最大参数数(调用方要学的量)
2. **实现深度**:文件行数、私有符号数(内部隐藏的行为量)
3. **删除测试**:删掉这个模块,复杂性是消失(浅)还是散布回 N 个调用方(深)?
4. **信息隐藏**:不变量、时序约束、错误语义有没有收进模块内部?

测量数据来自 AST 静态扫描(公开/私有符号、参数计数)+ 手工核实关键文件。

### 3.2 浅模块 / 接口债(需治理,共 3 个)

#### 🔴 高 — `trade_main.py` TradeApp:组合根过胖,业务逻辑未下沉

- 证据:`TradeApp` 11 公开方法 + **27 私有方法** [trade_main.py:180],文件 1351 行。
- 私有方法里混着**可独立成模块的业务逻辑**:
  - 盘后日报域:`_notify_daily` [trade_main.py:873]、`_build_trade_summary` [trade_main.py:955]、`_enrich_sell_quotes` [trade_main.py:1037]
  - 持仓变化域:`_diff_positions` [trade_main.py:1066]
- **为什么是债**:组合根(composition root)的职责是接线——把模块拼起来。业务计算(汇总盈亏、增强卖单字段、diff 持仓)是"行为",应该收进模块让测试直接打;堆在组合根里只能靠整机 e2e 测,改一处要重启整个交易进程。2026-08-01 抽 `AutoBuyFeature` 时已证明这个方向有效(1101→866 行),**同样的手术还没做完**。
- **删除测试**:删掉 TradeApp 里这些方法,复杂性不会消失,只是散到"组合根"这一个巨大的调用点里,更难定位。
- **建议**:参考 `trade/auto_buy.py` 的抽取模式,新增 `trade/daily_report.py`(盘后日报域,吞 `_build_trade_summary`/`_enrich_sell_quotes`/`_notify_daily` 的纯计算部分)+ 持仓 diff 纯函数。风险:涉及飞书卡渲染与快照比对,需保留 e2e 回归(`test_*_daily_report` 类)。

#### 🟡 中 — `trade/api.py`:业务计算混进路由闭包

- 证据:`create_api_app` 工厂 [trade/api.py:273] 内 25 个路由闭包,文件 876 行;内嵌计算:
  - `_calc_drawdowns` [trade/api.py:689]
  - `_entry_and_closed` [trade/api.py:149]
  - `_hold_days` [trade/api.py:240]
  - `_deep_merge` [trade/api.py:133]、`_diff_dicts` [trade/api.py:118]
- **为什么是债**:这些是**纯函数**——回撤计算、持仓拆 entry/closed、持有天数,正是"返回结果、无副作用、可单测"的理想模块形态,却埋在 FastAPI 闭包里。测它们必须起 HTTP 服务;它们也拉长了 api.py,让"路由壳"和"计算逻辑"无法分开演进。
- **删除测试**:删掉这些函数,计算逻辑不会消失,只会复制到前端或其他 API。
- **建议**:抽 `trade/analysis.py`(或 `trade/api_math.py`)纯函数模块,路由只留薄转发。低风险,纯移动不改行为。

#### 🟢 低 — `backtest/loop/builder.py` build_backtest_loop:40 参数宽构造器

- 证据:`build_backtest_loop` 签名 [backtest/loop/builder.py:31] 共 **40 个参数**(9 个资金/仓位 + 12 个策略开关 + 8 个止盈止损数值 + 公式卖出 + ATR + 优先级 + 冷却 + 敞口……),实现 134 行。
- **为什么是债**:这是全项目最宽的接口。调用方要学 40 个参数才能构造回测循环;参数与 `BacktestParams` dataclass [backtest/loop/builder.py:73] 大量重复(builder 内部其实已经组装 BacktestParams——接口没跟着收敛)。
- **但**:CLAUDE.md 记录这是**刻意冻结的契约**("签名顺序对齐原壳的 positional 参数,由 tests/test_engine_run_path.py 签名守卫锁定"),13 个测试文件 + engine 共用。**结论:记录在案,暂不治理**;若未来要动,方案是"参数分组 dataclass + 守卫测试同步改",属于破坏性变更,须单独立项。

### 3.4 性能取舍型浅容器(提醒,不治理)

- `backtest/loop/state.py` PositionBook:20 公开方法 [backtest/loop/state.py:270,305,324,337,344,347,352-385,387],实现 86 行。
- 其中 9 个是 `*_arr` 裸数组访问器 [backtest/loop/state.py:352-385],为了 hot loop 直接索引(回测主循环每 bar 调用,避免封装开销);`add`/`update_high`/`set_shares`/`slot_of`/`remove_swap_pop` 是数据结构维护。
- **判定**:接口≈实现,是"浅",但**这是有意的性能换深度**——数组访问器是给 `loop.run` [backtest/loop/loop.py:67] 内部用的,不是对外契约。记录在案,不治理(治理会拖慢回测主循环)。

## 六、治理建议(按优先级)

1. **🔴 trade_main.py 下沉盘后日报域**(新建 `trade/daily_report.py`,搬 `_build_trade_summary`/`_enrich_sell_quotes`/`_notify_daily` 纯计算,保留 e2e 回归)。理由:组合根瘦身 + 日报逻辑可单测,与 AutoBuy 抽取同模式,已验证可行。
2. **🟡 trade/api.py 抽纯函数模块**(`trade/analysis.py`,搬 `_calc_drawdowns`/`_entry_and_closed`/`_hold_days`)。理由:纯移动,行为不变,路由变薄,计算可单测。
3. **🟢 build_backtest_loop 参数分组**——仅当未来要改签名时顺带做,配合守卫测试同步,不单独立项。
4. **新代码纪律**:公开面 ≤ 6 个符号;函数参数 ≤ 6 个(超了先想 dataclass/分组);业务计算不进 API 层、不进组合根;删除测试不过的模块就是转发层,该并入调用方。
