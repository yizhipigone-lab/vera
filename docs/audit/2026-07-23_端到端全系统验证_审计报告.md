## 逐项发现

### [CRITICAL-1] `_simulate_core_v3_legacy` 缺少 `trailing_gap_protection` 参数

- **位置**：`backtest/engine.py:123-152`
- **影响**：`test_real_parity` 全部 3 个测试失败，引擎兼容壳的 parity 甲骨文机制被破坏
- **根因**：

  1. `_simulate_core_v3` (line 89) 新增了 `trailing_gap_protection=False` 参数（2026-07-21 移动止盈跳空保护）
  2. `_simulate_core_v3_legacy` (line 123-152) 作为 parity 甲骨文，没有同步添加此参数
  3. `run_cached` (line 1316) 向 `_simulate_core_v3()` 传递 `trailing_gap_protection=bool(trail.get("gap_protection", False))`
  4. `test_real_parity` 将 `_simulate_core_v3` 猴子补丁到 `_simulate_core_v3_legacy` 后，legacy 函数不接受该参数

- **复现步骤**：
  ```
  pytest tests/test_real_parity.py -v
  ```
  错误：`TypeError: _simulate_core_v3_legacy() got an unexpected keyword argument 'trailing_gap_protection'`

- **修复方案**：在 `_simulate_core_v3_legacy` 第 151 行（`atr_enabled=False, atr_matrix=None, atr_multiplier=3.0,`）之后添加：
  ```python
  # 移动止盈跳空保护 (2026-07-21): legacy 无此能力, 接收但忽略 (保持 parity 甲骨文)
  trailing_gap_protection=False,
  ```

- **为什么是 CRITICAL**：parity 甲骨文被破坏意味着新旧引擎的字节级一致性验证失效。如果引擎行为发生 drift，无法被测试捕获，构成回测结果可信度的系统性风险。

### [HIGH-1] Config Validate 阶梯止盈单位错位

- **位置**：`server.py:77`（默认值）、`server.py:146-154`（`_config_to_yaml_dict`）、`server.py:253`（validate endpoint）
- **影响**：`/api/config/validate` 返回的配置预览中，`ladder_tp.levels` 的值以百分比数字呈现但标注为小数位（如 `profit: 6.0` 应为 `profit: 0.06`），警告信息 "6000%" 没有意义
- **根因**：

  1. `StrategyConfig` 类（line 77）的默认值 `ladder_levels: str = "6:30,15:30"` 是百分比格式
  2. `_config_to_yaml_dict` (line 146-154) 直接将字符串 `split(":")` 转为 `float`，不做 `/100` 转换
  3. 前端在向 `/api/run` 发请求时**正确**地除以 100（`vera-ui.js:456`: `parseFloat(profit)/100`），所以实际运行不受影响
  4. 但 `/api/config/validate` 的默认路径和可能的直接调用路径使用的是 percentage 值

- **验证**：
  ```
  curl -X POST localhost:8080/api/config/validate -H "Content-Type: application/json" -d "{}"
  ```
  返回：`"ladder_tp": {"levels": [{"profit": 6.0, "sell_ratio": 30.0}]}`
  警告："阶梯止盈卖出比例合计为 6000%"

- **修复方案**：让 `_config_to_yaml_dict` 中的 `ladder_levels` 解析函数统一除以 100，或者让前端发送时统一用小数格式。当前 run 路径正确但 validate 路径不一致。建议在 `_config_to_yaml_dict:150-153` 添加 `/100`：
  ```python
  ladder_levels.append({
      "profit": float(parts[0]) / 100,
      "sell_ratio": float(parts[1]) / 100,
  })
  ```
  同时更新 `StrategyConfig.ladder_levels` 默认值为小数格式 `"0.06:0.3,0.15:0.3"`。

## /api/config/validate 默认值问题详析

这是 HIGH-1 的具体数据链路追踪：

| 环节 | 值 | 单位 |
|---|---|---|
| 前端 DOM 输入 (`cfgLadderVal`) | `"6:30,15:30"` | 百分比 (6%:30%) |
| 前端 → `/api/run` (除以100) | `"0.06:0.3,0.15:0.3"` | 小数 ✅ |
| 前端 → `/api/validate` | `"6:30,15:30"` | 百分比 ❌ |
| `StrategyConfig.ladder_levels` 默认值 | `"6:30,15:30"` | 百分比 ❌ |
| `_config_to_yaml_dict` 转换 | `[{profit:6.0, sell_ratio:30.0}]` | 未转换 ❌ |
| 引擎期望值 (`default.yaml`) | `[{profit:0.06, sell_ratio:0.3}]` | 小数 |

**结论**：`/api/run` 路径（实际回测）正确，`/api/config/validate` 路径显示值有误。不影响实际交易结果，但会误导用户审阅配置。
