## 1. 三个 HIGH：为什么它们会说反话

### 1.1 F-01 买卖方向口径（会说反话）

**病根不是算错，是"同一条规则写了两份"**：`notes_gen/daily.py` 自己写了一套 `0=买 / 1=卖`，
而生产库 `trades.direction` 只有 `23(买) / 24(卖)`（`xtconstant` 官方枚举，唯一定义在
[trade/book.py:42]）。后果是**每一笔买入都判不出来**：
「买价位置」那一节永远印「今日无买入成交」，「卖在相对高点」永远不触发。

**修法**（[notes_gen/daily.py:48]）：顶层 `from trade.book import DIRECTION_BUY as _DIR_BUY, DIRECTION_SELL as _DIR_SELL`，
判定收进两个函数 [`_is_buy`] / [`_is_sell`]；遇到不认识的方向码**不猜**，按"非买入"处理并打 WARNING。

**为什么测试没抓到**：测试夹具自己编了 `0/1` 造数 —— **测试和生产用两套口径，双双自洽**。
所以夹具也一并改成引生产常量（[`tests/test_daily_review.py`]），并加了一条锁死"只认 23/24"的回归测试。

**自己验一遍**：

```
"D:\Program Files\Python313\python.exe" scratch/f01_check.py
```

实测输出（生产库只读，`asof=2026-09-02`）：那天真有 1 笔买入（`513100.SH`）与 1 笔卖出（`518880.SH`），
现在买入那条能进「买价位置」、卖出那条能进「卖在相对高点」。

### 1.2 F-05 胜率分母（会说假话）

审计只说了一半，我修的时候发现**是两个坑叠在一起**：

1. **买入混进分母**：判据是「`pnl_amount` 不为空」，而买入那行的 `pnl_amount` 是 `0`
   （`trade/store.py` 该列 `REAL NOT NULL DEFAULT 0`）→ 过滤等于没写。生产库实测最近 200 行里混进 **58 笔买入**。
2. **"没记录"被当成"没赚钱"**（审计没提，是我实测发现的）：全库 212 笔卖出里有 **105 笔**
   `pnl_amount`/`pnl_pct` **恰恰都是 0**，日期**全部**落在 **2026-07-30 ~ 2026-08-07** ——
   正是 `trades` 表**还没有这两列**的时候（2026-08-07 才加）。所以它们是**"没记"**，不是"打平"。

**修法**（[notes_gen/daily.py:506]）：分母 = **有盈亏记录的卖出**，并**明写被排除的笔数**：
「胜率 38%（按能算出盈亏的 107 笔算）……（其中 93 笔没有盈亏记录 —— 是系统还不会记盈亏那阵子的成交。
它们既不算赚也不算亏，所以没进胜率的分母，免得把「没记账」说成「没赚钱」。）」

实测 **20.5% → 38.3%**，与审计独立算出的 38% 一致。

### 1.3 N-01 一个模块整个不能 import（审计没发现，我自己抓到的）

`core/kline_cache_maintenance.py` 在模块级写了 `_STUB_MIN_TRADED_RATIO = STUB_TRADED_RATIO`，
但这个常量只在 `_cache_handle()` **函数里**惰性 import → `import core.kline_cache_maintenance`
直接抛 `NameError: name 'STUB_TRADED_RATIO' is not defined`。

**为什么这是 HIGH**：它**不报错给你看**，而是静默降级 ——

- [core/market_position_runner.py:224] 的 `from core.kline_cache_maintenance import expected_last_trading_day`
  包在 `try` 里 → NameError 被吞成「**交易日历不可用，按今天处理**」→ 新鲜度判断从此**永远宽松**；
- `server.py` 与 `scheduler/__main__.py` 的补拉入口同样是函数内 import → 一起失效。

**发现过程**：跑一个新的回归测试时，日志里掉出一行 `WARNING ... name 'STUB_TRADED_RATIO' is not defined`。
**是日志抓到的，不是测试抓到的** —— 因为"降级"被 `except` 吞了，测试全绿。

**修法**（[core/kline_cache_maintenance.py:37]）：常量顶层 import（`core.kline_cache` 不 import 本模块，无循环）；
新增模块级契约测试锁死"这个常量在 import 那一刻就可见"。

## 3. F-06 ~ F-15：口径类处置的细节

### 3.1 F-06："4 个族"到底是不是 4

审计读成 3，理由是"波动族 12 个月 p=0.1017 不显著"。复测（2026-09-17）：
`n_families_usable = ` **4** —— 因为判据是「**至少有一个持有期**显著且两半一致」，
而波动族在 **6 个月**档通过（正文表格里那一行写的就是"在 6 个月 上显著且两半一致"）。

**所以正文和代码本来是一致的**，问题在**判据没写出来**：读者会默认按最显眼的"12 个月"那一列去数。
处置：正文改成从数据生成，并把判据与族名一起印出来：
「其中 **4 个族**至少在一个持有期上有可用证据：价格位置族、估值族、波动族、量能族」+「**不等于它在 12 个月上也显著**」。

### 3.2 F-07：预热余量不是巧合，是实测出来的

审计猜"需要 370 根"。我**把数据冻住再变预热**（否则生产缓存正被别的会话改写，测出来是噪音不是预热问题）：

| 预热根数 | 与长期预热基准不一致的天数 |
|---|---|
| 0 | 243 天 |
| 60 | 187 天 |
| 120 | 126 天 |
| 180 | 67 天 |
| 240 | 10 天 |
| **250 起** | **0 天** |

**下限就是整窗 250**（`amt_rank` 是 `rolling(250, min_periods=120)` —— **`min_periods` 是陷阱**：
满 120 根就有数，但那是"在 120 个值里排名"，**是错的**）。取 300 = 250 + 50 缓冲，
并且把常量改成**由单源推导**：`WARMUP_BARS = AMOUNT_RANK_WINDOW + 50`。

**顺带说明一个我没能复现的差异**：审计另有一处说"冻住数据后 `breadth` 仍有 12~19 天漂移"。
我复现到根因了，它**不是预热问题**：那是 **pandas 滚动均值的浮点尾差**
（同一批值的 `rolling(20).mean()` 在不同长度序列上得到 `14.920000000000002` 与 `14.919999999999998`），
恰好撞上"价格正好等于均线"的那一只股票，`c > ma20` 就翻了。影响量级 = **5211 只里的 1 只 ≈ 0.02 个百分点**。
**不修**（改成容差比较等于发明第三种口径），如实记在这里。

### 3.3 F-11/F-12：把"样本量"这件事说清楚

- **F-11**：日频 `n_eff` 算得没错，但读者会把它当成"独立信息份数"。现在正文写
  「**按天算**的有效独立样本约 X 天；但**真正独立的下注只有 N 次**（= 建仓次数），**以少的那个为准**」。
- **F-12**：双窗口表格加两列「前半段持有段数 / 后半段持有段数」，段数 < 30 的窗口标
  「⚠ 样本不足，不算数」（与单窗口那条纪律一致）。实测 `breadth50`：前半 83 段 / 后半 98 段，都够。

### 3.4 F-13/F-14：两个"静默"的边界

- **F-13**：`gap` 参数**已删除**。它一个参数同时管两条数据窥探纪律，`gap=0` 等于**静默把防护全关掉**。
  删掉之后误传直接 `TypeError` —— **响亮地坏** 好过 **安静地错**（有回归锁）。
- **F-14**：构建自检原来只在"不同 source 数 == 成功文件数"上判 —— 两个文件撞成同一个 source
  且其中一个失败时，**两边同时减一、等式照旧成立**。现在在**磁盘侧直接查重**（`Counter`），
  抓的是根因而不是它的影子。

### 3.5 F-15：为什么不改成 fail-closed

审计建议"把'该日无行'与'有行但零成交'分开统计"。**已经这么做了**（`no_row` 计数 + WARNING），
但**没有**把"无行"算进分母 —— 因为那会让**长期停牌股永远拉低比例**，
于是"判陈旧 → 全量补拉"变成**永不停止的误报**（补拉是小时级代价）。
当前实测：抽样里绝大多数票的末根日期是 2026-09-16，另有 7 只停在更早的日期。
方向是"分母偏小 → 比例可能偏高"，配合 WARNING 让人能看见；
真正"这批票没有那一天"由 `stale_periods` 的**日期**口径兜底。**这是取舍，不是遗漏。**
