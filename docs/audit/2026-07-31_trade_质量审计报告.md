## 二、HIGH

### H1. 卖单废单/部成被撤后 `_triggered` 不解除 → 该票当日监控失明 — 已验证
`monitor.py:235-236` 只在 `execute_exit` 返回 True (下单提交成功) 时标记；`executor.py:377-381` 终态分支释锁删 `_pending`，注释承诺"部成剩余由下一轮监控腿重新触发"，但**无任何路径把 code 移出 `_triggered`** (跨日清理除外)。触发场景: 触发卖出→提交成功→随后废单 (价格笼子/异步驳回) 或部成后手工撤剩余 → 该票当日止损/移动止盈全部失效。注释与行为直接矛盾。**本轮最值得修**。

### H2. `monitor._quotes` 跨日不清理，`high` 混入昨日最高 → 可驱动错误全仓卖出 — 已验证
`monitor.py:106` `high = max(quote.high, cur["high"])`，`cur` 可是昨日缓存；全项目无跨日重置点，与"当日最高"的注释/parity 口径矛盾。多日不重启时: 昨日 high 已破某未预埋档 → 今日首 tick `hit_ladder` 用昨日 high 命中 → `execute_exit` 以买一价**全仓卖出** (非档位比例)；trailing 激活线同理可被昨日 high 满足。

### H3. 09:15 预埋时 `prev_close` 缓存可能是前日收盘 → `limit_up` 判错 — 代码路径已验证，xtdata 行为待真机
预埋命令 09:15 发出早于当日首 tick；`trade_main.py:953-958` `_prev_close` 优先 monitor 缓存，而缓存**无日期戳**，多日运行时存的是昨日 tick 的 lastClose (=前日收盘)。昨日大涨 → limit_up 偏低误跳档 (漏挂)。修法: 缓存带日期校验，过期强制走 `query_quotes`。H2/H3 同根 (跨日缓存)，应一起修。

### H4. EOD 持仓快照可被"静默空查询"整体清空 → 次日对账 C 方基准丢失 — 已验证
`trade_main.py:603` `_on_eod` 直接 `save_position_snapshot(query_positions())` 无空守卫；`store.py:305-313` 是全量覆盖 (先 DELETE 再插)；`reconciler.py:30-32` 明确记载断线时 query_positions **静默返回空列表**。用户收盘后关 miniQMT 过夜是常态 → 15:05 EOD 归档空表 → 次日 B vs C 交叉验证全天缺席，且静默 (audit 只写"已归档"看不出是空)。修法: 空列表跳过归档 + audit。

- L3 trailing 正文 `回撤{:.1%}` vs `阈值{:.0%}` 精度档不一致，1.54% vs 1.5% 阈值可能误读为"未达却触发"。

- L6 深市 14:57-15:00 收盘竞价撤单被拒时，升级路径静默放锁无 audit 留痕。
- L7 atr_stop 回测调度表有、实盘无，当前 config 无 ATR 段无影响，启用即破 parity。
- L8 `limit_up` 未做 0.01 对齐，浮点尾差可致恰为涨停价时误跳档 (概率极低)。
- L9 `_wire` 回调里 append_raw 抛异常则事件永不入队且无 audit (磁盘满场景)；sync_reports 兜底可愈。
