## 一、致命（P0，必须立刻修）

### P0-1 `start_vera.bat` 的 QMT 等待块在 cmd 下解析期中断 → **三个进程一个都起不来**

- **位置**：`start_vera.bat`（批次 1.1 新增的 `for /l %%i in (1,1,10) do (` 块）
- **问题**：块内 `echo ... (第 %%i/10 次) ...` 的圆括号**未转义**。cmd 在**解析期**就把整块按第一处 `)` 提前闭合，余下内容报语法错并中止脚本。
- **我自己的复现**（不依赖审计员结论）：把三处 `start` 与 `pause` 桩化后跑原始文件 →
  ```
  退出码: 255
  [1/3] 启动回测 Web (8080) ...
  [STUB] start "VERA-Web-8080" ...
  [2/3] 启动实盘交易 (8081) ...
  stderr: ... was unexpected at this time.
  ```
  —— 输出停在 `[2/3]`，**交易进程与调度器都不会启动**，且与 QMT 是否就绪无关。
- **性质**：批次 1.1 的**目标（等 QMT 就绪，没就绪就不带病启动）被反向实现**：现在是不管 QMT 怎样都起不来。
- **为什么我漏了**：我当时只做了"字节级检查"（GBK/CRLF/无 BOM）+ 探针单跑，**从未真正执行这个 bat**。教训：脚本类改动的验收必须是"桩化执行"，字节检查不等于能跑。
- **修法**：块内括号转义 `^(` `^)`，或把提示语移出块外/去掉括号；修完必须**真跑一次桩化 bat** 并断言输出含 `[3/3]`。

## 二、高危（P1，尽快修）

### P1-1 mobile 版 POST 不查 `r.ok` → 急停/解除急停遇服务端错误会按"成功"走

- **位置**：`web/mobile.html:286`（`tradePost`）
- **已核实**（我亲自读码）：
  ```js
  function tradePost(u){ return fetch(TRADE_BASE+u,{method:'POST'}).then(function(r){ return r.json(); }); }
  ```
  只做 `r.json()`，不判 `r.ok`。
- **为什么是本次引入**：批次 2.2 把未捕获异常从**纯文本 500** 改成 **JSON `{"detail":...}`**。改前 `r.json()` 解析纯文本会 **reject**（页面报错）；改后解析成功 → promise **resolve** → 调用方按成功继续刷新。受影响的是 `/api/trade/kill|unkill`（急停/解除急停）与 `chat/reset`。
- **修法**：加 `if(!r.ok) throw new Error('HTTP '+r.status)`；并在 mobile 侧统一走 `describeTradeError` 口径。

### P1-2 `.gitignore` 把农场"唯一真相源"挡在 git 外，且注释称"可重建"

- **位置**：`.gitignore`（批次 1.4 新增的 `data/formula_farm/`）
- **证据**：该目录 `git ls-files` = 0、`git log --all` 无历史；而 `voided.json`（203 条作废名单）与 `archive.json`（610KB）被文档定为**唯一真相源**；`git clean -xdn data/formula_farm` 实测输出 "Would remove data/formula_farm/" —— 一条清理命令即可永久删除且无备份。
- **性质**：我的规则注释写成"运行时产物, 可重建"，对 `voided.json` 是**错的**（它是人/流程产生的判定结果，不可重建）。
- **修法**：给这两个文件加 `!` 例外（入 git），或把它们迁到受版本控制的位置并改注释。

### P1-3 `*.csv` / `*.json` 忽略规则误伤测试夹具 → **"全量 3028 例绿"无法从 git 复现**
