# 公式农场「→ 回测页」回填抛前端错误审计报告

- 成文日期：2026年9月17日
- 触发事件：用户点「→ 回测页」看到红色提示 `Cannot read properties of null (reading 'style')`（用户提供的截图）
- 关联：这是"回填回测页"功能的**第二个**故障。第一个是后端 404（服务进程比接口代码旧 50 分钟），已通过重启 Web 后端解决；本报告是修好 404 之后**才暴露出来**的前端故障。
- 结论：**按钮点了会抛错，参数只填了一半；页面看起来"填好了"，实际跑的是另一套口径**——比单纯报错危险得多

## 一、结论先行（大白话）

「→ 回测页」这个按钮，做的事是"把公式农场粗扫用的那套设置，抄到回测页的表单里"。
用户看到的红色提示只是**表面症状**；真正的问题是这个错误**恰好卡在抄写的中途**：

- 抄进去的部分：公式名 `GS1075`、股票池、周期、买入价口径、几个语义开关
- **没抄进去的部分**：回测区间、本金、单票上限、止盈止损全部参数、时间止损 —— 这些留在**页面默认值**上

实测对照（真浏览器，修复前）：

| 字段 | 粗扫口径（应当填） | 修复前实际留着的值 | 性质 |
|---|---|---|---|
| 本金 | 300万元 | **100万元** | 页面默认值，差 3 倍 |
| 移动止盈激活 | 8% | **3.5%** | 页面默认值 |
| 移动止盈回撤 | 0.5% | **1%** | 页面默认值 |
| 硬止损 | 20% | **12%** | 页面默认值 |
| 回测区间 | 2024年9月2日~2026年9月3日 | **2024年1月1日~2025年6月30日** | 页面默认值 |

**一句话风险**：用户核对"公式名对了"就点开始回测，跑出来的是一份**本金只有三分之一、止损止盈完全不同**的结果，而页面上没有任何提示说"参数没抄全"。这正是这个项目前两轮审计（HIGH-1 静默换语义 / HIGH-2 板块并集覆盖）拼命要防的那类事故，只是换成了"抄一半"的形态。

## 二、怎么查出来的（可复现的方法）

不靠读代码猜，用**真浏览器**跑一遍并抓证据：

1. 用 Playwright 加载 `http://127.0.0.1:8080/`，切到公式农场页签；
2. 在页面里给 toast 容器装一个监听器（toast 3 秒后会自动消失，直接读会读成空 —— 第一遍我就踩了这个坑）；
3. 点「→ 回测页」，然后读：toast 文本、页面 hash、横幅显示状态、以及回填后各字段的实际值。

关键证据（修复前）：toast = `Cannot read properties of null (reading 'style')`；hash 停在 `#farm`（没切到回测页）；横幅 `display: none`（没显示）；本金 `1000000`（默认值）。

## 三、根因

页面 HTML 里，板块"空态占位"元素是**板块格子容器**的子节点：

```
web/index.html:518   <div class="sector-grid" id="sectorGrid">
web/index.html:519     <div class="sector-empty" id="sectorEmpty">加载板块列表中…</div>
```

而重画板块的函数**整块替换了父容器的内容**（`grid.innerHTML = 各板块项`），于是这个占位元素在**第一次渲染成功时就被自己抹掉了**。
从那以后，任何 `document.getElementById('sectorEmpty')` 都返回 `null`，而旧代码直接对它取 `.style` → 抛 `Cannot read properties of null (reading 'style')`。

**触发条件**（两个同时满足才炸，所以平时不易发现）：
1. 通达信开着，板块列表加载成功（实测 128 个板块）→ 重画函数走过一次，占位元素被抹掉；
2. 再有任何一次重画 —— 农场回填会先清空板块选择，正好触发。

**为什么后果这么重**：农场回填的执行顺序是「填公式名 → 填池子/周期 → **清板块（这里抛错）** → 填区间/本金/止损 → 显示横幅 → 切页」。抛错点在参数区之前，后面的全跳过，异常再被 `.catch()` 吞掉弹成一条 3 秒就消失的提示 —— 用户只看得到一闪而过的红字。

## 四、修复（三处，同一根因不写第二份）

1. **占位元素改成"按需重建"**（`web/js/vera-ui.js:221` 新增 `_sectorEmptyBox`）：谁需要它、它不在了就现建一个塞回容器。自愈，不再依赖"它一直存在"这个假设。
2. **同一根因的第二处一并修**：`loadSectors`（`web/js/vera-ui.js:228`）原先也抓了这个元素并无保护地解引用（第 225 行 `.style.display`），触发路径是「板块加载成功过一次 → 之后加载失败 → 点重试」。顺手把失败提示收口成一个 `fail()`（`web/js/vera-ui.js:231`）——原来两处失败分支是近乎逐行重复的两份，重复即漂移，合并掉。
3. **附带动作不许打断核心动作**：农场回填里"清板块"那段套上 `try/catch`（`web/js/vera-ui.js:687` 起，catch 在 `web/js/vera-ui.js:695`），出错只写控制台警告并继续往下填参数。**理由**：清板块是附带动作，参数回填是核心；附带动作出错绝不该让核心动作半途而废——这正是本次事故的放大器。

## 六、附带修掉的一个"一直红着"的测试

`tests/web/test_data_cache.js:21` 断言"过期应红色"时找的是 `var(--red)`，而 2026年9月7日 的设计令牌收口（commit `ca42a3a`）已把颜色改成 `--up`(A股红 `#d6342f`) / `--down`，全项目现在 **0 处** `var(--red)`。
**也就是说这个测试自 2026年9月7日 起就一直失败**（`data_cache.js` 本文件与测试文件在工作区都未被改动，git 状态可证与本次无关）。红测试会掩盖真回归，已按当前令牌修正断言，语义不变。

## 七、教训：同一天踩了三次"看得见 ≠ 生效"

| # | 现象 | 真因 |
|---|---|---|
| 1 | 按钮点了返回 `Not Found` | **后端进程是旧的**（启动时间比接口代码早 50 分钟），接口根本不在进程里 |
| 2 | 按钮看得见、页面却是旧榜单 | **前端文件是直接读磁盘的**（js 新、后端旧），所以界面看着新、数据是旧的 |
| 3 | 前端抛 `null.style` | **DOM 元素被代码自己抹掉**（父容器整块重画），第二次访问就是 null |

三次都不是"代码写错了逻辑"，而是**"以为它在、其实不在"**。防御姿势：不要假设元素/接口/进程一直存在 —— 访问前判空、按需重建、改完 Python 就重启。
