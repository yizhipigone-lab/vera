## 三、审计发现与修复(按严重度)

### 🔴 发现 1(真 Bug,已修):deep 档留空保存被清空

- **位置**: 重构前 [ai_api.py] 保存路由的 deep 分支合并逻辑
- **问题**: fast/standard 档用 truthy 判断(空串=保留旧值),deep 档误用 `is not None`(空串 `""` 也会被写入)。前端总是全量提交三档 → 用户只改快速档点保存,深度档配置被悄悄抹掉。三个档合并逻辑手写三遍,必然漂移。
- **复现**: `test_save_deep_blank_keeps_old` 先红(断言 `'' == 'deepseek-official'`)
- **修复**: 合并语义统一收口 `ai_config.merge_patch`([llm/ai_config.py:83]),三档共用 `_FIELDS` 字段形状([llm/ai_config.py:76]),路由只调一行([ai_api.py:91])
- **防回归**: merge_patch 4 用例 + api 清空/未知字段用例锁行为

### 🟠 发现 2(测试假断言,已修):`assert ... or True`

- **位置**: [tests/test_ai_api.py] test_save_then_get_masks_key
- **问题**: 恒真断言(以 `or True` 结尾),等于没测,给"测试绿了"的假安全感
- **修复**: 删除,换成真正检查"明文 Key 绝不出现在整个响应"

### 🟡 发现 3(深模块化修复):ai_api.py 偏浅,合并语义下沉

| 对比 | 行数 |
|---|---|
| data_cache_api.py(既有薄路由范本) | 68 行 |
| ai_api.py 重构前 | 165 行 |
| ai_api.py 重构后 | 138 行 |
| core/kline_cache_maintenance.py(既有下沉实现范本) | 242 行 |

- **修复**: 合并+清空语义下沉 `ai_config.merge_patch` 纯函数(单一真相源),路由只剩参数校验+转发+视图
- **收益**: 消灭"三份手写漂移"的根源;合并规则可直接单测,不必绕 TestClient

### 🟡 发现 4(产品缺口,已补):无法一键清空配置回落默认

- **问题**: 原语义"留空=保留旧值",但无任何办法清空某档(如删快速档 Key 回到 .env 默认)
- **修复**: `merge_patch` 支持档内 `__clear__: true` 整档置空([llm/ai_config.py:83]);前端三档各加「清空本档」按钮([web/js/ai_settings.js:120]),清空 body 构造抽纯函数 `clearBodyFor`([web/js/ai_settings.js:114])可 node 测
- **防误清**: `__clear__` 仅严格 `is True` 触发,字符串 `"false"` 不误清(有测试锁)
