## 一、结论先行

**先说一句话结论：这套系统的病不是"抽象太多"，而是"同一件事被写了很多遍"。**

打个比方——像一个厨房，厨具数量不算离谱，但**同一把菜刀买了六把**，每把都稍微不一样。切菜时随手抓一把，结果同一块肉，今天切的片厚、明天切的片薄。VERA 的复杂度主要来自"同一条规则多份手写副本"，这恰好是项目自己在 `CLAUDE.md` 里反复记录、反复踩的老坑（买卖口径两份、行情陈旧判定三份、下单逻辑五份、达标口径曾三份）。

**总账（估算，七个子系统全部扫完）**：

| 项目 | 数量 |
|---|---|
| 发现条目（同类已合并） | **101 条主条目**（子代理原始清单 170+ 条） |
| 估算可砍代码 | **约 2.6 万行**（其中约 2.2 万行来自 `research/`+`scratch/` 一次性脚本，见 D 档） |
| 生产代码可砍 | **约 3600~4600 行** |
| 估算可去掉的可选依赖 | **3 个**（matplotlib、jinja2 + 1） |
| 一次能砍几百行的"大件" | **8 条（A 档）** |
| 不影响功能、删了少踩坑的"中等件" | **55 条（B 档）** |
| 零风险顺手清的小件 | **22 条（C 档）** |
| 研究档案瘦身（风险性质不同，单列） | **16 条（D 档）** |

**如果只做三件事，做这三件**：

1. **把 tests 的 104 份重复样板收掉**（A3+A4，约 −520 行）：104 个测试文件各自手写同 3 行 `sys.path` 引导，`store`/`kill` 夹具复制 15 份，`_wait` 轮询复制 7 份，`TradeApp` 装配手写 28 次。pytest 自己就有 `pythonpath` 开关和夹具继承，这是一行配置能换掉几百行的事。
2. **把公式农场的两套粗扫出榜合成一套**（A2）：现在 `farm_batch_sweep` / `farm_parallel_sweep` 与正式闸门④ `farm_backtest` 是**并行的两套出榜逻辑**，而且它们都往同一份人工总榜 `winners/index.md` 写。两套逻辑对同一批公式可能给出不同榜单——这是"会误导结论"的复杂度，优先级高于单纯的代码重复。
3. **把自动迭代的 6107 个生成脚本换成 1 个参数化脚本**（A5）：那个循环已经每轮往 `iter_log*.csv` 写了一行完整参数与成绩，却还额外物化一份 `.py`；下游 `portfolio_multi.py` 只能靠 **AST 解析** 从 `.py` 里把参数抠回来。这是把代码文件当数据库用。

## 二、标签说明（大白话版）

| 标签 | 意思 | 白话解释 |
|---|---|---|
| `delete` | 死代码、没人用的灵活性、投机式功能 | 直接删掉，什么都不用补 |
| `stdlib` | 手写了标准库已有的东西 | Python 自带函数，点它的名 |
| `native` | 依赖或代码在做平台/框架已做的事 | 比如 pytest 本来就有的开关 |
| `yagni` | 只有一个实现的抽象、没人会设的配置、只有一个调用方的层 | "以后可能有用"的东西，现在没用 |
| `shrink` | 同样逻辑、更短的写法 | 不删功能，只把代码写短 |
