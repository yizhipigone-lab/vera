# VERA 代码库架构 — 深模块/浅模块分析报告

**日期**: 2026-08-28
**范围**: 全代码库约 120 个 .py（trade/ 20 模块 + trade_main · backtest/core/selection/pipeline/scheduler 64 文件 · web/server/utils/tools）
**方法**: 3 个并行探索子代理分区域走查 + 主代理交叉核验（trade_main 42 方法、engine 双入口、trade/api 24 路由、测试覆盖 156 文件）
**词汇**: 深模块（小接口+厚实现）/ 浅模块（接口≈实现）/ 删除测试 / locality / leverage，沿用 codebase-design 定义
**HTML 版**: `%TEMP%/architecture-review-20260828-032500.html`（可视化，含 before/after 图）

---

## 一、结论先行

1. **trade/ 深模块纪律执行良好**：events/book/executor/monitor/risk/reconciler/auto_buy/notifier 都是真深模块（小接口厚实现）；gateway/store 两个基础设施豁免核实成立。08-16 旧报告点名的"第三份行情陈旧判定"已由 `quote_stale.py` 收口、"monitor._evaluate 拆 _hit_* 助手"已落地。
2. **backtest/core 区深为主**：`backtest/loop/` Strategy 模式、`core/kline_cache.py`、`core/progress.py`、`scheduler/vera_scheduler.py`、selection 三级缓存存储层都是正面样本；浅模块集中在两类——core 取数门面层的薄壳转发（data_fetcher/data_cache），和跨模块侧信道（last_batch_errors/_UNSET 哨兵）。
3. **web 区是最大风险区**：~5800 行手写 JS，ES module 与 classic script 双轨混用、无统一状态层、trade.js 破千行；server.py 拆分半途。
4. **根目录与 tools/ 临时脚本堆积**：11 个 `_tmp_*.py` + 15+ 个 .log 摊在根目录，无清理机制。
5. **trade_main.py（1314 行）**：组装与 13 事件静态接线是正当职责不拆；该拆的是漏进来的业务规则（资金口径三件套 ~200 行、热更私有字段穿透、日报编排残余），拆完预计 1314→约 900 行。

## 三、摩擦点候选（按严重度）

### A. 实盘交易区

**A1 [Strong] trade_main 资金口径三件套 + 热更契约下沉**
- 涉及: [trade_main.py:1120-1209]（`_stock_budget`/`_stock_pool_value`/`_in_flight_sell_returns`）、[trade_main.py:605-609]（`_apply_config` 直改 monitor/executor/timer/risk 私有字段）、[trade/rotation.py:660-670]（市值口径重复）
- 问题: 组合根埋约 200 行资金口径业务规则（ETF池 vs 股票池预算帽/在途回款，8-21 日亏闸误拒 bug 所在地）；热更无统一契约，直改 4 模块私有字段
- 方案: 资金口径下沉共享深模块（如 `trade/pool_money.py`），组合根只组装；热更改为"配置契约对象→各模块统一 apply"
- 收益: locality（口径改动一处）、leverage（rotation/auto_buy/对账共用）、可直接单测口径模块

**A2 [Strong] rotation.py 三态包袱迁出 + 破 shadow 循环依赖**
- 涉及: [trade/rotation.py:50-69]（deprecated MA20 三态 ~150 行）、[trade/shadow.py:38]（惰性 import 成环）
- 问题: 生产已切动量规则 2026-08-20，但 811 行里约 150 行三态（compute_signal/STATE_RATIOS/target_values）仅供 research/*.py 历史脚本 import；规则源放错文件
- 方案: 三态规则整体迁出（独立模块或 research 目录），rotation.py 只留动量规则；shadow 改从新位置 import
- 收益: rotation 811→约 650 行；新人不再被 deprecated 误导；破循环依赖

**A3 [Strong] reconciler 卖单登记收口（"rotation 绕过 executor"事实暴露）**
- 涉及: [trade/rotation.py:775-811]（`_place_order` 直接 gateway.order+risk.check, 不走 executor 撤单流水线）、[trade_main.py:297-301]（组合根手拼 executor+rotation 两路 in_flight）
- 问题: reconciler 正确装配依赖调用方知道"rotation 绕过 executor._pending"这个内部事实，否则对账误判 CRITICAL 急停——接口不完整
- 方案: 卖单登记统一收口（pending_sells 登记移入 book/store 共享接口）
- 收益: reconciler 少一条隐含契约；对账正确性不再依赖组合根手拼

**A4 [Worth exploring] api.py positions() 业务数学下沉纯函数**
- 涉及: [trade/api.py:157-292]（约 135 行当日盈亏口径数学，无法单测）
- 方案: 照 analysis.py 模式下沉纯函数（position_view 计算），api 端点只做取数+渲染
- 收益: 盈亏口径直接单测；api.py 回到真薄层

### B. 回测引擎 + core 区

**B1 [Worth exploring] core/data_fetcher.py 门面收口 + trading_days/dates 反义双胞胎**
- 涉及: [core/data_fetcher.py]（11 公开方法, compute_window_bounds 纯转发、3 个 sector/name 样板透传）
- 问题: get_trading_days vs get_trading_dates 名字几乎相同但错误处理语义相反（失败即崩 vs 降级空表），调用方极易选错
- 方案: robust 语义收唯一公开入口；双胞胎改名或合一；透传折叠
- 收益: 接口面缩小；消除"选错函数"类 bug

**B2 [Worth exploring] core/data_cache.py get_or 单方法收口**
- 涉及: [core/data_cache.py]（has/get/set 10 方法没吃掉"判过期→回源→回填"模式）、selection/stock_filter.py（无 TTL 的 _INFO_CACHE 另一份实现）
- 方案: `get_or(key, fetcher)` 单方法：过期/未命中自动回源回填，顺带收编 stock_filter 缓存
- 收益: TTL/过期语义一处定义；调用方接口变小

**B3 [Worth exploring] FormulaRunner.last_batch_errors 侧信道折进返回值**
- 涉及: [core/formula_runner.py:69,210] → [selection/signal_day_cache.py:227]
- 问题: "失败空不缓存"的正确性依赖调用方读类属性（副作用侧信道），不知道读它就是漏判；缺 locality
- 方案: 批次结果（含失败明细）折进返回值（BatchResult dataclass），类属性侧信道删除
- 收益: "真空 vs 失败"区分随结果返回，调用方不会漏判

**B4 [Worth exploring] backtest/result.py _UNSET 哨兵拆真实类型**
- 涉及: [backtest/result.py]（74 行, frozen dataclass 外壳 + partial dict 内核 + _UNSET 哨兵）
- 问题: 调用方须知"未设置字段用 get 不用 .field"；run vs run_cached key 集合还不同
- 方案: 拆真实类型（run/run_cached 各自明确返回类型），消除 _UNSET 语义
- 收益: 接口自解释

**B5 [Worth exploring] kline_cache_maintenance 只读查询上移 KlineCache**
- 涉及: [core/kline_cache_maintenance.py:65-72] 裸读 manifest.db 绕过 [core/kline_cache.py:47-128] 类
- 问题: schema 双写点（类内建表 + 工具直读），改 schema 需同步两处
- 方案: 只读查询上移为 KlineCache 方法，维护工具经接口访问
- 收益: schema 单点定义

### C. web + 服务端外围

**C1 [Strong] 临时脚本/日志双层堆积清理闸**
- 涉及: 根目录 11 个 `_tmp_*.py` + 15+ .log + 3 份 optimization_results*.json；tools/ 4 个 _tmp_/_batch_/_gen_
- 方案: 一次性清理；_tmp_*/*.log 入 .gitignore；临时脚本隔离到 scratch/；正式脚本按 e2e_/p0_/gs_/verify_ 前缀归位
- 收益: AI 可导航性（新会话扫目录不被垃圾干扰）；成本最低见效最快

**C2 [Worth exploring] server.py 分析域抽 analysis_api.py**
- 涉及: [server.py:452,506,547]（分析域 ~150 行滞留, C4c 拆分半途）
- 方案: 照 lab_api.py 范式抽 analysis_api.py，server.py 回纯装配（~470 行）
- 收益: 与"一域一文件"新范式对齐

**C3 [Speculative] 前端无状态层 + module/classic 双轨归一**
- 涉及: web/js/trade.js 1011 行；[web/index.html:1358-1368]（双轨 script）
- 问题: ES module 与 classic script 双轨混用靠 ?v= 与 window.VeraRecover 手工桥接；状态三层散布（裸变量+localStorage+window 钩子）
- 方案: 全量迁 ES module + 按域建 client + 收敛 store（改动面大, 分阶段）
- 收益: 前端可测；trade.js 千行可拆

**C4 [Speculative] 管线状态机靠注释托底 → core/run_state.py**
- 涉及: [server.py:73-100,207-239]（pipeline_status 单例 + _run_lock + lab_status 不对称互斥 + progress 融合）
- 方案: 状态机收进 core/run_state.py 深模块，不变量变代码结构（显式状态+迁移守卫）
- 收益: 不变量从注释变可测代码

**C5 [Worth exploring] api.js 承诺未兑现**
- 涉及: web/js/api.js（41 行, 唯一深模块, 只覆盖回测/配置/体检三域）
- 方案: 研究/数据/交易域各加 20-40 行 client 函数，页面 fetch 全部收敛
- 收益: 后端改路由只改一处；前端 fetch 行为统一

### D. 补充候选（trade/ 内）

**D1 [Worth exploring] 重复实现三处**: 市值口径两份（[trade_main.py:1138] vs [trade/rotation.py:660-670]）、DIRECTION_BUY 三处（book.py:42 / notifier.py:33 / llm_review.py:21, 两处防环注释理由不成立）、round_price vs round_price_etf 两份。方案: 常量收 book.py 单一真相源，市值口径随 A1 下沉。

**D2 [Worth exploring] executor fill_context 三件套收小对象**: executor 恰好顶满 8 方法纪律上限（647 行），fill_context 三件套（register/get/clear）收 FillContext 小对象释放接口预算。

**D3 [Speculative] regime.py 文档漂移**: 声称回测共用，实际仅 auto_buy 一个调用方。方案: 修文档口径或评估下沉。

## 四、Top Recommendation — 先做 A1

**trade_main 资金口径三件套 + 热更契约下沉（trade/pool_money.py）**

理由：
1. **直接关联实盘正确性**——8-21 日亏闸误拒 bug 就住在 `_in_flight_sell_returns` 里；"ETF池 vs 股票池"资金口径是轮动/选股桥/对账三处共享的核心语义，散在组合根 + 与 rotation._etf_value 重复，正是"接口不完整→bug 藏得深"的样本。
2. **改动面可控**——约 200 行移出 + 一个深模块 + 热更契约，有现成测试网（test_rotation/test_auto_buy/test_reconciler）兜底。
3. **顺带消灭 D1 市值口径重复**；trade_main 从 1314 行降到约 1100 行，组合根回归"组装"本职。

次选：A2（rotation 三态包袱迁出，811→650 行 + 破循环依赖，纯机械迁移风险低）→ C1（临时脚本清理，成本最低见效最快）。
