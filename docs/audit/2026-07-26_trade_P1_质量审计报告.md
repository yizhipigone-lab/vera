## CRITICAL

### C1. 档位乐观标记无日终过期,持仓隔夜后预埋单永久停挂 — 已验证

计划书 §5.1 明示"日终自动过期,本地标记,次日重挂",但实现里 tier 标记按持仓生命周期持久化、**无任何日期维度**:

- 下单成功即标记并落库 [trade/executor.py:210-212];`tier_state` 表只有 code 主键,无日期字段 [trade/store.py:47-51];
- 重启时原样灌回 [trade_main.py:202];EOD 只归档持仓快照,**不清 tier** [trade_main.py:302-306];全仓无任何 reset/clear tier 路径。

后果链:day1 挂出 tier0/tier1 未成交(券商端日终自动作废)→ day2 `place_ladder` 跳过已标记档 [trade/executor.py:178-179],剩余档又因涨停被跳过 → **该票零预埋单,阶梯止盈保护完全消失,且无告警**。e2e 只测到"重启恢复档位"([tests/trade/test_e2e_trade.py:176]),没测 day2 的 place_ladder,恰好掩盖此洞。持仓跨日是常态,这打穿系统主职责。

## HIGH

### H1. 监控腿"已触发"标记打在执行成功之前 — 已验证

`self._triggered.add(code)` 先于执行,`execute_exit` 返回值被丢弃 [trade/monitor.py:125-126]。而 execute_exit 有大量合法 fail-closed 返回路径:无买一价 [trade/executor.py:246-250]、可用为 0 [trade/executor.py:240-244]、风控拒绝 [trade/executor.py:309-313]。任何一条命中,该票当日再无监控腿——一跳行情延迟换一整天无保护。

### H2. `_triggered` 集合无跨日清理 — 已验证

注释自称"当日已触发票" [trade/monitor.py:46],但 EOD/跨日均无清理点。进程不重启时,昨日触发过的票今日规则永不评估。与 H1 叠加后唯一恢复途径是重启进程。

### H3. 铁律 4 的 parity 测试不存在,monitor 是回测规则的第二份实现 — 已验证

铁律 4 要求"共用规则+parity 测试锁定"。现状:monitor 独立实现规则 [trade/monitor.py:136-156],tests/trade/ 下无 parity 测试;config 注释声称默认值"对齐回测 stop_loss 口径" [trade/config.py:48-53],无测试锁这句话。这正是 QP C6 口径分裂教训要防的事,目前无锁。

### H4. `Book._seen_trades` 幂等集合不落盘,重启后成交重推将双扣持仓 — 已验证(触发条件待真机)

`_seen_trades` 是纯内存 set [trade/book.py:112],判重只查它 [trade/book.py:160-163]。重启后集合清空,而灌仓持仓已含当日成交;若 QMT 重连后重推当日成交回报(待验证),apply_trade 会再次加减仓;store 唯一约束炸 IntegrityError 被吞 [trade_main.py:281-288]——**账本已错、DB 正确,两者背离,要等下次对账才暴露**。修法:启动时用当日 trades 回填 `_seen_trades`(目前 Book/store 均无此接口)。

### H5. RealGateway 行情订阅腿没有接线 — 代码侧已验证,xtquant 行为待验证

`trade_main.py` 把 on_quote 接成事件入队 [trade_main.py:167-168],FakeGateway 由 push_quote 驱动、测试全绿;但 `RealGateway.subscribe_quotes` 只调 `xtdata.subscribe_quote`,未传 callback、未启动 xtdata 回调循环,无任何把推送转发给 `self._on_quote` 的代码 [trade/gateway.py:209-214]。即**生产环境订阅腿是哑的**,系统永远靠"心跳超时→轮询降级"工作 [trade/monitor.py:74-87]——功能上 fail-closed 兜得住,但"15s 心跳+60s 扫描"的止损延迟口径与计划书 §5.2"订阅为主"不符。列入 P0 验证。

## 总评与修复建议

3. **第三批(真机验证驱动)**:V1(open_price 字段,最高优先)→ H5(xtdata 订阅接线)→ V3(H4 回填 `_seen_trades`)。
4. **第四批(体验与安全)**:M11/M12(前端失败反馈)+ M13(账号抽环境变量)+ L3(stop_vera 校验进程名)+ L 级其余。
