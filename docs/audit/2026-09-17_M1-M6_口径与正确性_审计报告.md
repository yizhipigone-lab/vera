### F-01（HIGH）★ 复盘报告判"买/卖"用的方向码与生产库不符 → 有买入却说"今日无买入成交"

- **结论**：`notes_gen/daily.py` 把 `trades.direction` 当成 `0/1`（或 `"buy"/"sell"` 字符串），而生产库落的是 xtquant 常量 **23 = 买 / 24 = 卖**。判"买"的那一行过滤结果**恒为空**，于是「买价位置」段在**明明有买入的日子**打印"今日无买入成交"；判"卖"的那一行则把**买入**也当成卖出处理。
- **证据（每一环都读/跑过）**：
  - 常量定义：`[trade/book.py:42]` `DIRECTION_BUY = 23`、`[trade/book.py:43]` `DIRECTION_SELL = 24`

  - 复盘的判据：`[notes_gen/daily.py:361]` `if t.get("direction") not in (1, "1", "sell", "SELL"):`（判卖）、`[notes_gen/daily.py:419]` `buys = [t for t in trades if str(t.get("direction")) in ("0", "buy", "BUY")]`（判买）
  - 用**生产库**只读实跑（`asof = 2026-09-02`，那天真实有 1 笔买入 513100.SH(direction=23) + 1 笔卖出 518880.SH(direction=24)）：

    - `daily.py:361` 判"卖"口径命中 **2** 笔（真实卖出 **1** 笔）→ 那笔**买入**被当成卖出走了后续逻辑

### F-04（MEDIUM）"118 条被劣化"应为 **119 条**，区间起点应为 **2025-04-16**

### F-05（HIGH）★ "最近 200 笔卖出"的分母里含买入 → 胜率印成 20%（真实 38%）

### F-07（MEDIUM）`WARMUP_BARS = 300` 够用但余量靠巧合，且没写清"为什么 300 就够"

- **结论**：预热修复**有效**（我实测输出窗口内 null 为 0），但 `WARMUP_BARS = 300` 这个取值**恰好等于 `DEFAULT_BARS`**，而真正决定"够不够"的是 `amt_rank` 的 `rolling(250, min_periods=120)` 需要 **370** 根才出第一个有效值。当前能工作，靠的是"载入 `bars + WARMUP_BARS = 600` 根"这句话里的 `WARMUP_BARS` 顺手把可用根数推到了 500 以上，而不是"300 正好覆盖最长回看窗口"。
- **证据**：
  - 配置：`[core/market_position_runner.py:97]` `DEFAULT_BARS = 300`、`[core/market_position_runner.py:105]` `WARMUP_BARS = 300`；调用点 `[core/market_position_runner.py:816]` `_load_matrices(bars + WARMUP_BARS if bars else 0)`
  - `amt_rank` 的窗口：`[core/market_position_runner.py:828]` `total_amt.rolling(250, min_periods=120)`；`amount_pct_1y` 即使窗口未满也会给数（`min_periods=120`），所以**"预热够不够"的判据不是"非 null"，而是"值是否与全量历史一致"**
  - 实测（同一批日期，与全量历史对比）：载入 **600** 根 → 输出窗口内不一致 **0** 天；**500** 根 → **0** 天；**420** 根 → **122** 天不一致；**370** 根 → **136** 天；**300** 根 → **127** 天
  - 例：2025-06-27 载入 420 根时 `amount_pct_1y = 82.4`，全量算出来是 **70.8**（差 **+11.6** 个百分点）
- **这条的真正风险**：**现在的"0 天不一致"依赖精确载入 ≥500 根**，而 `_load_matrices(bars)` 是**逐票截断**的（`[core/market_position_runner.py:163]` 起，`if bars and len(df) > bars: df = df.iloc[-bars:]`）。一旦日线缓存的可用交易日变多（现在正常日约 5200 只票有量、每天 1 根），600 根里"有效交易日"占比就会变化；更直接的是**如果哪天缓存被截短或有大段停牌，600 根覆盖的自然日就会变短**，于是同样 0 null、但**数值静默漂移**。**这不会报错、不会有警告，只会让 `amount_pct_1y` 悄悄变成另一个数** —— 属于典型的静默劣化。
- **建议改法**：把预热写成"按需求的导出量"推导而不是常量：`WARMUP_BARS = 250 + 120`（滚动窗 + 最少观测）或直接 `max(250 + 120, 300)`，并在注释/测试里写清"输出窗口内须满足 `amt_rank` 的 `min_periods`，否则值会与全量口径不一致（不是 null，是静默漂移）"；最好再加一条回归测试：**同一批日期，分别用 `bars=300` 与 `bars=0` 跑，断言 `amount_pct_1y` 逐条相等**（现在只有"不许变 null"的断言，抓不到数值漂移）。

### F-11（MEDIUM）`n_eff` 在日频影子回放里的口径偏乐观，容易压过"持有段数"这个更硬的下界

- **结论**：`n_eff = n / vif` 算得**没错**（我手算 Newey-West 与实现逐位一致），但用在"两态择时"的日收益序列上会给出**接近样本总数的**数：`ma20` 的 `n_eff = 2819`（n=3329）、`breadth50 = 2790`、`regime = 3063`，而这三条规则的**持有段数只有 196 / 181 / 15**。报告里把 `n_eff` 和"持有段数"并排展示时，读者很容易理解成"有 2819 份独立信息"。
- **证据**：
  - 手算校验（AR(1) 序列 n=800）：实现 `se=0.09442598`、`t=-0.8803`、`vif=3.7382`、`n_eff=214.0`，与手算**完全相同**；白噪声 `vif=1.05`（≈1）→ Newey-West 实现正确
  - 真实序列自相关实测（lag 1/2/5/10/20）：`ma20` = 0.056 / 0.034 / 0.073 / 0.058（**很弱**）→ 所以 `vif ≈ 1.18`、`n_eff ≈ 2819`

- **建议改法**：不改算法，改**展示口径**：把 `n_eff` 与"持有段数"一起给时明确写"`n_eff` 是**日频**口径（把每个持仓日当一个观测），**真正不重复的下注次数是持有段数那一列（196 / 181 / 15）**"；或直接取 `min(n_eff, round_trips × 常数)`。理由是：对一个"持仓中位 4~5 天、空仓期是一串 0"的序列，日频 `n_eff` 天然偏乐观。

### F-12（MEDIUM）双窗口只报"年化同号"，不报**样本量**与段数，短窗口那一半可能是 2~3 个段

- **结论**："双窗口一致性"是《公式因子体检方法论》纪律 2 的正确落地，但实现只比较两个窗口的**年化是否同号**，**不报每个窗口里有多少持有段**。对 `regime`（全样本仅 15 段）而言，后半段约 7 年可能只有几段，同号与否的信息量很有限。

### F-13（LOW）`similar_days` 的兼容参数 `gap` 会把两条纪律同时改成同一个值，`gap=0` 静默改变语义

- **结论**：已废弃的 `gap` 参数同时覆盖 `exclude_recent` 与 `min_gap`（`[core/market_position.py:351]` 起）。传 `gap=0` 时 `exclude_recent=0`、`min_gap=0`，于是**数据窥探纪律被静默关掉**，同时 `min_gap=0` 会让所有相邻日都满足间隔条件。不抛错、不告警。

- **建议改法**：既然新代码路径已经不用 `gap`，建议直接**删掉**这个兼容参数（项目铁律"如无必要勿增实体"），或在 `gap <= 0` 时抛 `ValueError`。现在这样留着，将来任何一处误传 0 都会静默关掉数据窥探防护。

### F-14（LOW）`_to_source` 的"不同 source 数 == 处理文件数"自检，在"两个文件撞成同一 source 且其中一个失败"时会漏判

- **结论**：自检逻辑本身正确（我读了三重防线的实现），但存在一个组合场景它抓不到。
- **证据**：`[brain/search_engine.py:353]` 判据是 `len(distinct) != file_count`；`file_count` 只统计**成功处理**的文件数。若两个磁盘文件映射到同一 `source` 字符串、且其中一个**处理失败**（进 `skipped`），则 `distinct` 与 `file_count` 都减 1，等式仍成立；而第二道判据 `missing = set(disk_srcs) - indexed - skip`（`[brain/search_engine.py:360]`）因为 `disk_srcs` 是**去重后的集合**，同样看不出少了一个文件。→ **静默少收一篇语料**。
- **建议改法**：`disk` 侧改成用"文件路径"而不是"source 字符串"做集合（`_disk_files` 已经带了 path），或额外断言 `len(disk) - len(skipped) == file_count`。

### F-15（LOW）`last_bar_traded_ratio` 的抽样与"末根日期"的耦合

- **结论**：抽样是确定性的（固定步长取 50 只），这点很好；但它拿 `cached_last_date()` 的**全局 MAX 日期**去读每只票的那一天，如果某只票的历史截止日**早于**全局 MAX，读到的 `df` 为空 → 被 `continue` 跳过（既不算分子也不算分母）。方向是"分母偏小"，一般无害，但**遇到大面积停牌时会高估有成交比例**。
- **证据**：实现见 `[core/kline_cache.py:170]` 起（`last_bar_traded_ratio`）；实测各票末根日期确实分歧：众数 2026-09-16（5204 只），另有 2026-08-26（4 只）、2026-08-19（3 只）
- **建议改法**：把"该票在该日无行"与"该票在该日有行但零成交"分开统计，前者单列一个计数并打 WARNING。
