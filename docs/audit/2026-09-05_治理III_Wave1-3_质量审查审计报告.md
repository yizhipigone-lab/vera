## 三、高危改动调用方语义核对（本次新增扫描）

### 3.1 `executor.in_flight_sells()` 合并 `_external_sells` 的消费方语义

全库调用方仅 3 处：trade_main reconcile 注入（单源）、rotation 注释、test_executor 断言。**无其他模块把 `in_flight_sells` 当"executor 自己 pending"读** → 合并暴露不会造成他处误报。monitor/executor 撤单流水线内部仍读 `self._pending`（不经该合并），rotation 外部卖单不会触发追价/逃生。**结论：语义安全。**

### 3.2 `FormulaRunner` 返回值改为 `SelectionBatchResult` 后的老调用方

engine（614，交 `build_formula_exit_matrix`）、selector（219）、tools/e2e_l2_cache、e2e/pipeline 测试——逐一核对访问形式：`picks.empty`/`len()`/`[...]`/`[["a","b"]].sort_values`/方法链，全部可经 `__getattr__`/`__getitem__`/`__len__`/`__iter__` 委托。**无 `isinstance(result, pd.DataFrame)` 或 `type()` 依赖**（全库 grep 无命中）。`test_pipeline_mock_integration`（mock 返回路径）+ `test_signal_day_cache`（失败/真空语义）已实际经 BatchResult 走通。**结论：委托设计成立，老调用方零改动为真。**

### 3.3 牛熊口径 200 门槛的三方一致

core/index_regime 常量（测试锚定）↔ data_tools 注释 ↔ research 版委托，grep 无第三份实现；门槛改动的唯一入口是测试断言。**结论：分叉消灭为真。**

### 3.4 双胞胎更名后 raw 语义保留

`get_calendar_days` 仍异常上抛 + 字符串，5 个要"真失败大声失败"的工具与 2 个 KlineCache calendar_fetcher 契约不受影响；`get_trading_days` robust 为窗口数学唯一入口，engine/信号缓存调用不变。**结论：不是"伪消除"（没有把 raw 悄悄并进 robust 吞异常）。**

## 四、发现与观察清单（按严重度）

1. **[低·已顺手修正] CLAUDE.md 活文档改名残留**：两处引用已删符号——`FormulaRunner.last_batch_errors`（L2 缓存行）、`rotation.compute_signal deprecated 未删`（影子校尺行）。前者误导后续会话读已删类属性，后者指向旧文件。审计中已改为 `SelectionBatchResult.batch_errors` / `trade/legacy_three_state.py::compute_signal`。**提示：本项目"改名必改引用"规则应同样覆盖 CLAUDE.md（当前治理提交均只扫 .py）。**

2. **[中·记录在案] kline_cache_maintenance `_cache_handle` 每次调用新建 KlineCache 实例（新持久 sqlite 连接）**：cached_last_date/period_stats 每次读都 `KlineCache(...)` 构造（mkdir/_init_db/WAL pragma 各一次，随后 CPython refcount 归零关闭连接）。频率低（cache_status 一天数次）、无泄漏，但构造开销与"读接口"的朴素用法不匹配。**建议（可选）**：模块级 `functools.lru_cache` 复用同一实例或提供 KlineCache 只读连接复用。非阻断。

3. **[低] `SelectionBatchResult` 无独立直测**：委托协议（len/[]/iter/方法链）与 `failed_all/any_failed` 目前靠下游测试间接覆盖（pipeline mock / signal_day_cache）。**建议**：`tests/test_formula_runner.py` 加 ~6 行直测钉死委托与失败统计（防未来误删 __getattr__ 静默改变 engine 行为）。

4. **[低·过程观察] W3 五个代码任务未严格"先红后绿"**：W1-b、W2-①（pool_money）写了失败测试先红；W3 多数为纯改名/纯搬家/委托化重构，以"既有断言改指 + 全量回归"为绿判据，未单独造红（rpe 的测试是搬移目标而非先行红）。**裁定**：对行为零变的重构可接受（先红成本 > 收益），但需在提交信息/CHANGELOG 里声明"重构型，回归绿兜底"——本次多数已隐含；后续同类请在提交信息显式写"纯搬家，回归绿"。

5. **[低] rotation.py 行数 718（含空行），未达治理 II 报告"约 600 行"估算**：达成的真目标是"deprecated 误导代码出生产文件"（grep 空），行数收缩受动量路径既有实现体量限制。**裁定**：验收标准以"无 deprecated 定义"为实，行数为参考；已在 CHANGELOG 以实测值记录，不追加收缩任务。

6. **[低·文档措辞] data_fetcher.get_name_map 注释** "空结果不缓存——set 存空" 措辞自相矛盾（实际行为=空 map 缓存后 has 见空判定 miss→重试，与旧等价）。功能正确，注释易误导。**建议**：下一趟顺手改措辞。
