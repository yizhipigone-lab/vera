## 二、P0(可能算错钱/算错结果/真实威胁面)

### P0-1 选股缓存撞 key: `exclude_quit: False` 与缺键归一化成同一 key, 回测池语义被偷换

- 现象: `[selection/selection_cache.py:55-56]` 把显式 `False` 当假值从缓存 key 里剔掉, 但
  `[selection/selector.py:146]` 的 `exclude_quit`(是否剔除退市股)缺省值是 `True`。
  配置写 `exclude_quit: False`(保留退市股, 样本外回测用)与不写这个键(剔除退市股)产出**同一个缓存 key**,
  两种池子内容不同, 后跑的错拿先跑的缓存。
- 真实调用方存在: `[tools/batch_formula_rank.py:90]` 的 `--include-delisted` 会产出 `exclude_quit: False`。
- 大白话: 两个不同的购物清单贴在同一个储物柜钥匙上, 谁后开柜门谁拿错东西, 而且不报错。
- 建议: 归一化改为"按该键在 selector 的缺省值剔除"(缺省表驱动), 或对缺省为 True 的键保留显式 False。

### P0-2 K 线缓存 F6 复权漂移检测首末根口径矛盾: 5m/1m 每日误报"分红 shift"→ 全历史重拉

- 现象: `[core/kline_cache.py:422]` 的 `_close_at` 取当日**第一根** bar 的收盘价;
  而 manifest 里存的 last_close 在 `[core/kline_cache.py:495]` 存的是全文件**最后一根** bar。
  日线一天一根两者相等没事; 5m/1m 一天 48/240 根, 每次增量拉取后的比对(`[core/kline_cache.py:277-279]`)
  必然超 1e-6 阈值 → 误报分红 → 触发全量重拉(`[core/kline_cache.py:283-285]`), 每个新交易日对每只分钟级股票重复一次。
- 影响: 分钟级缓存等于每天白重拉一遍全历史(拉取耗时+TDX 压力), 疑似历史"5M 回测取数超时事故"的元凶之一。
- 建议: `_close_at` 改 `s.iloc[-1]`, 与 manifest/探针口径对齐(一行修复)。

### P0-3 阶梯止盈兜底部分卖只写内存不落库: 盘中重启后同一档可再次部分卖(同档双卖)

- 现象: `[trade/monitor.py:335]` 兜底触发部分卖后只调 `self._book.mark_tier(...)`(内存标记),
  其后**没有** `store.tier_state.save`; 对照预埋路径 `[trade/executor.py:415-417]` 是"标记+落库"双写。
- 后果: 进程盘中重启 → 当日档位标记丢失 → 同一档再次触发部分卖, 重复减仓。
- 建议: monitor 标档后同样落 `tier_state.save(code, sorted(self._book.tier_done(code, today)), today)`。

### P0-4 实盘交易 API(8081)零鉴权 + CORS `*` + 绑 0.0.0.0

- 现象: `[trade_main.py:1372-1374]` `origins = ["*"]` + `host="0.0.0.0"`, 而 `[trade/api.py:357-359]`
  的 `/api/trade/unkill` 直接解除急停、`[trade/api.py:410]` 的 `/api/trade/buy` 直接人工下单。
  CORS `*` 意味着用户浏览器里**任意网页**都能 POST 本机 8081 驱动实盘下单。
- 备注: 注释写明这是 2026-08-18 手机访问拍板的"用 * 兜底"——看页面可以, 但下单/解急停不该与看页面同级。
- 建议: 8081 写命令加共享密钥头, 或 `kill_off/buy/sell` 限回环来源; 读接口维持现状。

### P0-5 分析页 QMT 对账取错键名: 告警永远不触发(fail-open)

- 现象: `[trade/analysis_api.py:241]` `qmt_asset.get("totalAsset", rows[-1]["total_asset"])`,
  但网关实际返回的键是 `"total_asset"`(`[trade/gateway.py:416-418]`)。
  `.get` 恒取不到 → 回落**本地最后一行快照值** → 对账数字永远"一致" → 告警永远不触发。
  该处注释自己写着"查询失败 ≠ 对账通过"(审计 Q3 的 fail-closed 意图), 但键名写错把意图架空了。
- 大白话: 装了个烟雾报警器, 但电池槽装反了——灯亮着, 永远不响。
- 建议: 改 `qmt_asset.get("total_asset")`, 取不到给 None(视图层即告警), 不给静默兜底。

### P0-6 `tools/backfill_daily_asset.py`: 被取代的旧脚本会把推算行打上"QMT 实测"戳

- 现象: 默认 DB 路径错(`[tools/backfill_daily_asset.py:32]` 写 `data/trade.db`,
  生产实为 `[trade/config.py:185]` 的 `data/trade/trade.db`); INSERT 不带 source 列
  (`[tools/backfill_daily_asset.py:181-185]`), 按 `[trade/store.py:747]` 的 `DEFAULT 'eod'`,
  推算行被打上"实测"戳——违反"实测行永不被覆盖/推算必标 derived/缺价 fail-closed"三条停机日补算铁律。
  一旦有人带 `--db` 指向真库执行, 会污染 gapfill 的锚点。功能已被 `trade/asset_gapfill.py` 完全取代, 全仓无调用方。
- 建议: **删除整个脚本**。

### P0-7 QUANTQQ 两份报告的"达标"判定丢了回撤腿

- 现象: `[tools/quantqq_1m_sweep.py:381]` 与 `[tools/quantqq_5m_sweep_2010.py:464]` 的达标判定只有
  `年化 >= 阈值 且 笔数 >= 下限`两条, **没有回撤≤15% 约束**——回撤 50% 的组合也被计入"达标"。
- 建议: 改走 `core/farm_rules.py` 的判定(15% 年化与 farm_rules 同源, 笔数下限属本课题口径可作参数传入)。

### P0-8 同一 QUANTQQ 课题三份脚本三套达标线

- 现象: `[tools/quantqq_5m_sweep.py:392]` 仍硬编码 `annret > 0.23 且 回撤≤0.15 且 笔数≥1000`,
  而 1m 版已改 15%、2010 版用 15%(且都丢了回撤腿, 见 P0-7)——三份脚本三套口径。
  另 `[tools/gs_1d_detail_report.py:49]` 与 `[tools/gs_1d_detail_report.py:70]` 报告正文还写着旧线
  "年化>30% 且 回撤≤15% 且 交易≥1000笔", 而同文件实际筛选已走 farm_rules(15%/15%/20)——**生成的报告写错达标线**,
  直接违反"报告必须写全口径+达标线"。
- 建议: 全部收口 `farm_rules`, 报告文本用 `farm_rules.describe()` 生成。

### P0-9 公式流水线 5m 分段拼接指标缩进错误: 年化/累计收益只按最后一个分段算

- 现象: `[tools/formula_pipeline/stage_5m.py:231-233]` 三行(`v0`/`cum *=`/`n_days +=`)缩进到了
  `for eq in all_equity:` 循环**外面**, 只用最后一个分段的权益曲线算 total_ret 与 n_years →
  `results_5m.json` 的年化全错 → 流入 build_html 的 S4 结论与幸存者表。
- 大白话: 把全年 12 个月的成绩单只拿 12 月那张算平均分。
- 建议: 三行缩回 for 循环体内。同文件 `_max_dd_from_segments` 是正确的逐段写法, 可对照。
