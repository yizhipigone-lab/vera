## 二、CRITICAL 发现（修完前不要在不可信网络下启动服务）

### C1. 实盘交易 API（8081）绑定 0.0.0.0 且零鉴权 —— 局域网任何人可下真实订单、可远程解除急停

今天 22:59 的提交 `1d6f43d`（局域网手机访问）把交易 API 从只监听本机改成监听所有网卡：

- [trade_main.py:1340-1342]：`origins = ["*"]` + `uvicorn.run(..., host="0.0.0.0", port=args.api_port, ...)`
- [trade/api.py:281-286]：CORS 中间件直接吃 `allowed_origins=["*"]`；全文 876 行无任何鉴权依赖/token 校验/IP 白名单

裸露的高危端点（已逐行 Read 确认）：

| 端点 | 位置 | 后果 |
|---|---|---|
| `POST /api/trade/unkill` | [trade/api.py:606-609] | **远程解除急停**——kill switch"只许人工解除"在网络层被架空 |
| `POST /api/trade/buy` / `sell` | [trade/api.py:611-620] | 真实资金买卖 |
| `PUT /api/trade/config` | [trade/api.py:577-597] | 热改风控参数（日亏熔断线等即时生效） |
| `GET /api/trade/asset` | [trade/api.py:303-321] | 读实时总资产/现金 |
| `GET /api/trade/config` | [trade/api.py:572-575] + [trade/config.py:652] | **泄露券商资金账号**（全字段导出含 `account_id`） |

影响：同一 WiFi 下任何设备可查看资金/持仓/券商账号并用你的钱下单。这是直接金钱损失级暴露。

### C2. `/api/research/chat` = 无鉴权远程任意命令执行（RCE）

- [research_api.py:58-85]：接收任意 `{question}` 直调 `ask_brain`
- [brain/claude_cli.py:162-164]：启动 claude CLI 时带 `--allowedTools Read,Grep,Glob,Bash,Write,Edit` + **`--dangerously-skip-permissions`**

即：局域网任何人 POST 一句话，就能以本机用户身份跑一个带 Bash/Write/Edit 且零审批的 agent。`.env` 里的 API key、券商配置全部可被打包外发。文件头注释 [brain/claude_cli.py:10-14] 自述"C 裸奔"。

### C3. CORS `allow_origins=["*"]` —— 互联网上任何网页都能隔着你的浏览器读资产

- [server.py:49]：`allow_origins=["*"], allow_methods=["*"], allow_headers=["*"]`（8081 同款 [trade/api.py:281-286]）

CORS `*` 意味着你浏览器误点的任何恶意网页，其 JS 都能向 `http://<你的局域网IP>:8080/8081` 发请求并读响应。写操作（下单/解除急停）走 simple request 甚至不需要 CORS 放行。"局域网信任"被扩大成了"整个互联网"。

### C4. 回测 parity 哨兵红 2 天，期间 8 个提交照常落地

- 现象：干净工作区上 `tests/test_run_cached_parity.py` 9 个测试全红（`np.array_equal` 断言，[tests/test_run_cached_parity.py:174]）
- 根因：08-16 提交 `97ff548` 在 [backtest/engine.py:326] 把生产路径价格矩阵统一转 float32（提速），但测试对照组 [tests/test_run_cached_parity.py:135] 仍用 float64 喂数据——两边差 6e-9（百万分之六），断言必炸。该提交修了 `test_open_positions` 容差、重生了快照基线，**唯独漏了这个文件**
- 数值本身问题不大，真正的风险是**流程**：这个测试是"两个回测入口数出来的钱必须一分不差"的验钞机，它红了 2 天（08-16 → 08-18）没人发现，说明这段时间的提交没跑全量测试

### C5. CI 形同虚设

[.github/workflows/ci.yml](.github/workflows/ci.yml) 三个洞：
1. 只在 `master` 分支触发（第 4-7 行）——当前开发分支 `feature/policy-layer-a` 的提交 CI 从没跑过，C4 由此漏网
2. 依赖只装 `ruff pytest pandas numpy`（第 18 行）——缺 fastapi/pydantic/pyarrow，真跑了也会大面积 import 失败
