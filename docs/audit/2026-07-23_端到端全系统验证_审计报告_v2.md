## [CRITICAL-1] `_simulate_core_v3_legacy` 缺少 `trailing_gap_protection` 参数

- **位置**：`backtest/engine.py:123-152`
- **复验方法**：逐行读三处代码 + 实测跑测试
- **证据链**：

  1. `_simulate_core_v3` line 89: `trailing_gap_protection=False` ✅
  2. `_simulate_core_v3_legacy` line 123-152: 最后参数为 `atr_enabled=False, atr_matrix=None, atr_multiplier=3.0,` line 151 → `)` line 152 — **无** `trailing_gap_protection` ❌
  3. `run_cached` line 1316: `trailing_gap_protection=bool(trail.get("gap_protection", False))`
  4. `test_real_parity` line 101-106: monkeypatch `_simulate_core_v3 → _simulate_core_v3_legacy`
  5. 实测：`pytest tests/test_real_parity.py -v` → 3/3 FAIL，全部 `TypeError: _simulate_core_v3_legacy() got an unexpected keyword argument 'trailing_gap_protection'`

- **根因**：2026-07-21 新增 `trailing_gap_protection` 到新壳（line 89），但 parity 甲骨文 `_simulate_core_v3_legacy` 未同步。已有同样模式的 `atr_*` 参数（line 87/151）被同步，但此参数遗漏。

- **修复**（1 行）：在 `backtest/engine.py:151` 之后插入：
  ```python
  # 移动止盈跳空保护 (2026-07-21): legacy 无此能力, 接收但忽略 (保持 parity 甲骨文)
  trailing_gap_protection=False,
  ```

- **严重性**：CRITICAL。parity 甲骨文是确保新旧引擎字节级一致的唯一防线。破坏后引擎 drift 无法被测试发现。

## [LOW-1] `StrategyConfig.ladder_levels` 默认值与实际数据格式不一致

  - 默认值是百分比格式（"6:30"），但前端 `collectConfigFromForm:456` 发送的是小数格式（"0.06:0.3"）
  - 全链路实测：`POST /api/config/save` 写入的 YAML 值为 `profit: 0.06, sell_ratio: 0.3` ✅
  - 默认值仅在没有传参时使用，而前端永远传参，所以不影响运行
  - 但 `/api/config/validate`（孤儿端点）用此默认值时会显示错误警告 "6000%"
- **修复**：将默认值改为 `"0.06:0.3,0.15:0.3"` 或在前端去掉 `/api/config/validate` 端点

## 全链路闭环验证（HIGH-1 复验依据）

以下 6 步追踪确认 config 单位全链路正确：

| 步骤 | 值 | 来源 |
|---|---|---|
| 1. 前端 DOM 输入 | `"6:30,15:30"` | 用户看到的百分比 |
| 2. `collectConfigFromForm()` | `"0.06:0.3,0.15:0.3"` | `vera-ui.js:456` — `parseFloat/100` |
| 3. `POST /api/config/save` Body | `ladder_levels: "0.06:0.3,0.15:0.3"` | 前端发送 |
| 4. `_config_to_yaml_dict()` | `profit: 0.06, sell_ratio: 0.3` | `server.py:150-153` — `float(split)` |
| 5. YAML 落盘 | `profit: 0.06, sell_ratio: 0.3` | 实测读取 `config/current.yaml` ✅ |
| 6. `applyConfigDict()` 回显 | `l.profit*100 + ':' + l.sell_ratio*100` | `vera-ui.js:518` — 回到百分比 |

结论：实际用户触发的所有路径（save / run / load）数据单位正确，只有孤儿 validate 端点的默认值有偏差。
