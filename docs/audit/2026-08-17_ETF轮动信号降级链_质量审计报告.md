## 二、发现（按严重度）

### HIGH-1 · YAML `execute_time` 未加引号 → 六十进制整数 → 启动崩溃 —— 已修复

`config/trade.yaml:63` 写成 `execute_time: 14:56`（未加引号）。YAML 1.1 把无前导零的
`14:56` 解析成 sexagesimal 整数 896，`_coerce_rotation` [trade/config.py:487] 判非 str
抛 `TypeError: rotation.execute_time 必须是 str`，`trade_main.py` 启动即崩。

根因：原值 `09:30` 有前导零（非法八进制）被 YAML 侥幸当字符串；同文件其余时间值
（`'14:54'`、`'14:57'`、`'14:55'`）均已加引号，仅本次改动漏加。

修复：`execute_time: '14:56'`。已验证 `load_trade_config('config/trade.yaml')` 返回 str
`'14:56'`。**教训**：所有 HH:MM 时间值必须加引号，防 sexagesimal 误解析。

### MEDIUM-1 · 降级链无显式超时 —— 保留（记录）

`_fetch_tdx_closes` [trade/rotation.py:313] 与 `_fetch_tencent_closes` [trade/rotation.py:330]
无显式超时。若 TDX/akshare 网络挂起，信号工作线程 hang → `_running` 恒 True →
当日轮动静默停摆（次日才自愈）。缓解：`_worker` 是 daemon 线程，不阻塞消费者线程；
且 akshare/TDX 自带超时。v1 接受，后续可在 `_fetch_closes` 外层加 `_call_with_timeout`。

### LOW-1 · 跨包依赖（trade → core/data_fetcher + akshare）—— 保留（惰性 import 已隔离）

`trade/rotation.py` 首次让实盘链路依赖回测侧 TDX（`core.data_fetcher`）与公网库 akshare。
均惰性 import（方法内），无启动成本、主源 QMT 命中时不触发。前提：trade 进程环境已装
akshare（同环境 brain 已在用，满足）。

### LOW-2 · 腾讯 symbol 转换无防御 —— 保留（配置校验已保证格式）

`_fetch_tencent_closes` 的 `num, ex = code.split(".")` [trade/rotation.py:332] 假设信号指数
恒带交易所后缀。`RotationConfig` 校验 [trade/config.py] 已锁 `XXXXXX.SZ` 格式，安全；
若将来改传裸代码会 ValueError（非静默，可接受）。
