## ⚙️ 功能分析师发现

### ✅ 核心逻辑正确 (PASS)
`bucketReason` 正则 `/[:：·]/` 对实盘真实格式全部命中 (11 样本验证):
- `"移动止盈: 最高 12.00 (峰值涨幅 +20%...) 触发"` → `移动止盈` ✅
- `"阶梯止盈·档1"` → `阶梯止盈` ✅
- `"硬止损: ..."` → `硬止损` ✅ (旧词"成本止损"已对齐实盘 executor.py:40)

### ⚠️ 归一后丢失原始 detail (MEDIUM — 交互降级)
- old 代码: label = `slice(0,12)` 截断长文本, tooltip 至少显示部分数字;
- new 代码: label = 纯策略名, **聚合后同类原因的具体触发参数 (峰值/回撤/阈值) 不可见**。
- 权衡合理 (不归一会因每笔数字不同拆成无数扇区), 但属信息降级。建议 tooltip 增强: 显示该类目下首条原始 reason 全文。

### ⚠️ reason 字段格式为隐式契约 (MEDIUM — 架构耦合)
`bucketReason` 假设 reason = `"策略名(:|·)描述"`. 若 executor (trade_main.py:80 `_reason_from_ctx`) 将来改 reason 拼接格式 (去冒号/换分隔符), 归一静默失效重新掉灰。**前端无任何契约锁**知道后端格式约定。根治方案: 后端 reason 拆成结构化 `{label, detail}` 而非拼接字符串。

### ✅ 边界条件 (PASS)
- `deals` 空 / 全 BUY → `reasonCount` 空 → 空饼 (echarts 正常渲染空, 非崩溃)
- `t.reason` 空串 → `t.source==='manual' ? '人工卖出' : '未标注'` (与 old 一致)
- `t.source` undefined → `===  'manual'` false → "未标注" ✅
- head 为空 (reason=`": xxx"`) → source 兜底 ✅

### ⚠️ 非字符串 reason 会崩 (LOW — 预先存在)
若后端某笔 `t.reason` 是 number 等非字符串, `raw.split()` 抛 TypeError。**但 old 代码 `reason.length` 同样会崩** → 归因: **预先存在**, 非本次引入。实盘 reason 是 TEXT 字段 (store.py:179), 实际概率极低。

## 🤔 额外想到的隐患

1. **fbIdx 提模块级就会错位 (LOW)**: 当前 `let fbIdx = 0` 在函数内每次重置, 正确。但若将来重构提到模块级, 会跨渲染累积错位。脆弱点, 建议注释标注 "必须在函数内"。
2. **回测页仍用旧词"成本止损" (LOW, 已知遗留)**: 与实盘"硬止损"术语不统一。若将来 engine.py:796 reason_map 改"成本止损"→"硬止损", charts.js:647 的 key 也得跟改, 否则回测页该词掉灰。前端 key 与后端字面强耦合。
3. **fallbackPalette 取色顺序依赖 sort (LOW)**: `pieData.sort` 降序后 fallback 按序取色, 顺序确定。但若去掉 sort, 同份数据两次渲染 fallback 取色可能不同 (取决于 Object.entries 顺序)。建议保留 sort。
4. **可观测性缺失 (LOW)**: 若将来再次掉灰, 前端无任何日志输出哪笔 reason 未命中表。建议 bucketReason 走 fallback 时 `console.debug` 一次, 便于排查。
