## ⚠️ 发现的问题

### MEDIUM-1: `submitBacktest` 导入但从未调用（死代码）

**位置**: `web/js/vera-ui.js:3` 导入, `web/js/api.js:12-20` 定义

**原因**: `runPipeline()` 中的 `/api/run` fetch 需要 `AbortController.signal`(超时中止), 因此保留了原始 `fetch('/api/run', {..., signal})` 调用, 未使用 `submitBacktest(config)`.

**影响**: 无功能影响。但 api.js 声称"所有后端 HTTP 请求的单一入口"不完整——最重要的 `/api/run` 实际绕过它。

**建议**: 要么给 `submitBacktest` 加 `signal` 参数支持 AbortController, 要么从 api.js 删除它并注释说明 `/api/run` 不走此模块。

### LOW-1: `saveBlock` 成功日志被抑制

**位置**: `web/js/vera-ui.js:51`

原代码中 `saveBlock` 调用 `addLog('全部配置已保存到浏览器', 'ok')`。新版本中 wrapper `saveBlock(blockId)` 调 `cfgSaveBlock(blockId, saveAllConfig, refreshAllSummaries, addLog)`——已传入 `addLog`, 所以日志**正常显示**。经代码核实结论为无误。

> 更正: agent-1 初版报告称 wrapper 未传第 4 参数, 后经手动 grep 验证 line 51 确实传了 `addLog`, agent 报告有误。

### LOW-2: `charts.js` 导出 `_charts` 但无外部消费者

**位置**: `web/js/charts.js:113`

`export let _charts = {}` 仅被同模块的 `setChartsRef` 和 `echartsInit` 使用。虽然导出它不产生问题, 但不必要地扩大了公共接口。

**建议**: 改为非导出(`let _charts = {}`), 仅通过 `setChartsRef` 暴露。

### LOW-3: config.js `loadConfig` 末尾缺 `refreshAllSummaries` 调用

**位置**: `web/js/config.js:58-82`

原 `loadConfig()` 末尾调用 `refreshAllSummaries()`(line 177)。新 `loadConfig()` 末尾(行 82)仅注释 `// refreshAllSummaries is called from vera-ui.js after importing this`。实际调用点在 vera-ui.js init(行 410): `loadConfig(); refreshAllSummaries();`。

**验证**: vera-ui.js:410 确实连续调用两者, 功能等价。但若未来有其他调用方用 `loadConfig()` 而不补 `refreshAllSummaries()`, 摘要不会刷新。这是设计选择(分离关注点), 但值得文档化。

## 🤔 穷举隐患

### 隐患 1: ES module 在 file:// 协议下的行为
VERA 通过 `http://localhost:8080` 访问 (FastAPI StaticFiles), 不是 `file://`。ES modules 在 http:// 下正常工作, 无风险。

### 隐患 2: `toggleTheme._onToggle` 默认 undefined
`charts.js:51` 调用 `if (toggleTheme._onToggle) toggleTheme._onToggle()`。若 vera-ui.js 初始化失败(import 错误), 钩子不赋值, 调用安全跳过——不会崩溃 ✅

### 隐患 3: 浏览器缓存旧 `vera-ui.js`
原 `index.html` 用了 `?v=20260721` 缓存破坏。新版本改为 `?v=20260723`, 确保浏览器加载新模块文件。✅

### 隐患 4: `echarts.min.js` 加载失败时
若 echarts CDN/文件不存在, charts.js 中 `echarts.init()` 抛 ReferenceError。这是**预先存在的问题**(原代码同一风险), 非本次引入。

### 隐患 5: `recover.js` 的 `var` 声明污染全局
recover.js 用 `var RECOVER`, `var deps` 等(为 Node vm.runInContext 兼容)。在浏览器中, `<script>` 标签内的 `var` 会挂到 `window`。但随后 `window.VeraRecover = { RECOVER, deps, ... }` 将它们封装在一个命名空间下。副作用: `window.RECOVER`, `window.deps` 等变量泄漏, 但概率极低与现有代码冲突。
